## 2. 模型身份及当前参数

| 用途 | 目录展示名 | modelKey / toolKey | 创建节点时的参数 |
| --- | --- | --- | --- |
| 四视图、必要内饰/场景参考 | `Lib Image 2.5 Pro` | `lib-image-2.5-s` | `-s 'model=Lib Image 2.5 Pro'` |
| 整段多镜视频 | `Seedance 2.5` | `star-video2.5` | `-s 'model=Seedance 2.5'` |

`libtv model <key>` 可以用 modelKey 查询；`libtv node ... -s model=...` **只接受目录展示名**。本次 `libtv model` 输出顶层 `modelName` 仍可能返回 key 字符串，不可机械复制；以 `model search` 的展示名为准。

本次视频搜索也返回 `Seedance 2.5（样片模式）`（`star-video2.5-draft`）；它是另一条模型记录，不能自动替换默认 `Seedance 2.5`。用户称图片模型为 GPTimage2.5，但本次目录只核实了 Lib Image 2.5 Pro 的执行身份，未证实其底层厂商版本对应关系。

### Lib Image 2.5 Pro

- 参考模式：`image2image`，schema 范围 **0–14 张图片**。
- `resolution`：`1K`、`2K`、`4K`；默认 `2K`。
- `quality`：`low`、`medium`、`high`、`xhigh`、`max`；默认 `medium`。
- `count`：`1`、`2`、`4`。一张四视图板是 `count=1`，不是四次生成。
- `ratio` 包含 `16:9`、`9:16`、`1:1` 等，以本次 schema 为准。
- 仅为明确列入并获准的参考资产出图；不因多镜视频包含多个镜号而生成对应分镜图。缺少真实内饰证据时，不能把模型补全当作真实配置。

### Seedance 2.5：本 Skill 使用的多图模式

| 字段 | 已核验值 | 本工作流用法 |
| --- | --- | --- |
| `modeType` | `image2video` | 多图参考；不替换为 `singleImage2video` 或 `frames2video` |
| 图像数量 | **1–30 张** | 按本段所需连接车辆、内饰和场景参考；上限不是应填满的目标 |
| `duration` | **4–30 秒，整数，步长 1**；默认 5 | 每个生成节点对应一段多镜视频，明确设置本段总秒数 |
| `resolution` | `480p`、`720p`、`1080p`；默认 `720p` | 按已确认质量和预算选择，不因默认值降低已承诺规格 |
| `ratio` | `adaptive`、`16:9`、`4:3`、`1:1`、`3:4`、`9:16`、`21:9` | 同一片显式统一画幅 |
| `count` | `1`、`2`、`4` | 默认1条；不得自行扩大候选数量 |
| `enableSound` | `on` / `off`；默认 `on` | 按声音方案显式设置 |

`image2video` 只接图片。确需音频/视频混合参考时，须另核验并在方案中明确切换到 `mixed2video`；本次 schema 为总资源1–50、图片最多30、视频最多10、音频最多10。不得把音视频硬塞进图片模式。本版默认仍是图片多参考，不因支持其它路径自动增加素材。

目录注明 Seedance 2.5 按秒计价，上传的参考视频时长计入总时长。本次没有查询到账户精确单价、余额或本次报价，不得编造积分费用。

## 3. 参考资产的连接与职责

建议资产命名：`CAR_4VIEW`、`CAR_FRONT`、`CAR_LEFT`、`CAR_REAR`、`CAR_RIGHT`、`CAR_INTERIOR`、`SCENE_PORTICO`、`SCENE_ROAD`。默认四视图分别为正前、左侧、正后、右侧；左右均按车辆自身方向定义。实际资产按主 Skill 和已确认清单准备，不为凑四格虚构未知配置，也不默认新增后侧45°等付费角度。

- **subject 参考**：车辆四视图及必要内饰，约束同一辆车的轮廓、车色、灯组、轮毂与座舱结构。
- **scene 参考**：环境空间、材质、光向和天气。场景图中的其它车不作为主体身份依据。
- `subject` / `scene` 是提示词内的**职责说明**，不是本次 schema 验证过的 CLI 参数；不要虚构 `--subject`、`--scene` 或 `timeline=` 字段。
- 四视图板或内饰板可以作为多图模式中的参考。若各格足够清晰，优先本地裁出干净单视角，避免模型将版式误解为视频画面；含平面示意图、路线箭头或大量文字的场景卡必须裁出写实视角后再输入。裁切只分离既有视角，**不是生成分镜图**，不新增广告构图、镜头灯光或车型细节。
- 裁出的图片分别计入参考数量；一张未裁的板按一张图片连接。去掉格线、编号和邻格残片，检查像素是否足够。不要把模糊裁图放大后称为新增真实细节。
- 使用参考板时，在提示词中写明：板中各格展示同一辆车，所有格只是身份资料；输出始终为单一全幅镜头画面，按时间轴切换镜头，不展示宫格、分屏、画中画、标签或参考板本体。
- 参考图的连接顺序不等于剪辑顺序。真实切镜顺序由文字时间轴定义；多图输入也不是逐张轮播。

先上传需要使用的真实文件，获得资源节点和 nodeKey；已存在且核验可用的资源节点直接复用。将这些节点用重复的 `--left <节点名或nodeKey>` 连接到本段视频节点。`--left` 只确保入边存在，不删除旧边；更新旧节点时先查询已有输入，显式移除不需要的引用，避免上一版车辆或场景混入。

提示词通过以下任一格式引用**已连线**的节点：

```text
{{Node "CAR_FRONT"}}
{{Node <真实nodeKey>}}
```

第一种要求名称在整张画布唯一；同名时使用真实 nodeKey。不能写 `{{Node CAR_FRONT}}`，未加引号会被解释为 nodeKey。引用未连线的节点会失败；不得用占位符冒充已存在资源。

## 4. 整段多镜与约0.5秒时间轴

**执行参数与模型提示词分开。** 模型名、`modeType`、`duration`、`ratio`、`resolution`、`count`、`enableSound` 属于节点/API 配置；拟用或未提交状态、资源路径和验收状态、参数核验、授权/费用、后期安排、全片与段内时间换算以及生成后的检查结论属于执行记录。它们不能混进 `--prompt`，也不能用提示词中的文字代替真实参数设置。镜头自身的起止秒数、画面、运镜、衔接和参考图语义属于提示词内容。

一个 `CAR_CLIP_01_v01` 节点生成一段含多个镜头的视频，不为每个镜号建立视频节点。每段 `duration≤30`；超过30秒的成片按叙事、空间或音乐转折分段，每段重新使用相关身份/场景参考，并记录跨段车姿、光线、门状态和行驶方向。

当前 API 总时长步长是 **1秒**。提示词内可以用约 **0.5秒** 粒度安排镜头边界，例如 `[0.0,0.5)`、`[0.5,1.5)`；这不代表 `duration=0.5` 合法，也不代表每个镜头必须只有0.5秒。长镜仍可保留1.5–3秒或更多时间承载识别和运动。30fps项目中0.5秒对应15帧，这是本地时间轴换算，不是模型提供的逐帧控制。

每段提示词必须包含：

1. 参考职责和车辆一致性锁；未知配置不编成事实。
2. 多镜剪辑意图；明确允许按逐镜时间轴硬切/转场，**不要残留旧版“单一连续镜头、无切镜”约束**。总时长、比例等数值作为接口参数另设，提示词中保留逐镜起止时间即可。
3. 连续覆盖本段 `[0,duration)` 的镜头时间轴，逐镜写画面、运镜、衔接和车体状态；不要只写“豪车快切”。
4. 整段摄影与空间连续性、驾驶方向、已开/已闭门等状态；需要省略动作时用明确切镜表达，不要求跨镜形变。
5. 不展示参考板、无新车型/不新增部件、无自动字幕/无无关人物等具体约束。
6. 仅按作品需要写入真实台词、具体环境声/动作声，或“无对白、无旁白”等内容描述；不把 API 声音开关、后期配乐安排或声轨验收备注写进提示词。

以下仅示范最终提示词中的参考语义与风格片段；完整逐镜表使用 [时间轴示例](timeline-prompt-example.md) 的模型提示词内容。正式提交前在代码块外完成参考绑定与完整性检查，不把“待替换”“不得带占位符提交”等操作备注传给模型。

```text
{{Node "CAR_FRONT"}}、{{Node "CAR_LEFT"}}、{{Node "CAR_REAR"}}、{{Node "CAR_RIGHT"}}
均为同一辆汽车的主体身份依据，分别约束相应方向的结构。
{{Node "CAR_INTERIOR"}}仅约束该车真实内饰；{{Node "SCENE_PORTICO"}}仅约束门廊环境，
{{Node "SCENE_ROAD"}}仅约束道路环境。它们不是首尾帧，也不是按输入图序播放的分镜。
以明确硬切交替呈现整车、细节与行驶机位，保持同一车辆和相连场景的空间关系。
每个时刻均为一个完整画幅，严禁四宫格、分屏、参考板、图像轮播或把不同视角融合成一辆变形车。
```

`enableSound` 在节点配置中显式设置：关闭时不依赖模型声轨；开启时才按已批准的内容需求生成声音，之后检查实际声轨。参数选择和声音后期安排记录在执行表中，不附到模型提示词末尾。

schema 验证的是输入模式、数量和总时长，**没有验证每0.5秒切镜、镜头数量或逐帧服从能力**。整段多镜时间轴是生成指令，不是服务端确定性剪辑 API。生成后需逐段检查实际切点、镜头是否遗漏/合并、身份与空间连续性；必要时在已授权范围内调整提示词、重新生成或本地剪辑。不得将时间轴写进prompt就声称已经精确实现。

## 5. 命令骨架：直接引用资产，不生成分镜图

以下仅为执行模板，参数中的占位符必须替换；当前核验没有运行这些写操作。正式生成仍遵循主 Skill 的出图确认与视频授权规则。先准备可审查的完整方案，再按已有授权执行。

```bash
# 仅用于已确认的四视图图片方案；原图节点须已存在。
# count=1生成一张四视图板，四格为正前/左侧/正后/右侧。
# 本行只创建配置，不触发生成；取得本批出图授权后另行决定执行。
libtv node create 'CAR_4VIEW' -p '<画布UUID>' -t image \
  -s 'model=Lib Image 2.5 Pro' -s modeType=image2image \
  -s ratio=16:9 -s resolution=2K -s quality=medium -s count=1 \
  --left 'CAR_ORIGINAL_01' --prompt '<已确认的完整四视图提示词及真实原图引用>'

# 仅示意上传已确认车辆资产；其余必要内饰/场景资产同理。
libtv upload 'CAR_FRONT' -p '<画布UUID>' --resource '<车辆正面参考绝对路径>'

# 单个视频节点承载完整20秒多镜段；没有S01_FRAME等逐镜图像节点。
libtv node create 'CAR_CLIP_01_v01' -p '<画布UUID>' -t video \
  -s 'model=Seedance 2.5' -s modeType=image2video \
  -s ratio=16:9 -s resolution=1080p -s duration=20 -s count=1 \
  -s enableSound=off \
  --left 'CAR_FRONT' --left 'CAR_LEFT' --left 'CAR_REAR' --left 'CAR_RIGHT' \
  --left 'CAR_INTERIOR' --left 'SCENE_PORTICO' --left 'SCENE_ROAD' \
  --prompt '<仅含参考语义、完整多镜时间轴、画面动作及风格物理约束的提示词>'

# 提交前检查本段实际入边、模型、总时长和完整提示词。
libtv node 'CAR_CLIP_01_v01' -p '<画布UUID>'

# 仅在本段视频执行已经获准时触发一次。
libtv node 'CAR_CLIP_01_v01' -p '<画布UUID>' --run
```

示例中的所有上游名称必须真实存在；如果本段没有内饰或没有道路，删除相应连线与提示词引用，不为满足模板生成多余资产。使用板而非裁图时，连接实际 `CAR_4VIEW`，并写清板的用途；不要同时混入相互冲突的旧版板与新视角。

长提示词建议保存成UTF-8文本，读取后用 Python `subprocess.run([...])` 的参数列表传给 `--prompt`。CLI并未提供本次已核验的 `--prompt-file`，不要发明这个选项；也不要把任意提示词直接拼进shell，让引号、反引号或`$()`被执行。
