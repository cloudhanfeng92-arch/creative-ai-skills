# 车辆、内饰与场景参考资产

本流程先完成剧本与分镜，再依据镜头实际可见内容规划参考资产。用户上传车辆图像后，自动规划汽车四视图；在出图批次已获确认的范围内执行。参考资产供 Seedance 的多图参考工作流约束身份、结构和空间，不按镜号逐张制作首帧。参考图数量与剪辑镜数没有一一对应关系。

## 1. 先按分镜列资产，再提交出图批次

逐镜标记会露出的车辆方位、部件、座舱区域和主要场景，建立 `镜号 → 参考资产 ID → 用途` 映射。只为缺失且确实可见的内容补资产；用户原图足够清晰时直接引用，不为凑格或凑张数重新生成。

| 需求 | 资产决定 |
| --- | --- |
| 用户上传车辆图像，要制作该车宣传片 | 默认规划一张外观四视图板：正前、车身左侧、正后、车身右侧；先核对四面证据与未知部位 |
| 全片仅展示外观 | 不生成内饰卡 |
| 分镜包含驾驶舱、后排、门板或从窗外看到的清晰内饰 | 先核对相应区域的用户照片；仅生成会被看到的内饰参考，必要时合成一张内饰卡 |
| 要完成开门、后视镜展开、顶棚开合等机构动作 | 查明结构和动作前后状态；必要时在已确认清单中补同一部件的状态参考，不默认新增一套全车图 |
| 同一主要地点反复出现，或有反打、有限绕行、出入口和路线关系 | 建立该场景多视角卡，锁定空间锚点和照明方向 |
| 仅一次无背景微距，或环境只有模糊色块且不会换角度 | 无需专用场景卡；保留光线、材质和背景简述 |
| 已有场景照片足以约束相关机位 | 直接使用已验收照片；仅补确有缺口的方位 |

所有新图使用用户指定 **Lib Image 2.5 Pro（用户称 GPTimage2.5）**。执行时以 LibTV 实时目录中的身份、参数和能力为准；不能因借鉴场景卡的排版而改用其他 Skill 的默认模型、降级模型或擅改质量。

出图前展示一份具体批次清单：资产 ID、用途、完整提示词、来源图 ID、已知与推断项、模型执行名、画幅、分辨率、质量、每项张数、总张数和预计费用。费用无法确认时写“未知”，不能虚构报价或零成本。把四视图板、所需内饰卡、所需场景卡及可能的状态补图分别列项，先取得用户对这一批的确认。

已有授权覆盖同一提示词版本、数量、参数和预算时继续执行，不额外要求逐图审批。此前“出图前确认”的要求不等于必须每张都重新问；对图片内容的接受与新增付费出图授权分开记录。新增卡、扩大数量、修改已批准内容或重试超出范围时，先展示变更及费用，再执行。局部不合格只定向修正相关资产；同一错误连续出现时改视角、减动作或避开该部位，不无限追图。

## 2. 四视图的身份与证据

默认外观板为 **2×2**：左上正前、右上车身左侧、左下正后、右下车身右侧。方位以车辆自身为准：驾驶员正常朝前时的车辆左边就是车身左侧，不以观看图片时的屏幕左右命名。左侧与右侧是两个真实观察方向，禁止把左侧镜像当作右侧；充电口、油箱盖、单侧饰件、车门和方向盘位置按证据分别核对。

四视图是同一辆车的四次观察，不是四辆车。统一车漆、车身尺寸比例、轴距、车顶、格栅、灯组、轮毂、门把手、镀铬、玻璃、徽标、号牌处理及车门开闭状态；前后视图轴线端正，侧视图完整显示轮廓，不裁车轮或车尾。

对每项结构记录：

- `observed`：能在指定用户原图中直接辨认；写来源图和可见区域。
- `user-confirmed`：用户明确说明的配置；保留原意。
- `inferred`：合理但未经证实的视觉补全；明确列出推导依据和待接受项。
- `unknown`：既无证据也未接受补全方案；不能当成真实车型配置传下游。

单张前侧照片不能证明尾灯、另一侧接口、车顶细节或内饰。可以先完成证据充分的外观视图，不因内饰缺图停掉所有外观准备；但“没有内饰照片”也不是允许随意补尾部的理由。若四面不能一次可靠完成，先生成已知方位的单视图，或在审核板中将未知格明确留空并在板外标注待补证据；未完成格不能算有效四视图，也不得传给视频模型。

需要补全时，优先使用用户补充照片或用户确认的真实配置；合理推导方案标 `inferred`，用户接受后才能成为本片的视觉设定。生成图和用户接受的设定都不能倒推为真实车辆事实。若用户已明确授权接受某范围的合理视觉推导，则记录范围后继续，不重复审批；范围之外的关键结构仍待解决。避免仅凭品牌、相似车型或文件名补出具体年款配置。

## 3. 内饰与场景卡

### 内饰：按镜头所见补齐

需要内饰时，默认考虑四种视图，按实际镜头选择：前舱驾驶视角、仪表台与中控、后排整体、指定侧门板。左右舵、屏幕数量与形状、方向盘、旋钮和档把、座椅排数、头枕、缝线、饰板、门把手、车顶和氛围灯须能对应同一套座舱。

缺证据时先说明具体缺口，并请求对应图；也可由用户接受明确标记的概念内饰或暂不展示该区域。不能把常见品牌内饰搬进目标车，也不能把前排门板直接镜像成后排或另一侧门板。内饰卡可与已知外观资产并行准备，但未确定的内饰不能进入视频执行批次。

### 场景：先锁空间，再展示角度

仅为确需保持空间连续性的主要地点制作卡。默认覆盖建立全景、反打、左侧、右侧和俯视平面关系；机位数量依据镜头需求，可合成一张多视角卡。俯视图用于说明结构、路径和相对方位，不直接作为写实视频的画面参考。

先指定场景原点、车辆停放点或行驶线、主入口、固定建筑/柱网/路缘、背景地标、主光来源和摄影机方位。各视图绕同一组锚点换角度，反打后保持门、柱、车道和光源的实际位置，不重新设计另一个地点。背景物体保持数量、比例和相对位置；有意的光照或天气变化须在剧本中另有段落。

场景卡优先为空场，不生成另一辆示例汽车；需要示意目标车位置时，仅在平面关系图里用简洁定位框或箭头标记，写实视图保留预留空间。多角度只表示同一个场景，不表示多个并排的空间或需要同时入镜的地点。情绪参考图只能指导色光，不自动覆盖已锁定的几何布局。

## 4. 资产编号、来源与使用

可采用以下编号；项目已存在编号时保持一致，不另起冲突命名：

| ID 示例 | 内容 | 下游职责 |
| --- | --- | --- |
| `SRC_CAR_01`、`SRC_INT_01`、`SRC_SCENE_A_01` | 用户原始车辆、内饰、场景图 | 事实来源；保留原文件 |
| `CAR_EXT_BOARD` | 外观四视图审核板 | 审核与展示，不直接作为首帧 |
| `CAR_EXT_FRONT / LEFT / REAR / RIGHT` | 从合格格裁出的单视图或独立图 | 车辆外观身份与对应方位结构 |
| `CAR_INT_BOARD` | 内饰审核卡 | 审核座舱一致性 |
| `CAR_INT_DRIVER / CONSOLE / REAR / DOOR_L` | 相应内饰单视图；门板加明前后排和左右侧 | 座舱布局、材料和部件结构 |
| `SCENE_A_BOARD` | 场景 A 多视角审核卡 | 核对空间关系 |
| `SCENE_A_EST / REVERSE / LEFT / RIGHT` | 场景 A 独立写实视图 | 场景几何、背景与光线 |
| `SCENE_A_PLAN` | 场景 A 俯视关系图 | 编写镜头和判断空间，不默认输入视频 |

每项记录 `asset_id、entity_id、asset_role、source_ids、view、evidence_status、inferred_items、prompt_version、model、generation_job_id、file_path、crop_source_and_bounds、accepted_scope、qa_status`。未生成或尚无任务 ID 就留空；用户原图无需伪造生成信息。外观、内饰共用同一 `entity_id`（例如 `CAR_01`），同场景各视图共用 `SCENE_A`，防止模型把参考数量理解为实体数量。

审核板通过后，优先裁出需要的合格视图；清除板框、分隔线、标题、编号和注释，不把这些内容带进视频。含俯视平面示意图、路线箭头或大量文字的场景卡必须裁出写实视角，示意图只用于编写空间描述；纯写实且各格清楚的参考板可以整张绑定，并明确禁止版式出现在视频中。裁切保留完整主体和必要空间，不靠放大补不存在的细节。板的总分辨率不等于每格分辨率；单格不足以辨认轮毂、灯组或屏幕时，优先用清晰用户原图，否则提出该部位的新增图计划。

提交视频时按镜头选最少且相关的独立图：车辆方位、必要内饰、对应场景各有明确职责；不把所有板和所有角度一股脑加入。实际引用数量、尺寸及可用模式以当前 Seedance 2.5 接口能力为准，不捏造上限。提示词明确“这些图展示同一辆车/同一个场景的不同角度，最终画面只有一辆目标车和一个连续空间”。它们是身份、结构和空间参考，不要求视频复现板布局或所有参考构图。

若某镜确需精确首帧，说明这需要切换工作流；仅在用户明确选择切换后，才可使用现有合格照片或另行规划首帧。保持本版时通过参考图、文字构图与分段调整，不静默转首帧模式，也不退回“每镜先出首帧”。

## 5. 出图提示词模板

将占位符替换为已观察、已确认或已接受的具体内容。执行前显示完整实填文本，不提交含糊占位符。以下模板中的格子、编号只是资产板排版；视频制作时可使用清晰的纯写实参考板，也可裁出干净视图分别绑定，含平面示意图或箭头的板须裁出写实视角。提示词明确这些视角均属于同一主体或地点。示例文本只提供格式，不继承其他作品的人物、剧情、车辆配置或音色。

### A. 汽车外观四视图板

```text
制作一张用于汽车宣传片身份一致性的专业汽车外观四视图参考板。参考图 {来源图 ID 与用途} 中的是同一辆 {已确认车型/代次；未确认则描述可见造型}，本图四格均为这同一辆车的不同观察角度，不是四辆不同汽车。使用写实汽车摄影质感，完整保留真实车身比例与可辨结构，不做概念改装。

版式为2×2，等大干净画面：左上为正前视图，右上为车身左侧完整正侧视图，左下为正后视图，右下为车身右侧完整正侧视图。左右侧按车辆自身方向定义，分别重建相应可见结构，不使用镜像替代。各格保持相同车辆尺度、水平地面与合理车高，车体完整落在画面内，轮胎全部着地。前后视图中轴端正，侧视图完整露出前后轮和车身轮廓，避免夸张透视。

锁定外观：{车色与双色分界}；{车身轮廓、车顶、轴距比例}；{格栅和前保险杠}；{头灯与尾灯结构}；{轮毂和轮胎}；{门把手、后视镜、窗框和镀铬}；{徽标、号牌处理}。左右侧差异分别为 {有来源的左右差异；未知则明确不臆造}。车门 {关闭/已确认状态}，车轮 {静止及朝向}，灯光 {已确认状态}。每格保持这些配置一致。

证据优先级：用户原图和已确认配置优先；已接受的视觉推导仅限 {逐项列出，或“无”}。仍未知而未接受的区域为 {列表}，对应格留空供后续补参考，不制造可被误认为真实配置的细节。不得把其他年款、另一种轮毂或品牌常见配置混入。

背景为 {中性浅灰/约定背景}，柔和均匀照明，受控的车漆与镀铬反射，清晰展示形体、灯组和接缝，不添加戏剧化烟雾、强烈眩光或道具。格内不含标题、编号、边框、说明文字、水印和人物；必要格名后期放在格外。四格相互分离，不出现跨格拼接车身、重复车轮、额外车辆或不可能结构。画幅 {画幅}，分辨率 {已批准分辨率}，质量 {已批准质量}。
```

部分方位缺证据时，将上文改成明确列出的单视图或留空格方案，并在批次中调整有效视图数量；不要让一句“保持真实”掩盖缺失资料。


## 6. 逐视角验收与放行

1. **证据**：逐项对照来源；未确认的推导仍标 `inferred`，不能因生成图精致就改为 `observed`。记录用户已经接受的范围，避免重复征询。
2. **外观**：四面是同一车，检查比例、双色边界、灯组、车门、轮毂、徽标和单侧差异；左侧镜像、混年款、轮数错误或未知部位伪造均不能通过。
3. **内饰**：检查左右舵、前后排关系、屏幕与控件、座椅、缝线、门板和车顶；外观、内饰分别验收，不能以“参考图已完成”掩盖内饰缺口。
4. **空间**：场景反打和左右角度能对应同一入口、柱网、道路和光源；平面图与写实视图不相互矛盾。无法对应的格隔离，不扩大为多个地点。
5. **可用性**：实际查看板和裁图，确认主体完整、细节够清晰、无格线/标签残留、文件存在且可打开。可读性不足不能靠自动放大宣称修复。
6. **放行**：合格视图可继续供已授权镜头使用，坏格单独标记并移出引用。补图确有必要时只提交该缺口的修正计划；可用已有视角改写镜头时，优先调整分镜以减少无效重试。
