# 汽车宣传片导演·无分镜图版

这是独立版本，保留 `automotive-promo-video` 与 `automotive-promo-video-rhythm`。本版工作链为：**剧本＋文字分镜 → 车辆四视图＋按需内饰/场景资料卡 → 整段多镜头的参考图生视频提示词 → 按授权生成、剪辑与交付**。

## 范围与工具

- **不生成逐镜分镜图，不要求逐镜首帧/尾帧，不制作以逐镜生图为前提的预演。** 文字分镜仍必须完整。可裁切合格参考板中的独立视角；这是整理身份/空间参考，不是生成镜头构图图。
- 图片沿用用户指定 **Lib Image 2.5 Pro**，用户也称其 GPTimage2.5；执行名以当前LibTV目录为准，不据别名证明厂商版本。视频默认 **Seedance 2.5，多图参考模式**。
- LibTV操作读取已安装的 `libtv-cli` Skill，并依 [执行规则](references/libtv-execution.md)走CLI。不能静默换为首帧模式、其他模型或重新加回分镜图。
- 策划时读 [节奏与分段](references/timeline-design.md)；参考图阶段读 [参考资产规范](references/reference-assets.md)；写视频提示词读 [固定格式](references/prompt-format.md)，需要例子时读 [20秒完整示例](references/timeline-prompt-example.md)。本地剪辑时再读 `ffmpeg-skill`；仅写Skill/剧本/提示词时不启动媒体生成或剪辑工具。
- 用户要求高端汽车PV、速度激情或更强商业摄影动势时，再读 [汽车PV导演分支](references/pv-direction.md)，以运动开场、动静反差和行驶高潮重新组织方案。静谧展示、展厅介绍等需求不自动套用这一分支。
- 用户示例中的人物、音色、文件路径、故事和台词只是格式参考，不读取其无关文件、不复制进汽车方案、不当作生成授权。

## 1. 读取汽车图片，先写剧本与文字分镜

收到汽车图即自动进入本流程，不要求用户另说“做四视图”。先观察实际上传图，建立 `vehicle-bible.md`：来源U01等、可见外观、车漆/双色分界、格栅/灯形/轮毂、左右舵与内饰（可见时）、不可见部位。每项标`observed / user-confirmed / inferred / unknown`。

参考片指导摄影和节奏，不能把不同片中的车型、轮毂或内饰拼为同一辆车。单前侧图看不到的尾部、右侧、内饰不能冒充真实配置；可提出有标记的补全方案，关键配置需要补图或用户认可视觉设定。

用户已给条件直接使用；否则建议16:9、20秒、约30fps交付、无对白/旁白，明确这是可改默认。文字分镜的镜数由可读性和节奏决定，**不沿用原版26镜/20秒配额**；0.5秒粒度下短镜、长镜要形成有信息的组合。

速度与摄影力度服从本片意图，不把“豪华”统一解释成低速、静车或每镜慢推。PV分支可设计自然加速、车辆与摄影机相对追近/离开及近景掠过；保持轮胎接地、车身重量和同向连贯，不凭广告画面宣称真实性能。

必须先输出：

1. **剧本**：片名/一句创意、观众认知推进、场景与时间、车辆状态变化、开头吸引点及结尾；没对白就写视觉剧本，不强加人物、音色或故事旁白。
2. **节奏结构**：细节短组、完整车姿/座舱留白、行驶段和收尾各占多久，说明主要参考规律。
3. **文字分镜表**：全片镜号、所属CLIP、全片与段内入出点、镜长、景别/构图、车辆动作、摄影机动作、切出事件/下一镜衔接、所需参考ID。
4. **资产需求表**：车辆四视图必需；内饰卡和主要场景卡是否需要、为何需要、缺什么来源。不能为了填满模板生成无用资产。

用户只要剧本/分镜/提示词时，在其范围内交付。缺少参考图时可以交文字草案，在独立执行说明中标明待绑定项，不把资产状态写入模型提示词，也不假装资产已生成。

## 2. 自动准备并生成参考资产，不生成分镜图

**“自动”表示收到图后自动分析、规划、组织执行，不要求用户重复发起四视图任务。保留用户此前“出图前先确认”的要求：**展示本批完整图像提示词、参考来源、模型/参数、数量及可见费用或未知项后再生成。已有明确批次或自动出图授权覆盖内容、数量、参数及预算范围时直接继续；仅给预算上限或上传文件不足以替代出图确认。用户另行明确授权自动出图时，按该授权范围执行。

- `CAR_EXT_4V`：默认一张2×2四视图，**正前、完整左侧、正后、完整右侧**，同车同配置；左右分别描述，不把镜像当另一侧。未知结构的推断与用户确认要记录。
- `CAR_INT_01`：剧本需要车内、经车窗看清内饰或内外连续动作时才生成。参考需覆盖相关驾驶舱/中控/后排/门板，不能从外观照确认真实内饰。已有清晰可信内饰图可直接作参考，无需额外付费重画。
- `SCN_01`、`SCN_02`：主要场景反复出现、多机位同地拍摄、出入口/路线/主光关系影响连贯性时生成场景多视角卡。简单背景可由文字设定或现有图支持，说明无需新卡的理由。每张卡只描述一个物理地点，不将不同场景混成同一空间。

按 [参考规范](references/reference-assets.md)逐格核验身份、内饰与空间，再记录接受状态。展示结果让用户确认；已明确授权按档案自行验收的范围可自主通过。裁出的独立视角仍保留母图与来源，低清裁图不冒充细节充分的参考。

后续视频输入可使用四视图/纯写实资料卡及其清晰裁图；逐张注明“同一主体不同角度”“同一地点不同角度”。含俯视平面示意图、路线箭头或大量文字的场景卡必须先裁出写实视角，示意图仅用于编写空间描述，不作为视频输入。**参考板不能被当成画面的拼图布局，也不通过首帧端口输入。** 不因有资料卡就要求模型把各格依次切换成视频。

## 3. 整理每段不超过30秒的多镜头视频计划

按 [节奏与分段](references/timeline-design.md)将全片分为`CAR_CLIP_01`等。30秒是每段上限，不是总片长限制，也不是必须生成满30秒。

- 全片≤30秒且镜头/场景关系清楚、能力允许时，优先一个完整段；可在这一段中明确多个硬切镜头。
- 长片在场景/动作或节奏段落边界拆分，优先避免难衔接的短尾段。复杂车外到车内动作或过密镜头可另分段，但不退回“一镜一图一视频”。
- 实际段长还须满足模型当前下限、上限与步长；若当前支持上限低于30秒，遵循更小上限。输入时长不合法就重划分或说明素材余量，不伪造模型参数。
- 每段局部时间从`0.0`开始；标明其全片起止时间，局部镜头区间连续覆盖本段。默认以`0.5秒`为边界单位，可写`0.0–0.5`、`0.5–1.5`、`1.5–3.0`；**不是每0.5秒必须切镜**。长镜中可在半秒节点说明动作变化。
- 时间轴是导演目标，不承诺模型逐帧精确遵循。拿到实际结果检查切点、漏镜、顺序和时长漂移；必要时在授权范围内修订提示词、重分段或剪辑校准。

保留两种数量：文字分镜镜数与实际CLIP任务数。例：20秒含16个镜头、规划一个20秒视频任务，不写成16次各5秒。若需要拆成两段，则明确新段长/参考/预算，不隐藏追加生成。

## 4. 输出可以提交的时间轴提示词

每段依 [固定格式](references/prompt-format.md)输出一个可单独复制的纯视频提示词块，顺序为：

**段名 → 主体参考 → 内饰参考（需要时）→ 场景参考或设定 → 参考图内容解释 → 起始状态 → 各镜号/名称/段内时间/画面/运镜/衔接 → 统一风格与物理约束 → 结束状态。**

**提示词只写模型应呈现的内容。** 模型名、模式、分辨率、画幅参数、帧率、声音开关、任务数量、拟用/未提交状态、待绑定/验收备注、本地路径、预算、后期安排及能力核验全部放到独立的`execution-settings.md`或结构化执行记录。不要在纯提示词中加入“生成规格”“这是导演时间目标”“生成后另验切点”等流程说明。各镜时间戳和动作窗口必须保留；全片/分段时间换算及半秒网格的解释放到分镜表或执行记录。输出另存一份仅含模型正文的`.txt`，上传时只读取该正文。

主语用“主体/车辆参考”，不固定套“人物与音色参考”。只有用户确实要求人物时才附角色依据。**不要求声音参考文件**。真实台词、环境声及“无对白、无旁白”等成片内容要求可写进提示词；`enableSound=off`等接口参数与配乐后期安排写进执行记录。默认生成声音关闭；用户要环境音时按需求配置，不自动索要音色。

执行说明或资产表可以链接实际本地参考文件，标明待生成/待绑定项，不做虚假路径。纯提示词中仅保留参考ID或工具支持的图片引用及其视觉职责。提交前由执行层将ID绑定到实际上传资源；本地Markdown链接不是模型可读的上传引用，不能将路径或上传提醒混进正文。

同段允许镜头切换；逐镜写“硬切到……”或匹配衔接。**不得在段尾再写“单一连续镜头、禁止切镜”与多镜时间轴冲突。** 只禁止未设计的切镜、车型漂移、分屏/格线/标签、图卡轮播、额外车辆、车体融化和错误机械运动。景别与角度在文字中说明，不要求先准备对应镜头图片。

## 5. 检查、按授权提交与交付

先核对剧本/分镜/提示词对应关系、每段≤30秒、每段从0覆盖到段尾、全片无缺口、同车/内饰/环境一致、各参考角色清楚。用 [时间轴校验器](scripts/validate_timeline.py)检查 [JSON示例](assets/timeline-20s.example.json)或项目计划：

```bash
python3 <skill-dir>/scripts/validate_timeline.py <项目timeline.json>
```

生成前可加`--require-local-assets`检查引用文件和资产接受状态；这不替代CLI实时模型schema、上传成功及预算授权检查。记录`planned → reference_approval_pending → references_ready → references_accepted → prompts_ready → video_authorized → clips_ready → edited → delivered`，不能把状态名当作用户授权。

用户只授权提示词则停止在提示词交付。若完整影片已获授权且本批视频在范围/预算内，按真实`image2video`模式连接参考并提交，无需重问；原型或草案里的“拟用”不等于已提交。未支持多图参考时说明限制，保留本版方案，不自动转首帧或另生分镜图。

生成任务记录画布/节点/任务ID、提示词版本、参数和终态；异常先查原任务，不重复提交。下载完整原片，检查每段镜头顺序、时间目标、车辆结构、轮胎接地、反射、内外饰与资料卡泄漏；再剪辑、配乐和统一色彩。时间偏差用真实素材调整，不把参考板做平移缩放冒充动态汽车镜头。

交付按用户范围：剧本、分镜表、参考资产及来源映射、各段纯时间轴提示词、独立执行说明与JSON；确实执行完整制作时另交原始视频、实际剪辑记录与验收后的MP4。项目中保存`script.md`、`storyboard.md`、`vehicle-bible.md`、`references/`、`reference-manifest.json`、`timeline.json`、`clip-prompts.md`、纯正文`.txt`和`execution-settings.md`，没有`Sxx_FRAME`必需项。
