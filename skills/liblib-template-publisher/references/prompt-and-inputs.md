# 玩法描述、参考图与风格备选

编写提示词或设计输入时读取。以下是本技能设计示例，不是已在哩布验证的模板；需通过当前页面解析与实际测试确认。

## 玩法写法

固定部分描述持续成立的视觉规则，可变标记只承载用户确实可以修改的内容。采用页面提示的括号语法，先用最少必要变量，检查是否被解析成预期控件。

例如纯文本玩法“宠物探险徽章”：

```text
为【宠物品种或名称】设计一枚探险队徽章。宠物为主体，活动场景为【探险场景】。
保持清晰的徽章轮廓、统一的印刷插画质感与简洁背景；主体突出，场景作为辅助元素。
不要出现水印、额外说明文字或无关标志。
```

可准备“柯基／雪山营地”作为演示内容，测试改为“黑猫／热带雨林”。固定指令中不能再写“主体必须是柯基、背景必须是雪山”。重复标记是否合并、多标记如何展示，必须看实际解析，不预设行为。

若用户需要生成指定文字，可另设计 `【需要显示的标题】`，明确标题逐字输出；只有检查真实图中文字后才声称文字能力通过。不要为所有玩法强加标题字段。

对于“上传照片换装／宠物变玩偶”等玩法，先核实当前模式是否真正允许终端用户上传或替换图片，再编写身份保持、服装或材质变化规则。不能仅通过 `【上传一张照片】` 的文本说明虚构图片控件。

## 图片的五种角色

| 角色 | 用途与证据 |
| --- | --- |
| 固定参考图 | 作者固定在模板中的视觉约束；记录顺序、来源和角色，不宣称用户可替换 |
| 用户输入图 | 使用者通过实际控件提供；确认进入测试与生成，记录可用张数与顺序 |
| 演示源图 | 为测试准备的输入；不是模板效果，用户指定素材优先 |
| 结果／示例图 | 本模板实际生成；关联版本、输入、任务或时间与输出证据 |
| 封面 | 用于展示玩法；排版图不能冒充未经修饰的模板输出 |

缺少演示输入时先使用用户提供或明确可用的素材。若确需生成素材且任务范围允许，使用当前可用生图工具，保存来源并标为演示输入；不凭其它技能曾有的图库授权读取无关图库。涉及用户指定身份时保留原始参考，不换成自选人物。没有合格真实结果时不得用宣传图补成“已测试”。

## 风格模式

用户明确选择风格模式，或需求明确只需“任意主体统一转成某种画风”时，可采用此备选模式并说明选择，无需为常规模式选择重复确认。在当前风格表单配置持续成立的规则，例如细线勾勒、有限矿物色、纸本颗粒、平面构成、留白比例；把特定主体与场景留给真实可用的用户输入。因玩法受限而需要改变原功能时，先说明差异并取得用户选择。

先确认风格表单允许如何描述、引用和替换素材，不能照搬玩法字段。用已有的不同主体合格结果展示一致画风；没有结果时按预算做最小测试，不强制五组示例或一整套参数组合。
