# 工作流、提示词与演示设计

## 选择节点而非套用节点名称

普通图生图使用 `image-nodes.md` 中的用户节点；额外节点只在实现效果需要时添加。可选方向包括裁切/缩放、遮罩、抠图、多图融合、文字输入、拼接或替换。优先当前 RunningHub 已安装且端口类型兼容的节点；不要因为其它平台存在同名节点就直接写入 JSON。

在编辑器“节点库”搜索功能词，查看节点说明、输入/输出和 widget。必要时在本任务独立工作流中插入一个节点并从 UI 导出，用导出内容确认 class 和字段。由 UI 导出的工作流 JSON 与“导出工作流 API”不是同一种文件；保留用途清楚的文件名。

2026-10-12 在当前节点库搜索 `concatenate` 可见 `Concatenate Text`、WAS Suite 的 `Text Concatenate` 和 Comfyroll Studio 的 `🔤 CR Text Concatenate`。这些是已见候选显示名，尚未验证 class 和端口；按上述步骤选取并验证，不能直接把显示名当作 JSON class。

修改图结构同时保持顶层 links、源 outputs.links、目标 inputs.link 一致；图片链接必须为 IMAGE，文本链接必须为兼容的 STRING。有多个 LoadImage 时，用中文节点名/公开标签标明 Image 1、Image 2 的角色。确保没有悬空必填端口、循环或无效占位图。

## 固定效果

例如“照片变靛蓝蜡染”：固定 prompt 写全效果、主体保持、材质及必要排除项；仅公开图片、resolution、aspectRatio。不要添加“创意主题”文本、五个不相干主题或空文本节点。

## 可变玩法

例如“宠物做厨师”：

- 固定规则：保留上传宠物的毛色、眼睛和品种；生成拟人厨房场景；姿态自然；成像和安全要求。
- 可变内容：菜品、厨房风格、情绪；这些具体值只放用户输入及示例，不在固定规则中写死“披萨”“法式厨房”等默认值。
- `final_prompt = fixed_rules + separator + user_creative_text` 是设计关系，不是已验证的 RunningHub 节点名称。找到真实文本拼接节点，确认 separator/输入顺序，并将输出连接至生成节点的 prompt。生成节点 prompt 被上游连接后通常由上游提供完整文本，不能假设其旧 widget 固定文字还会自动追加。
- 若使用“文本替换”，固定模板中放明确标记，替换节点只替换目标标记；核对替换字符串是否逐字匹配，避免误改主体保护或成像规则。拼接是追加，替换是改指定片段，不混称。
- 需要把 prompt widget 转成输入端口时，通过当前节点菜单操作并从 UI 导出确认；不猜测转换后的数组索引。
- 可准备三至五个有用英文例子，数量由玩法决定。只有发布页实际提供示例/预设配置时才宣称已配置；否则将可复制例子写入介绍，明确它们是说明中的例子，不是随机按钮。

选择原模板中不存在的节点时，先证明当前网站可用，再扩展工作流。无法实现变量链时保留可审阅草稿并说明缺失；不要把全部固定规则暴露给用户来冒充“只改主题”。

## 素材与封面

- 默认用当前可用内置生图能力生成原创演示输入；需要时读取该生图 Skill。选用已有用户素材必须符合本轮明确授权。
- 批量任务给每个应用分配不同主体/场景，保留素材清单及输入角色。人物优先多样的欧美成年面孔；题材或用户指定身份优先。服装覆盖完整，避开平台曾拒绝的暴露表达。
- 输入图、应用生成结果、营销封面分开记录。先有明确原图，才可能验证图生图；封面不得被误当试用结果发布社区。
- 封面延续 3:4 英文大标题和明确玩法示范，文字可读、主题突出；中文封面槽或 AI 站如果提出语言/尺寸要求，按当前要求调整。真实输出与封面预告应一致。
- 记录实际像素；prompt 中写“2K”不代表生成文件已经达到该尺寸。

## 运行与恢复

保留 SaveImage，平台编辑器提示“预览节点出图不显示在任务列表中”。结果存在但任务列表无图时先检查输出节点，不立即再次计费运行。

每次运行记录工作流/应用 ID、版本、模型、输入角色、公开参数、预估费用及单位、任务 ID、开始时间和状态。同名项目及全局任务历史不能只凭位置识别。

遇到容量或网络问题先核对是否已提交及完成，确认失败后才在预算内重试。选用备用模型必须实际改节点模板和字段映射，重新验证连线；不能只更改应用简介中的模型名称。
