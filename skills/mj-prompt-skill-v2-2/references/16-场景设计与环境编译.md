# 场景设计、尺度路由与环境编译｜V2.2

> 本 Reference 是 Scene / Environment 的结构权威。它负责回答“这个地方是什么、为什么这样形成、如何被使用、当前镜头应该控制到哪一层、摄影机物理上在哪里”。
>
> 核心链路：**Scene Read → Scale Router → Scene Structure → Use State → Human Presence → Macro Density → Camera Contract → Visual Organization → Prompt Compiler**

# 1. 职责边界

本 Reference 唯一负责：
- Scene Identity
- L / M / S 控制尺度
- 空间形成与功能关系
- 生命周期 / 维护状态
- Human Presence 策略
- 宏观信息密度
- Camera Contract
- 普通场景的 Visual Organization / Visual Finish
- Scene Prompt 的结构压缩

本 Reference 不负责：
- 架空文明的世界身份细节与功能地编：交给 `18`
- 明确电影化任务的最终观看路径、灯光、综合色域、空气、曝光、焦点、DOF 与光学响应：交给 `17`
- 导演 / 类型风格坐标：交给 `10`
- 传统构图词库：只在需要时查 `11`

`10/11/12/17/18` 无权修改本文件已锁定的 Scene Structure 与 Camera Contract。

# 2. COMMON｜跨尺度共同原则

## C00｜先设计，再编译

完整专业逻辑留在内部。最终只把会改变画面的高杠杆关系交给 MJ。

## C01｜控制粒度必须匹配镜头尺度

当前画面只能强控制当前尺度可读的关系。

典型错误：
- 城市鸟瞰精确控制台阶、单个桥头、小庭院、摊位；
- 房间任务重新描述完整城市规划；
- 为了执行小尺度关系让模型自动改变 Camera Scale。

## C02｜因果优先于元素罗列

先知道元素为什么在那里，再决定哪些结果需要 materialize。

## C03｜场景连续性优先于视觉技巧

构图、地标、疏密、视觉终点都不能破坏真实空间连通关系。

## C04｜设计规则与 Prompt 规则分层

专业设计上成立的原则，不代表必须原样写进 MJ。

如果某条设计原则在当前尺度无法稳定通过文字执行，将它编译成可见后果，而不是强行写术语。

## C05｜已锁定规则不被新变量重写

修改或测试时，只让目标变量及必要下游失效。已通过的 Scene Identity / Scale / Structure / Camera 继续锁定。

## C06｜图像设计先于风格渲染

跨媒介设计内核：`可辨认主体 → 可信结构 → 明确空间关系 → 有目的的观察 → 大形明暗与信息组织`。渲染方式依本轮用户/风格参考选择。真实尺度与物理因果是现实性任务的优先要求；明确象征、抽象或超现实任务可有意修改物理规律，但内部关系仍须自洽。

## C07｜主导视觉关系而非视觉元素数量

针对当前场景选择一个最具识别/理解价值的主导关系，例如：形体与空白、主次体量、地形与人造结构、路径与终点、内部机制与操作区域、近远尺度。只保留可在当前画面尺度读取的关系。不同题材不得套用同一个视觉母版。

# 3. Scale Router｜按控制粒度判断

尺度由**当前镜头覆盖范围 + 需要模型控制的设计粒度**决定，不由现实建筑绝对尺寸单独决定。

## L｜District / Large Environment

典型：
- 城市 / 首都 / 聚落
- 城区 / 港区 / 宗教区 / 校园 / 城堡群
- 大型建筑群
- 大型自然环境与人造系统

摄影机主要理解：
- Geography / terrain
- 3–5 个一级空间大形
- 区域肌理 / visual grain
- 主要系统及长期生长结果
- 城市与外部腹地的连续性

**Stop Rule：**
L 级不强控制抽屉、家具、单个摊位、单个门洞、精确小巷、局部台阶、单个桥头细节。需要这些信息时说明当前镜头实际上应进入 M / S。

## M｜Urban Node / Building Space

典型：
- 广场 / 市场节点 / 庭院 / 街区节点
- 大厅 / 机构公共空间 / 大型房间
- 建筑入口、服务区、公共平台

摄影机主要理解：
- 一个主要功能空间
- 2–4 个关键工作流节点
- 1–2 个主要连接方向
- 公共 / 后台 / 限制边界
- 建筑结构如何支持功能
- 中等权重视觉锚点

**Capacity Rule：**
M 级不因“首都 / 王宫 / 国家级机构 / 宗教总部”自动膨胀成：多层纪念平台 + 多组巨型阶梯 + 多座独立纪念建筑 + 巨型中轴。

机构身份决定等级与语言；**具体功能决定实际空间尺度。**

## S｜Human Scale

典型：
- 街巷 / 小庭院 / 走廊
- 商店 / 工作室 / 办公室 / 客房 / 宿舍
- 小型维修、制作、实验、储藏空间

摄影机主要理解：
- Primary Operation / daily use
- Door / window / threshold
- Main work surface / stall / furniture relation
- Local level changes
- Human movement clearance
- 高频支持与收纳
- 少量功能物

**Stop Rule：**
S 级停止调用城市规划逻辑。世界身份应通过近距离建筑构件、公共设施和日常系统表现，不用远景巨型地标证明世界观。

# 4. Scene Read

内部只回答：
1. **Target First Read**：第一眼必须读成什么？
2. **Adjacent Drift**：最容易被误读成什么？
3. **Differentiating Relation**：哪一条可见关系最能区分两者？

身份优先来自：
- 空间原型
- 工作流 / 操作关系
- 交通 / 邻接关系
- 机构化系统
- 请求规模的可见后果

身份不优先来自：
- 泛题材标签
- 装饰数量
- 长道具清单
- 单一超强地标

如果第一读取只能靠题材名词成立，Scene Read 未通过。

# 5. Scene Structure

## 5.1 L｜空间形成因果

内部推导：

**Geography / Resource → Access / Transport → Primary Systems → Large Masses → Growth Pattern → Current Urban Fabric**

只保留真正改变一级形态的因果。

### L01｜空间形成因果

地形、水系、运输、历史与功能共同决定空间如何形成。

Prompt 不需要写完整因果链，只写其可见结果。

### L02｜一级大形优先

先建立 3–5 个缩略图尺度可读的大形，再允许复杂细节。

可包括：
- 地形 / 水系开放带
- 连续城市主体量
- 历史 / 行政 / 宗教核心所在的较高权重区域
- 工作 / 交通带
- 外围腹地

这些大形应通过连续街区、覆盖率、道路网络、建筑密度与高度渐变表达。

避免：
- 把区域切成孤立平台；
- 用大量中小构件硬解释一级关系；
- 空地上散落无归属建筑碎片。

### L03｜视觉颗粒层级

大尺度疏密优先通过：
- building footprint size
- urban grain
- coverage ratio
- spacing
- continuity

而不是随机制造空地。

典型：
- 高频细颗粒：密集小体量、连续屋顶、窄街巷；
- 中频粗颗粒：较大公共 / 机构建筑、较宽间距、更多可见地面；
- 低频开放带：水岸、运输、广场、外围生产 / 农业空间；
- 城市边缘：连续肌理逐步打断，而非突然切线。

变化必须由功能与生长逻辑解释。

### L04｜地标等级：设计原则保留，Prompt 谨慎编译

场景设计层应存在权重差异，但城市级 MJ 纯文字容易把 `primary / secondary landmarks` 放大成多个巨型复合体。

因此：
- 用户确实需要明确地标时，优先具体描述 **一个** 关键地标的形态与空间关系；
- 不默认显式要求一组 `secondary landmarks`；
- 其它节点优先通过自然城市肌理与系统差异从属；
- 重要性不靠独立高台、围墙或孤岛式分区实现。

### L05｜交通动线：设计层必须成立，远景编译成城市形态

设计层必须知道：
- 人 / 货从哪里进入；
- 主要交通如何连接功能节点；
- 哪些是一级路径，哪些是次级路径。

但高位城市鸟瞰中，不默认要求 MJ 精确画出完整道路线路。

优先编译为宏观后果：
- dense fabric extending along historic access corridors
- commercial growth concentrated near transfer nodes
- working waterfront connected to adjacent trade districts
- urban grain bending with terrain and long-term routes

只有当前镜头尺度足够、或用户明确要看交通节点时，才要求具体道路 / 桥 / 门的可追踪连接。

### L06｜连续性

核心区、旧城、外围、河岸或高地之间应通过：
- density gradient
- terrain transition
- continuous building fabric
- roads / slopes / terraces at readable scale

形成连续城市，而不是多个主题公园式独立区。

## 5.2 M｜功能原型与节点

内部推导：

**Functional Archetype → Workflow → Key Adjacency → Public / Restricted Boundary → Architecture Shell**

### M01｜空间原型优先

完整行为流程只用于内部设计，最终只输出能改变布局的 2–4 个关键邻接关系。

不要把：
`entry → registration → wait → check → permission → internal access`
逐项写成 Prompt 教程。

应压缩成类似：
`reception beside the public entry, waiting directly adjacent, a clear circulation zone leading to controlled internal access`。

### M02｜功能行为簇

功能区不是靠单个代表性物件成立，而由少量相互支持的元素形成一个行为系统。

例如接待簇：
`counter + information surface + document storage + usable queue / working clearance`

行为簇的具体地编由 `18` 执行；本文件只决定该簇是否需要、在哪里、与谁邻接。

### M03｜建筑身份与功能尺度分离

世界观 / 机构等级决定：
- 结构品质
- 材料语言
- 适度层高
- 权威感

具体房间功能决定：
- 实际面积
- 工作距离
- 家具 / 服务设施视觉权重
- 通行尺度

国家级机构里的日常接待厅仍然可以是人尺度行政空间，不必变成圣堂中殿。

### M04｜行为热点密度

宏观空间必须保留：
- 功能热点：信息较高但受控；
- 主要通行：清楚、畅通；
- 低频区域：视觉更安静。

局部物件如何聚合交给 `18`。

不得把“低频”翻译成灰尘、杂草、废弃。

不得用精确微观磨损作为该规则的主要执行语言。

### M05｜结构与功能对齐｜内部检查项

这条作为内部合理性检查，不强制独立写入 Prompt；只有结构明显与功能冲突时才 materialize。

柱网、主要拱券、墙体、门洞、楼梯应支持：
- 功能区边界
- 主要交通
- 服务 / 限制转换
- 空间节奏

不能像另一套装饰系统随机生成。

### M06｜Shell Removal Test

内部暂时删除建筑风格词，只看功能关系。

如果仍无法区分：
- archive vs library
- administration vs courtroom
- clinic vs generic office
- reception hall vs ceremonial hall

说明功能原型仍不够强。

## 5.3 S｜人的直接使用尺度

内部推导：

**Primary Operation → Main Work / Use Surface → High-frequency Support → Local Movement → Secondary Zone → Low-frequency Storage**

### S01｜Primary Operation first

先判断这个空间最主要做什么：
repair / fabrication / inspection / cleaning / preparation / diagnosis / assembly / living / retail / waiting 等。

空间应围绕主动作成立。

### S02｜主工作面 / 主使用面

主工作面必须有足够净空，并与高频支持系统形成近邻。

长期使用不等于桌面塞满。

### S03｜少量高区分度锚点

职业 / 功能身份通常只需要 2–4 个强锚点：
- 主工件 / 主商品 / 主操作对象
- 关键工具 / 设施
- 专属收纳 / 待处理系统
- 必要第二功能区

优先写关系，不写百科清单。

### S04｜第二功能区只在改变布局时进入

例如 intake / washing / testing / damaged-item holding。

如果不改变动线与空间，不为“完整”强加。

### S05｜相邻职业漂移

主动检查：
- repair workshop → junk room / antique shop
- jewelry restoration → retail boutique / watch showroom
- laboratory → sci-fi control room
- prop workshop → costume room / warehouse

删除更像错误原型的强身份锚点。

# 6. Use State

先锁：
- Active / Maintained
- Active / Worn
- Inactive
- Abandoned
- Ruined

状态是形态许可边界。

## Active / Maintained

先读成：
- structural surfaces intact
- functioning fixtures
- usable doors / glazing / storage
- clear circulation
- maintained work surfaces
- localized replacement / repair

历史感可以来自：
- material maturity
- additions and replacements
- building generations
- restrained local use state

不要用 `worn + weathered + peeling + dusty + damaged + crumbling` 的串联证明历史。

## Active / Worn

允许较明显粗粝和长期使用状态，但：
- 主结构完整
- 设备可用
- 主工作面可操作
- 通道正常

## Inactive / Abandoned / Ruined

只有这些状态才逐步开放：
- dust accumulation
- vegetation intrusion
- broken fixtures
- debris
- exposed structure
- collapse

## Damage Ownership

维修 / 修复类 Active 场景中，主要破损优先属于**被处理对象**，不是房间本体。

# 7. Human Presence Policy

默认：**No character subject**。

不是默认 `--no people`。

环境人物可以用于：
- 运行证据
- 尺度参照
- 流线证据

要求：
`small-scale, subordinate, no character focus`。

明确排除人物：
- 用户要求无人；
- 建筑 / 空间资产母版；
- 纯结构测试；
- 人物会干扰目标读取。

# 8. Macro Detail Density

宏观信息密度形成：

**concentration → transition → decay**

- 复杂区集中在主要功能 / 空间转换。
- 安静区仍然完整、有材质信息，但缩略图先读成大面。
- 宏大感依赖大面与局部精细的尺度差，不依赖全图高频。

本节不决定局部桌面 / 摊位 / 功能物的摆放；局部 Set Dressing 归 `18`。

# 9. Camera Contract

Camera 必须形成唯一物理状态：
- **Physical Location**
- **Relative Height**
- **Viewing Direction**
- **Pitch**
- **Distance**
- **Focal-length Class**
- **Frame Coverage**

用户明确 Camera / POV 是硬约束。

## Content-driven Camera Selection｜仅机位未锁定时

1. 以 `Scene Read + 主导视觉关系 + 必需可见结构` 设定镜头的首读任务。
2. 在内部比较至少两种**可实际存在**的观察点（高度、方位、朝向、倾斜、距离），而不是只替换 `eye-level/high-angle` 字样。
3. 逐一检验：身份锚点是否可辨、关键因果是否被遮住、功能空间是否可读、视线是否有自然路径、前中远层次是否成立、取景能否维持原定尺度。
4. 选总约束最满足的一种镜头并锁定 Camera Contract；其余候选不进入最终 Prompt。
5. 平视、低机位、架高斜俯、近距离、远距离、局部俯拍都是条件候选。俯视能读布局但易弱化垂直体量；低机位能凸显尺度但易遮挡功能；不是越极端越电影。
6. 焦段服务透视和空间覆盖；不把 `wide establishing shot` 当成某个固定毫米数。手绘媒介可把镜头属性改写为透视点、视高与取景，而非强制模拟摄影镜头。

**Camera Fitness 最高权重：身份与主导关系可读、空间事实不变。** 在这些成立后，再优化新鲜感、视觉张力与画面优雅度。

## Camera Physicalization

标签必须产生可见后果：
- high-angle / elevated → 摄影机高于主场景平面、向下看，暴露更多地面 / 顶面 / 布局；
- bird's-eye → 更高位置、更陡向下，但未要求 top-down 时不自动变 90°；
- low-angle → 摄影机低于主体视觉中心、向上看，更多下表面 / 上部结构进入画面；
- eye-level → 接近正常视线高度；
- top-down / overhead → 接近垂直向下，仅明确要求时使用。

同一 Prompt 不得同时出现相互抵消的机位词。

**Shot size / establishing coverage ≠ focal length.**

# 10. Visual Organization

> **Composition reveals an established space; it does not redesign it.**

## Design Intent / Viewing Path

先锁一条可见的主导关系和第一阅读目标，再安排第二层阅读信息与视觉结束位置。用已有大形、负空间、明暗分组、边界、反差、路径、重叠组织视线。主视觉不必最大或最亮，但必须能在缩略图中被迅速找到。

## Frame Balance / Rest Zones

- 画面复杂度按 `主焦点高信息 → 过渡 → 次要低信息` 分配；低信息区域可有完整材质与生活状态，不等于空地、废墟或死黑。
- 大形、中形、小形的重复与变化须有节奏；避免所有区域同时达到高频细节。
- 不强制对称/三分/三角/框景。既定空间适合时可以使用，不为满足公式增加实体。
- 遮挡只有在提供真实观察位置、强化尺度或隐现关系时才使用。无意义的巨大虚焦前景、黑色边框与假景深不作为默认美学手段。

## Light-Aware Composition

光照应使主体表面转折、空间分层和视觉路线更清楚；基于真实光源、可解释的遮蔽与反射组织值域。必要时局部选择性清晰，对次要区域概括。电影摄影明确启用时只输出 Value Intent，由 `17` 一次性控制光影/成像。

## Shape
- 大形先于中形，小细节从属。
- 避免大量同尺度中形平均竞争。
- “重要”不自动等于最大、最高、最居中。

## Value Intent
这里只决定哪些区域需要相互分离，不建立第二套灯光。
- 2–4 个大尺度明暗组即可。
- 主区域不要求全图最亮。
- 若 `17` 启用，只输出 Value Intent；由 `17` 物理实现。

## Structural Depth
先用空间本身建立深度：
- overlap / occlusion
- perspective / scale recession
- terrain / architecture layering
- physically plausible atmospheric perspective

这里不决定 DOF。

不要用“前景黑框 + 白雾”替代真实深度。

## Color Organization
普通场景只锁场景材料色与必要功能色。
若 `17` 启用，最终 Unified Color Field 由 `17` 负责。

## Traditional Composition
三分、三角、对角线、S 曲线、框景、对称等只在：
- 用户明确要求；或
- 已成立空间天然呈现时轻量强化。

不为了构图新建桥、路、楼梯、建筑、光束。

# 11. World Identity Interface

当题目是架空、奇幻、科幻、历史文明，或用户要求强世界观辨识度时，把以下状态传给 `18`：
- scene function
- L/M/S scale
- use state
- architecture shell facts
- allowed / forbidden technology or magic
- current visual identity requirements

`18` 返回少量可见世界身份锚点与局部功能地编，不改变 Scene Structure。

# 12. Cinematic Interface

用户明确要求电影感时，把以下状态传给 `17`：
- Target First Read
- Camera Contract
- existing structural depth
- Value Intent
- real light-source conditions
- use state
- material facts
- optional Style Coordinate from `10`

`17` 不得重选 Camera 或重新设计空间。

# 14. Visual Finish｜普通场景只收尾一次

## Medium
**DEFAULT_VISUAL_STYLE = NONE。** 当前输入指定何种媒介，就用该媒介的完成度术语：手绘概念图表达笔触/颜料层/边缘节奏，动画表达线条/造型/色块，摄影表达镜头与曝光，CG表达材质及渲染；未指定媒介时写中性形态、空间和光色事实。风格图或模糊风格名的解码委托给 `19`；本文件只提供 L/M/S 控制粒度、结构和视觉组织，不在此生成第二套风格词模板。

用户要求写实 CG 时使用一套清楚媒介语言即可，例如：
- `ultra-realistic high-end CG environment concept art`
- `high-detail realistic CG scene art`

普通 CG 场景不因“高质量”自动加入 movie still / film grain / anamorphic。

## Light
`17` 未启用时：
**Light explains space first, organizes attention second.**

只保留：
- 真实主光来源 / 方向
- 必要光质
- 大尺度明暗关系
- 必要色温关系

体积光必须有真实介质。

`17` 启用时，本文件不再输出第二套灯光。

## Material
只写：
- 身份所需主材质
- 当前尺度可见的表面状态
- 生命周期允许的差异

远景不写微观磨损。

# 15. Negative Prompt

正向结构优先。

`--no` 通常只处理 1–3 类当前最高风险：
- adjacent wrong archetype
- scale drift
- lifecycle drift
- unwanted character focus
- modern / sci-fi contamination
- ruin / clutter when model repeatedly introduces them

人物负面服从 Human Presence，不固定 `--no people`。

`letterbox / matte border` 只在实际黑边问题出现时作为 repair，不作为默认电影规则。

# 16. Compact QA

最终只问：
1. Identity 是否第一眼成立？
2. L/M/S 是否正确，是否有跨尺度控制？
3. 空间因果 / 工作流 / 主操作是否成立？
4. Active 场景是否被错误破败化？
5. 世界身份是否需要 `18`，且是否与结构分离？
6. Camera 是否物理执行且无冲突？
7. 信息密度是否有层级？
8. 是否明确首读主体与主导视觉关系，且不通过重建设计实现构图？
9. 风格是否由本轮用户/参考图/确定媒介定义，未暗加 CG 或摄影身份？
10. Prompt 是否只保留可见高杠杆关系？

失败时回到对应层重编，不在旧 Prompt 末尾追加补丁。
