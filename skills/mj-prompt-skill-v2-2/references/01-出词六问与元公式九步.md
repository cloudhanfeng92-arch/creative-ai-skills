# 出词六问与元公式九步｜V2.2

> 六项是输入解析维度，不是固定问卷。信息足够时直接推导；只有缺失内容会明显改变方案方向时才询问。
>
> 九步是覆盖检查，不是最终九段模板。

# 1. 六项前置解析

| 维度 | 说明 |
|---|---|
| 媒介与风格 | 当前用户指定的 CG / 摄影 / 手绘 / 油画 / 动画 / 概念原画等；未指定则 STYLE_UNSPECIFIED，不将题材词当成成像媒介 |
| 机位与画幅 | 视角、景别、空间覆盖、比例 |
| 参考与资产 | 参考图、身份锁定、已有设计、当前编号职责；若为风格图，区分 Style Reference / Image Prompt，并核查是否有 MJ 可访问的链接 |
| 时间与光线 | 时间、天气、主光来源与方向 |
| 用途 | 场景母版、环境概念设计、电影环境帧、建筑或景观资产等 |
| 目标模型 | Midjourney 场景 Prompt；未指定版本时默认 V8.2 |

解析原则：
- 已提供 → 直接继承；
- 可合理默认且不改变方向 → 直接默认；
- 缺失会导致完全不同方案 → 再询问；
- 最新明确要求覆盖旧状态。

# 2. 场景任务前置路由

## Scene / Environment

先调用 `16-场景设计与环境编译.md`。

内部顺序：
1. 解析硬约束、参考图职责与 STYLE_STATE；模糊文字风格或风格图由 `19` 提取可见风格机制，同时建立主体可见身份锚点；
2. 判 L / M / S 控制尺度；
3. 建立 Scene Read；
4. 建立 Scene Structure；
5. 锁定 Use State / Human Presence / Macro Detail Density；
6. 若世界身份或功能地编重要，调用 `18-世界身份与功能地编.md`；
7. 确定主导视觉关系；机位未锁定时内部比较两个可行观察点，建立 Camera Contract；
8. 组织首读/视线过渡/大形/复杂区和休息区/Value Intent / Structural Depth / Color；
9. 用户明确电影化时调用 `17`；需要导演 / 类型坐标时由 `10` 给坐标；
10. 按本轮媒介动态实现光照与技法，进行 Scene Prompt Compiler + Conflict Audit + Compact QA。

`10/11/12/17/18` 都不得越权覆盖 `16` 已锁定的 Scene Structure 与 Camera Contract。

# 3. L / M / S 判断不是现实尺寸判断

判断标准是：**当前画面需要模型控制到哪一层空间关系。**

- L：摄影机理解区域系统、城市或建筑群关系。
- M：摄影机理解一个功能节点、公共空间或建筑内部关系。
- S：摄影机进入人的直接使用尺度，门窗、工作面、摊位、工具、局部通道开始决定身份。

同一建筑可以因镜头不同而分别进入 L / M / S。

# 4. 元公式九步

1. **任务与媒介**：交付是什么，按用户文字/有效风格参考判断媒介；风格模糊或图文组合用 `19` 提取 2–4 个高杠杆可见风格锚点，无全局默认画风。
2. **主体 / 场景身份**：第一眼必须读成什么。
3. **空间 / 关系**：真正影响结果的结构、邻接、距离和层级。
4. **Camera + 视觉主关系**：本轮看什么、为什么从这里看、看多少，真实高度/俯仰/视距/适当焦段。
5. **动作 / 使用状态**：只写改变画面的动作或运营状态。
6. **世界身份 / 关键元素**：只保留高区分度、尺度匹配的可见锚点。
7. **光线 / 色彩 / 材质**：按物理来源、综合色域与当前尺度表达。
8. **必要 Drift Guard**：只防当前最高概率错误。
9. **硬参数**：用户参数优先；MJ 未指定版本时 `--v 8.2`；V8.2 不使用 `--q`，Raw Mode 需要时使用 `--raw`。

# 5. Scene Prompt 编译纪律

Scene 最终不按九步逐段输出。

优先压缩为：
- Scene Identity / Scale
- Spatial Structure / Workflow
- Camera / Composition
- World Identity / Use State / Visual Finish
- Drift Guard / Parameters

内部完整推导不等于完整输出。

对于空间设计，最终通常只保留 **2–4 条最强空间关系**；过多同级关系会降低控制权。

# 6. 语义 Delete Test

每句话都问：

> 删除后会失去什么明确可见变量？

可以保留：
- 改变场景身份；
- 改变规模；
- 改变邻接 / 工作流；
- 改变 Camera；
- 改变世界身份的可见系统；
- 改变生命周期；
- 改变大明暗 / 色域；
- 改变关键材质响应。

优先删除：
- 更高级；
- 更真实；
- 更专业；
- 更有电影感；
- 更有层次；
- 与前句同义的质量词。

# 7. 编译纪律

- 同一关系只写一次。
- 具体关系已表达后，删除抽象复述。
- 多个 Reference 命中同一维度时先按 SSOT 合并，只输出一套结论。
- 不因去 AI 默认加入破败、脏污、积灰、墙皮脱落。
- 不因电影感默认加入 film grain / anamorphic / shallow DOF / foreground obstruction。
- 世界身份不靠装饰数量证明。
- 场景默认无角色主体，但是否出现环境人物由 Human Presence 决定。
- `--ar` 已控制画幅时正文不重复堆宽画幅术语。
- 最终 MJ Prompt 使用规范英文 ASCII。
