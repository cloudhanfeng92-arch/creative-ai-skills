# 世界身份与功能地编｜V2.1

> 本 Reference 解决两个紧密相关但与 Scene Structure 分离的问题：
>
> 1. **World Identity**：如何让一个架空 / 奇幻 / 科幻 / 历史文明在不同尺度持续成立，而不是只靠装饰符号。
> 2. **Functional Set Dressing**：如何让环境中的物件、设施和使用痕迹围绕真实行为组织，而不是随机撒细节。
>
> 它不负责重新设计场景结构、改变场景尺度或重选 Camera。

# 0. Compatibility With V2.1

本层提供可见的文明身份、功能系统与局部地编证据，遵守当前任务指定的媒介及 `16` 的尺度、结构、主导视觉关系与 Camera。世界身份若无法在本轮画幅/机位中被辨认，优先换用当前尺度更可读的基础设施或构件证据，不靠增加巨型奇观、历史废墟、发光装饰或无意义道具强化。高质量不等于全画面平均高密度。

# 1. 什么时候调用

调用 World Identity 分支：
- 架空世界 / 奇幻 / 科幻文明；
- 历史世界需要区别于现代默认；
- 用户明确要求文化、宗教、国家、组织的视觉体系；
- 当前结果过度像现实世界某一现成城市 / 文明，缺少原创世界身份。

调用 Set Dressing 分支：
- M / S 场景需要功能使用状态；
- 市场、办公室、工作室、接待、街道、店铺、庭院等需要日常活动证据；
- 当前结果“空但假”或“乱但空洞”。

不调用：
- 纯几何 / 极简任务无需世界身份；
- 世界身份已被参考图完整锁定且无需补充；
- L 级极远景看不到局部设施时，不输出小物件。

# 2. 权限边界

输入来自 `16`：
- Scene Identity
- L/M/S Scale
- Scene Structure
- Use State
- Human Presence
- architecture / material facts

本 Reference 可以补：
- 文明级设计语法；
- 尺度匹配的基础设施 / 公共设施；
- 功能性世界观锚点；
- Activity Cluster；
- 局部 Behavior Hotspot Density。

本 Reference 不得：
- 新增一级城市功能区；
- 改变道路 / 建筑 / 房间基本布局；
- 把 M 节点升级成城市核心；
- 把 S 小空间拉成宏伟场景；
- 用幻想装饰覆盖实际功能；
- 为“真实”制造废弃状态。

# 3. World Identity｜系统化而非贴图化

核心判断：

> **如果移除旗帜、徽记和文字，这个空间还像属于这个文明吗？**

如果答案是否，世界身份未成立。

世界身份优先从以下层级选择 2–4 个当前可见维度：

1. **Built Grammar**：结构比例、屋顶 / 开口 / 廊道 / 支撑 / 边界的共同语法。
2. **Material Grammar**：稳定的主材质、金属体系、木石关系、维护方式。
3. **Civic Infrastructure**：路面、排水、照明、护栏、门禁、信息系统、公共设施。
4. **Movement / Transport**：人和货怎样移动，运输器具 / 站点 / 接驳方式有什么文明特征。
5. **Institutional Grammar**：宗教 / 行政 / 商业 /住宅如何共享文明母语又保持等级差异。
6. **Symbol Grammar**：少量稳定重复的符号、形状、比例和放置逻辑。
7. **Technology / Magic Integration**：只有设定需要时，让技术 / 魔法进入实际功能系统。

不是每个场景都需要全部七项。

# 4. Fantasy Identity｜奇幻不是装饰数量

架空奇幻场景优先让“幻想性”进入：
- 建筑工程逻辑；
- 公共设施；
- 宗教 / 权力机构的空间语言；
- 照明、门禁、运输、信息传递；
- 日常工具与工艺；
- 受控的符号体系。

不要默认依赖：
- giant crystals
- floating structures
- neon magic
- oversized statues
- repeated banners everywhere
- excessive gold ornament
- impossible megastructures

除非世界设定本身要求。

**奇幻感应像文明真实生活的一部分，而不是主题公园覆盖层。**

# 5. Real-world Drift Control

架空文明容易被模型拖向某一现实文化模板。

处理顺序：
1. 正向建立原创结构 / 材料 / 基础设施语法；
2. 明确哪些现实体系不是目标时，再做最少 Drift Guard；
3. 不用长串国家 / 民族负面词定义原创世界。

如果结果只像“现实地中海 / 中东 / 东亚古城 + 一个宗教徽记”，优先加强系统化身份，不增加更多徽记。

# 6. Scale-specific World Identity

## L｜District / Large Environment

只控制远景能读到的文明系统：
- 公共机构与普通城市肌理的等级关系；
- 宗教 / 行政 / 商业系统如何进入城市；
- 主要建筑语法的区域连续性；
- 基础设施与交通形态的总体特征；
- 有限地标 / 轮廓语言。

不输出：
- 单个灯具；
- 门把；
- 摊位工具；
- 室内家具；
- 精确街头小物。

## M｜Urban Node / Building Space

世界身份主要进入：
- 公共设施
- 门禁 / 信息 /登记方式
- 建筑构件
- 功能家具
- 交通 / 等候 / 服务边界
- 仪式与行政活动的实际设备

宗教 / 权力身份不等于全空间纪念碑化。

## S｜Human Scale

世界身份主要进入人的直接接触层：
- doors / windows / shutters / screens
- lamps / sconces
- niches / plaques / signs
- drainage / water / heating / ventilation solutions
- storage / locks / counters / shelving
- transport tools / hand carts / containers
- household / workshop / retail fixtures

小尺度越小，越应该靠日常系统证明世界观，而不是靠远景巨型宫殿。

# 7. Symbol & Motif Budget

符号体系要稳定，但不能平均覆盖所有表面。

建议：
- 1 个主几何母题；
- 1–2 个材料 / 工艺表现；
- 按机构等级决定出现密度；
- 普通住宅只保留弱化版本；
- 国家级 / 宗教级建筑才允许更高强度表达。

`banner / emblem / relief` 只能作为辅助，不作为唯一世界身份。

# 8. Activity Cluster｜行为簇

地编不是随机撒道具。

一个功能区的物件应围绕同一行为形成近邻系统：

**主物件 / 主操作对象 → 高频支持 → 辅助物 → 使用净空 → 收纳 / 待处理**

例如：
- reception：counter + information surface + document storage + usable queue / staff clearance
- market stall：goods + weighing / packing + containers + cart / storage + customer clearance
- workshop：workpiece + tools + task-specific support + material storage + safe working clearance

规则：
- 物件之间有行为关系；
- 不同 Cluster 之间保持主次；
- 不用同等密度填满整个场景；
- 不为了“生活感”随机加箱子、布料、纸张、瓶罐。

# 9. Behavior Hotspot Density｜M04 V0.1 冻结规则

这是经过测试保留的稳定版本：

> **高频功能区拥有更高但受控的信息密度与使用状态；主通行区保持畅通；低频区域降低信息量。真实感来自行为热点之间的密度差，而不是全场平均丰富。**

## 高频功能区
- 允许更高物件密度；
- 物件必须与行为相关；
- 仍保留主物件 / 辅助物 / 净空层级。

## 主通行区
- 保持物理畅通；
- 不放随机杂物证明使用感；
- 可以通过正常活动或整体状态读出高使用率，但不需要精确微观磨损描述。

## 低频区域
- 更安静；
- 物件更少；
- 大面更完整；
- **不等于更脏、更灰、更破、更长草。**

# 10. Deprecated｜明确废弃的执行方式

以下不作为 V2.0 地编主规则：
- 精确指定每个把手、扶手、桌角、地面路径的微观磨损；
- 用全场磨损分布证明长期使用；
- 为了去 AI 强制增加纸张、杂物、灰尘、裂纹；
- 把低频区翻译成 abandoned / dusty / neglected；
- 通过“更多细节”证明专业性；
- 将每个世界观符号铺满建筑表面。

这些方法在需要近距离材质特写时可以作为条件性材质描述，但不属于场景结构 / 地编默认算法。

# 11. Maintenance-aware Set Dressing

地编必须服从 `16` 的 Use State。

## Active / Maintained
- 功能物可用；
- 物件分组清楚；
- 通道和工作面可操作；
- 新旧替换可以存在；
- 不自动出现垃圾、坍塌、长期无人维护痕迹。

## Active / Worn
- 允许更粗粝、更高使用密度；
- 仍维持功能秩序。

## Abandoned / Ruined
- 才允许地编向散乱、失效、侵入、崩坏发展。

# 12. Human Activity Evidence

如果 `16` 允许环境人物，人物可以成为世界运行证据：
- 市场交易；
- 搬运；
- 等候；
- 值守；
- 通行。

人物必须低权重，从属于环境。

如果场景要求无人，可以通过：
- 已摆放的功能物；
- 开启的设施；
- 合理准备状态；
- 未完成但有秩序的工作状态

表达“有人长期使用”，不需要破败或随机杂物。

# 13. Prompt Materialization

World Identity 最终一般只输出 2–4 个可见锚点：
- 1–2 个结构 / 基础设施身份；
- 1 个功能性日常系统；
- 必要时 1 个受控符号 / 技术 / 魔法锚点。

Set Dressing 最终一般只输出：
- 1–3 个 Activity Cluster；
- 一个主通行 / 净空要求；
- 一条热点密度关系。

如果 World Identity 与 Set Dressing 已经能通过具体名词和关系成立，删除 `distinctive fantasy / rich worldbuilding / lived-in / immersive` 等抽象总结。

# 14. QA

- 是否移除旗帜 / 徽记后仍属于该世界？
- 当前锚点是否符合 L/M/S 可见尺度？
- 世界身份是否进入功能系统，而不是装饰堆叠？
- 是否无意滑向单一现实文化模板？
- Activity Cluster 是否有明确行为中心？
- 主通行与工作净空是否仍清楚？
- 低频区域是否被错误废弃化？
- 是否出现已废弃的精确微观磨损控制？
- 是否越权修改了 `16` 的空间结构 / Camera？
