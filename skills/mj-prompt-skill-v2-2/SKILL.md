# MJ提示词skill V2.2

> **总纲**：先锁定当前任务事实，再路由专业规则；先设计，再摄影，再按用户指定风格编译。Reference 用于内部判断，不要求全部进入最终 Prompt。最终只保留会造成明确可见差异的信息。

**跨媒介设计内核（先于出词）**：`意图与可见身份 → 结构/功能因果 → 空间覆盖粒度 → 主导视觉关系 → 观察点/构图 → 光影与信息层级 → 指定媒介实现`。这条内核在城市、建筑室内、自然、人工奇观与人尺度场景中统一成立；具体景物、视角、风格、色板、镜头参数必须每次重新判断，不继承示例答案。

**V2.2 核心编译链**：`用户意图与参考图职责 → 主体视觉身份 → 结构/功能因果 → 场景尺度与空间关系 → Camera → 构图/视觉组织 → 条件性电影摄影 → 文字/参考图统一风格编译 → 职责与尺度审计 → 英文 Prompt`。

**STYLE CONTRACT（硬规则）**：
- `DEFAULT_VISUAL_STYLE = NONE`。超写实CG、照片、胶片、手绘、游戏原画、插画、动画和任何风格均不得设为全局默认。
- 风格来源优先级：当前用户明确指定 → 被赋予风格职责的当前参考图 → 交付任务可确定的媒介要求 → 未指定风格时使用中性视觉描述。
- “电影感”不是默认风格；只有明确的电影化需求才调用电影摄影成像系统。
- 当前任务风格优先于历史案例和旧 Prompt。未知风格时不暗中加入 `ultra-realistic CG / PBR / photorealism / film grain / cinematic still / anime` 等媒介信号。
- `DEFAULT_MJ_MODEL = V8.2` 是模型规则，不等同于风格默认；画幅按本轮输入，不将21:9设为通用默认。
- 同一任务的风格、成像与材质必须相容。图像质量标准通过遵守指定媒介的完成度实现，不通过跨媒介堆质量词实现。
- **TEXT / IMAGE / HYBRID / UNSPECIFIED 是同一 STYLE_STATE 的输入形态，不是四套 Skill。** 文字本身可独立形成明确风格；用户有有效目标风格图时，以参考图强化其指向性，不得要求所有用户必须上传图片。
- 参考图首先按本轮职责分离 **风格 / 内容 / 身份 / 构图 / 镜头**。风格图的色彩、线条、材质概括、光影和可授权的造型规律可以转译，图中具体景物、地标、人物和镜头不因风格职责自动复制。

# 1. 全局优先级

固定优先级如下，低层不得覆盖高层：

**P0 当前用户明确要求**  
**P1 当前参考图 / 资产锁定**  
**P2 任务身份与交付目的**  
**P2.5 主体视觉身份与不可变结构（所有任务）**  
**P3 场景尺度与空间结构（仅 Scene）**  
**P4 世界身份与功能地编（仅需要时）**  
**P5 Camera / POV 与电影观看逻辑**  
**P6 构图与视觉组织**  
**P7 光影 / 色彩 / 材质 / 成像**  
**P8 质量与风格强化词**  
**P9 默认参数**

执行原则：
- 用户本轮明确要求覆盖历史默认与旧方案。
- 参考图只锁定用户赋予它的职责，不跨职责继承。
- 修改任务先重建当前有效状态，不在旧 Prompt 尾部累积补丁。
- 无权威来源的下游模块不得重写上游已锁定内容。
- 风格只能由 P0、承担风格职责的 P1 或明确的交付媒介推导；P8 质量词不得倒置定义主体媒介。
- 本轮身份锚点由用户输入及当前参考图确定，不能把测试案例的特征永久写进通用规则。

# 2. Model Contract｜默认模型锁定

默认目标模型：

**DEFAULT_MJ_MODEL = V8.2**

规则：
- 用户未指定 Midjourney 版本 → 最终必须使用 `--v 8.2`。
- 用户明确指定 V8.2 → 使用 `--v 8.2`。
- 用户明确指定其它 Midjourney 版本 → 仅此时允许覆盖默认版本。
- Skill 不得根据题材、风格、媒介或旧母版自行切换模型。
- 当前 V8.x Raw Mode 使用 `--raw`；V8.2 不使用 `--q`。
- 任何旧模板中的模型参数都不得覆盖当前用户参数或本包默认模型。

用户明确提供的 `--ar / --s / --c / --seed / --raw` 等参数优先；未指定时不为“专业感”无理由堆参数。

# 4. Task Router

本包专精 **Scene / Environment**：城市 / 地区、建筑 / 室内、自然环境、人工奇观、工作场景、空间资产图，以及以环境为主体的摄影、CG、动画、绘画 / 概念美术。人物若只是尺度参照或环境活动，按 Human Presence 管理。

独立人物 / 服装立绘、产品主图、海报封装和视频运动提示词不在本包的执行范围。遇到非场景任务不得用场景规则冒充相应专业模块。

**STYLE ROUTING**：先确定本轮用户指定的画面媒介；`Scene` 不自动等于 CG、摄影或电影截图。文字风格描述、参考风格图及图文混合输入共用 `19` 的风格信号编译，单纯文字输入无需上传图片。

# 5. Scene Compile State Machine

场景任务严格按上游 → 下游建立状态；上游未成立，不向下游补词硬救。

## PHASE 0｜CONSTRAINT_STATE

锁定：
- 当前用户硬约束
- 参考图职责与编号
- 画幅 / 用途
- 是否允许人物
- 生命周期 / 维护状态
- 明确机位 / POV / 观察方向
- 明确媒介与风格，或记录 `STYLE_UNSPECIFIED`
- 主体类型与用户明确锁定的形态/结构
- 明确 MJ 参数 / 模型覆盖


## PHASE 0A｜STYLE_STATE｜场景先决策

风格先于视觉完成度编译：
1. 用户明确指定的绘画/照片/CG/动画/原画等媒介及风格是唯一首选。
2. 参考图按本轮职责继承：身份图不自动锁定风格；风格图不自动重设计身份或服装。
3. 任务可决定输出媒介时据此选词；其余标为 `STYLE_UNSPECIFIED`，只写清主体、场景和构图。
4. 标记输入模式 `TEXT_ONLY / STYLE_IMAGE / HYBRID / UNSPECIFIED`，仅表示风格证据来源；不分离 Skill，不对某种输入模式预设“更优质量”。
5. 调用 `19` 将风格证据拆解为 **媒介与造型 / 形体概括 / 笔触线条边缘 / 材质与渲染 / 明暗光照 / 色彩 / 成像特征**，区分可见证据、推断和无依据联想；只提炼当前任务有用的高杠杆信号。
6. 对显式文字要求与参考图表现分别分配职责，冲突时以用户明确文字锁定为先，其它风格维度择兼容者转译；参考图不可偷换主体和 Camera。
7. 电影化是独立开关 `CINEMATIC_REQUESTED`，不能由“场景”“高质量”“3D”或“幻想题材”自行触发。

**风格冲突例外**：用户指定的抽象、象征、超现实风格允许有意偏离实际物理结构；在没有明确授权时，真实/功能性任务优先结构自洽。摄影镜头语言与绘画视角组织可以共享构图原则，但不得共享一套写实材质/胶片词。**形态变形语言不全等于绘制媒介风格**：仅当用户任务明确需要侵蚀、扭曲、变形、风格化比例等形态变化时，风格图才可提供一般化的变形语法；不得照搬参考图中的具体对象。

## PHASE 0A.1｜STYLE_SIGNAL_STATE｜按需调用 `19`

先判断用户要控制的是 **媒介身份**（照片/CG/二维手绘等）、**艺术处理**（线、笔触、轮廓、材质等）还是 **世界/主体设计语言**（造型夸张、几何形体、灾害变形等）；不要将三类信号混为一个“风格词套餐”。从文字或有效风格参考图提炼出 2–4 个最强、可被视觉识别的风格锚点，并各自匹配具体的英语图像描述，按当前画面尺度删去无法被看见的微观信号。

**图像是可选来源**：收到风格图时先在本轮语境中分配职责并提取视觉语言。若用户有可用于 Midjourney 的真实风格图 URL 或在 MJ 界面使用 Style Reference，可额外使用对应原生风格参考机制；若图片只存在当前聊天，不得编造可用 URL 或把聊天附件路径写入 `--sref`，应输出提炼后的文字 Prompt，并简要说明用户可在 MJ 端将原图设为 Style Reference。

## PHASE 0B｜IDENTITY_STATE｜场景先决策

将主体名称转换为可观察的视觉证据，并提炼 3–5 项高杠杆锚点（按任务实际数量，不机械凑齐）：
- **Category Signature**：类别决定性视觉特征；
- **Silhouette / Proportion**：全貌外轮廓和体量关系；
- **Morphology / Topology**：各部件的数量、连接、方向和层次；
- **Distinctive Traits**：区别于近邻类别的独特结构；
- **Contextual Evidence**：主体与功能环境相互证明的关系。

以 `Identity → Visible Evidence → Adjacent Confusion → Positive Disambiguation` 进行内部排错，先写可见的正向形态证据，再根据剩余风险考虑少量 `--no`。抽象气质词、历史设定或世界观标签不可替代身份结构；镜头不能把唯一关键锚点全部遮住。

身份锁定高于摄影与风格修饰。对于结构复杂且文字难以稳定固定的资产，可建议独立形态参考图，但不能假装仅靠提示词可保证每个细节必然正确。

## PHASE 1｜TASK_SCALE_STATE

由 `16` 按**当前画面需要控制的空间覆盖与设计粒度**判：
- L｜District / Large Environment
- M｜Urban Node / Building Space
- S｜Human Scale

不是按现实建筑的绝对尺寸机械分类。

## PHASE 2｜SCENE_STATE

由 `16` 建立：
- Scene Read
- Scene Structure
- Use State
- Human Presence
- Macro Detail Density

只推导当前尺度真正能影响画面的结构。

**Structure / Causality Gate**：检查 `身份 → 必需部件 → 连接/支撑 → 关键邻接 → 功能使用证据 → 生命周期状态`，把最重要的因果关系转为可见设计，而非在 Prompt 中解释故事。世界身份、空间用途和结构语义必须自洽；有意超现实的设计按本轮风格与用户要求处理。

## PHASE 3｜WORLD_IDENTITY_STATE｜条件

需要世界身份或功能地编时调用 `18`。

`18` 只能回答：
- 这个文明如何通过可见基础设施、建筑语法、公共设施和日常物件表现身份；
- 功能物如何按行为成组；
- 局部行为热点如何分配信息密度。

`18` 不得：
- 改写 `16` 的场景功能与空间结构；
- 扩大场景尺度；
- 仅靠旗帜、徽记、奇观装饰制造“世界观”；
- 把正常运营空间做成废墟。

## PHASE 3A｜VISUAL_INTENT_STATE｜场景美学目标

由 `16` 确定本轮画面的一个**主导视觉关系**（例如体量对照、纵深揭示、空间连接、形态孤立、重复与节奏、功能机制的清楚暴露；仅是候选，不是固定清单），再建立两个从属视觉关系，作为 Camera 和光照设计的选择依据。目标是“观看后能认出什么、理解什么、被什么吸引”，不是机械规定中心点、黄金三角或固定比例。该层只调整既有实体间的呈现，不增加空间结构。

## PHASE 4｜CAMERA_STATE

由 `16` 建立唯一 Camera Contract：
- Physical Location
- Relative Height
- Viewing Direction
- Pitch
- Distance
- Focal-length Class
- Frame Coverage

用户明确机位时必须物理执行，不能被“更电影”“更有构图感”等下游默认改写。

**内容驱动选择（用户未锁机位时）**：先问需要读懂的主体剪影、关键结构与空间关系是什么；内部对比至少两个可行观察点，再只选能同时突出身份、交代结构、组织视觉终点的一种。选择平视、俯视、低机位或斜侧不靠随机和极端程度；平视/中心/中景均可合理成立。机位必须有真实可解释的空间观察点与相应几何后果，不能借构图增建建筑、道路或平台。

**景别不等于焦段。**

## PHASE 5｜CINEMATIC_IMAGE_STATE｜条件

仅用户明确要求电影化时调用 `17`，且调用条件由 `STYLE_STATE` 与本轮硬约束决定。电影化是一种光影、观看和成像组织方式，不能覆盖用户指定媒介。例如绘画风格的电影化应翻译成明暗、景别与叙事组织，而非强行变为摄影或CG。

`17` 消费已锁定 Scene + Camera，建立：

**Camera Position → Viewing Subject → Visual Route → [optional Occlusion] → Depth Hierarchy → Light Hierarchy → Color / Atmosphere / Imaging**

其中 Camera Position 来自 `16`，不可重选；Viewing Subject 与 Visual Route 只能在已有空间里组织观看，不得重建设计。

## PHASE 5A｜COMPOSITION_STATE｜跨媒介、跨尺度观看组织

`16` 在锁定 Camera 后负责组织：`主导视觉关系 → 首读目标 → 视线过渡 → 纵深与遮挡 → 复杂区/休息区 → 光影指向`。设计中至少保证一个视觉终点、一段清楚的观看路线、可辨认的大形，并在视觉高频区之外留出有内容的低频区域。对称、不对称、平视、高角度、低角度、框景、近景遮挡均依据场景目标选用，不列为统一默认。绘画媒介将摄影几何翻译为透视和图形组织，而非自动加入相机成像词。

## PHASE 6｜VISUAL_FINISH_STATE

- 普通 Scene：由 `16` 组织 Shape / Value Intent / Structural Depth / Color / Light / Material，再根据 STYLE_STATE 转成对应媒介语汇；不得默认写实CG。
- 明确电影化：`16` 只提供场景事实与不可变光源条件，最终电影摄影组织由 `17` 执行，再与指定媒介统一；`17` 不选择新 Camera。
- 世界身份可见锚点由 `18` 提供，但不得再建立第二套材质 / 色彩 / 灯光系统。
- 风格视觉执行由 `19` 提供，只落实已获授权的风格维度；不重建 `16` 的场景、`17` 的电影摄影或用户锁定的 Camera。避免将“3D动画电影”生成纪实照片，或将“二维背景美术”退化为三维物体附加卡通描边。

## PHASE 7｜PROMPT_MATERIALIZATION

最终 Scene Prompt 按高杠杆语义编译，不按 Reference 章节逐项抄写。

默认语义顺序：

**A. 目标媒介的短主锚点 + Subject Identity / 关键形态**（风格未指定时不放媒介锚点）  
**B. Scene Scale + Spatial Structure + Functional Relations**  
**C. Camera + Visual Organization**  
**D. 2–4 个可见风格高杠杆信号 + Light / Material / Imaging（电影化按需）**  
**E. Targeted Drift Guard + 有效风格参考接口（如有）+ User Parameters**

风格身份若容易被内容吞没，可在 A 首句用精确媒介短语，并在 D 用**不同而互补**的具体视觉机制落地；不得把同一风格形容词在开头结尾重复堆叠。有效 `--sref` 或 MJ Style Reference 应作为风格辅助而非免除文字中的场景身份；正文避免和风格图冲突的写实/CG/胶片套词。

内部可能推导很多规则，最终通常只 materialize 2–4 条真正改变空间关系的结论。

## PHASE 8｜CONFLICT_AUDIT

交付前检查：
- 是否存在两个 Reference 同时决定同一维度；
- 低优先级是否覆盖用户硬约束；
- L/M/S 规则是否跨尺度串用；
- 世界身份是否退化为装饰堆叠；
- 电影感是否改变了空间 / Camera；
- 正向与 `--no` 是否互相打架；
- 参数是否满足 Model Contract；
- 是否存在被新要求覆盖的旧信息；
- STYLE_STATE 是否有真实来源，是否偷偷加入了固定 CG / 摄影 / 胶片 / 电影画风；
- 风格参考图是否发生对象、场景、构图、机位或身份越权迁移；
- 风格语汇是否可见、互补、按 L/M/S 粒度筛选，而非媒介标签和通用“高级”词反复堆叠；
- 图片仅来自聊天时是否错误生成了 `--sref` 伪 URL / 本地路径，或把风格图错用作普通 Image Prompt；
- 主体身份的关键可见形态是否被角度、遮挡或装饰稀释；
- 正向结构、风格与负面词是否相互冲突。

冲突时删除低优先级表达，不把两套规则混合保留。

# 6. Semantic Compression

每加入一句都执行 Delete Test：

> 删除后，预计会失去什么明确可见变量？

如果只能回答“更真实 / 更高级 / 更专业 / 更电影 / 更有层次”，优先删除。

压缩规则：
- 同一关系只表达一次。
- 具体空间关系成立后，不追加抽象近义词总结。
- 质量词不能替代场景设计；也不能偷偷植入未经要求的媒介。
- 负面词只处理剩余高风险，不重复正向已经锁死的规则。
- 一个局部细节若超出当前尺度的可见控制能力，删除。
- Reference 中有知识 ≠ 最终 Prompt 必须出现。

# 7. Scene Gates

- **Identity Gate**：主体名称必须转化为可见的类别/外形/组成/比例证据；背景、风格和摄影机不得替代主体身份。
- **Causal Gate**：复杂物体与场景必须呈现最关键的连接、支撑、邻接或使用因果；按指定媒介控制真实度，尊重用户有意设计的非现实结构。
- **Style Gate**：风格由本轮用户文字和/或有效风格参考定义；不使用超写实CG或电影摄影作为默认。风格证据被提炼成可见的媒介、形体、笔触/边缘、材质、光色与成像信号；参考图按职责传递风格，不自动传递对象和机位。
- **Scale Gate**：当前规则粒度必须匹配 L/M/S；不得用城市规划控制房间，也不得用桌面地编控制城市鸟瞰。
- **Structure Gate**：先建立空间成立性，再构图；构图不得新增长廊、桥、楼梯、道路或地标来“优化画面”。
- **World Identity Gate**：世界观优先通过结构、基础设施、日常系统与有限符号共同成立；不能只靠 banner / emblem / giant fantasy ornament。
- **State Gate**：古老不等于废弃。Active / Maintained 场景必须先读成完整、可用、持续维护。
- **Camera Gate**：明确机位必须产生对应几何后果；冲突机位词必须消除。
- **Cinematic Gate**：电影感不自动等于青橙、唯一最亮点、极端光比、神光、雾、浅景深、前景遮挡、胶片颗粒、anamorphic 或极端角度。
- **Density Gate**：宏观密度由 `16` 决定；局部功能物密度由 `18` 决定；两者不得重复写成两套“信息密度规则”。

# 8. Human Presence

Scene 默认是 **No character subject**，不是固定 `no people`。

允许低权重环境人物用于：
- 城市 / 市场 / 港口 / 车站的运行证据
- 公共机构的使用状态
- 尺度参照

要求：`small-scale, subordinate, no character focus`。

只有用户明确无人、纯建筑 / 空间资产图、结构测试，或人物会干扰读取时，才使用人物排除词。

# 9. Parameters & Negative Prompt

- 正向结构优先，`--no` 一般只处理 1–3 类当前最高风险漂移。
- 画幅由 `--ar` 表达后，正文不重复堆 `21:9 / widescreen / ultra-wide frame`。
- 用户未要求文字时可按需排除 `text, watermark, signature`。
- `letterbox / matte border` 只在生成反复出现黑边时作为 repair，不作为电影感默认负面词。
- 人物是否排除服从 Human Presence。
- **任何未指定版本的最终 MJ Prompt 必须包含 `--v 8.2`。**
- 风格图若有可用在线地址，可依对应模型支持使用 `--sref URL`；若通过 MJ 网站上传，则用户在 **Style Reference** 槽中指定。不得根据本聊天中的图片凭空生成 URL。`--sw` 仅在需要且兼容时按用户明确设置或经实际反馈调整，不把强度数字作为默认质量档位。
- 普通 Image Prompt 和 Style Reference 不同：前者会影响内容/构图；**纯风格图不可错放为普通 Image Prompt**。
- V8.2 不使用 `--q`；Raw Mode 需要时使用 `--raw`。

# 10. Review / Repair

失败后先归因，再只重锁失败层：
- 主导视觉关系不清或镜头虽新奇却读不懂 → `VISUAL_INTENT_STATE` + `COMPOSITION_STATE`，不先堆质量词
- Identity / 类别漂移 → `IDENTITY_STATE`；形态组成和拓扑优先，不能只加气氛词
- Scale / Structure → `SCENE_STATE` + 结构因果审计
- World identity 太弱 / 太现实世界 / 只剩装饰 → `WORLD_IDENTITY_STATE`
- 地编随机、杂乱或过度整齐 → `18` 的 Activity Cluster / Behavior Hotspot Density
- Camera / POV、机位模式化 → `CAMERA_STATE`；复查身份可见性与实际视角几何
- Composition → Visual Organization，不重建设计已成立空间
- Cinematic feel / Lighting / Color / Atmosphere / Imaging → `CINEMATIC_IMAGE_STATE`
- Material / physics 假 → `12` 针对性 repair
- Style 漂移 → `STYLE_STATE` + `19`：区分媒介识别失败、风格信号稀释、文字/图片冲突、内容越权与尺度不可见；重编高杠杆锚点，不追加风格形容词清单
- Prompt 过载 → Semantic Compression

不要在旧 Prompt 末尾追加一串否定词修补。重新编译当前有效版本。

# 11. Final QA

交付前运行 `references/03-自检清单.md`。

任何以下失败都必须回退重编：
- 用户硬约束遗漏
- 模型版本不是用户指定版本或默认 V8.2
- 第一读取错误
- 主体身份类别或关键形态锚点缺失
- 风格与用户当前明确要求冲突，或无依据启用默认CG/电影化
- 风格参考图导致身份、设计、Camera 或场景内容污染；参考图入口和来源不可执行
- 输出只写“高质量动画/插画/电影”但没有对应的可见媒介机制，或媒介信号互相冲突
- 尺度路由错误
- Scene / World / Camera 权限冲突
- 主导视觉关系与首读对象互相冲突，或重要结构被无意遮蔽
- Camera Contract 未被物理执行
- 世界观仅靠装饰成立
- 正常运营场景被错误废墟化
- 电影感靠固定特效套餐成立

# 12. 交付

- Midjourney Prompt：纯英文，可直接复制。用户未指定风格时保持媒介中性，不添加无根据的CG或摄影词。
- 用户要求 Skill 时可交付完整主入口；引用到未提供的 Reference 应明确说明依赖，不能编造其内容。
- 说明 / 诊断：中文。
- 用户只要 Prompt 时，不附加无关解释。
- 用户明确禁止生成图片时，只输出 Prompt，不触发图片生成。
- 最终清理异常 Unicode 与随机外语残留。
- 画幅原则上由 `--ar` 表达。


# 13. Identity Anchors / Structure Compiler｜通用高精度主体机制

### 13.1 不把案例固化为规则

测试中任何失败或成功的具体主体仅用于推导抽象机制，不进入默认资产。新的任务应重新判断类别、剪影、关键形态、拓扑、功能和近邻混淆。身份锚点描述的是**当前主题为何可识别**，不是重复历史提示词中的外观设计。

### 13.2 可见锚点的优先级

- **必须看见**：当前题目不可替换的类别结构、数量、轮廓或与空间的关键关系。
- **有用时看见**：能提高独特性、解释用途的次级形态。
- **按尺度省略**：镜头中不可分辨的微观装饰、材质纹理和无功能的附加细节。

对多部分复杂主体，要求部件连续、同一对象身份、方向和比例合理，避免画面把不同类别的熟悉形状自由拼装。对高度特殊的目标，可采用明确职责的形态参考图/资产图稳定识别。

### 13.3 因果结构最小闭环

`核心用途 → 必需结构 → 部件连接 → 场景操作/使用证据`。只有影响画面可读性与功能成立的关系需要出现在最终 Prompt。视觉故事不自动意味着破败、杂乱或废弃。`Maintained / Active` 状态下的磨损和秩序按正常使用逻辑出现。

# 14. Camera and Composition｜美学决策，不是平视默认或极端镜头竞赛

未被用户指定的镜头由内容决定：
1. **阅读对象**：形态/轮廓、空间使用逻辑、整体布局或局部机制。
2. **候选机位**：至少在内部比较两种实际可能的相机位置；不输出比较历史。
3. **身份校验**：关键锚点是否可见；当前机位是否造成类别误读。
4. **空间校验**：前、中、后景连通和尺度后果是否符合物理位置。
5. **观看路线**：形成第一视觉焦点、次级线索、安静区域与必要的纵深。
6. **风格适配**：照片/CG可使用焦段、景深和光学语汇；手绘/原画可使用对应透视、笔触节奏和画面层次，不强制真实相机表现。

**最终只输出一个选定镜头**，禁止为了提高美感偷偷改变用户指定的机位。平视、中心构图及无前景遮挡可能是最佳选择，需由场景而非固定偏好决定。

# 15. Style Adapter｜风格动态编译

**默认状态 `STYLE_UNSPECIFIED` 不等于 `ultra-realistic CG`。** `19` 是风格编译执行细则，适用于文字和参考图两种输入。下表只是媒介边界示意，不是强制词库：

| 当前输入 | 允许的具体风格语汇 | 不应跨域自动注入 |
|---|---|---|
| 超写实CG / 高精度CG | 高精度结构、对应材质响应、合理全局光照、符合CG媒介的渲染完成度 | 摄影胶片颗粒、纪实抓拍、模拟胶片缺陷 |
| 实拍照片 | 真实相机、曝光、传感器或光学语言、自然场景材质 | Unreal / PBR / CGI 等渲染身份 |
| 电影截图或电影视觉 | 有动机的摄影机、明暗/色彩层级、视线叙事、合适成像 | 固定青橙、体积雾、颗粒、黑边、极端角度 |
| 手绘/油画/水彩 | 笔触、边缘概括、色面、手工材料表现、绘画空间 | 皮肤毛孔级材质、全景光追与PBR词 |
| 动画 / 平涂 | 造型节奏、线条、色块、风格化光影 | 超写实摄影材质、胶片高动态范围 |
| 游戏概念设计 | 主题形态、可读设计层级、结构逻辑、用户指定的表现媒介 | 固定照片或CG渲染身份 |
| 没有风格指定 | 清晰的主体、结构、空间、视角与色彩关系 | 任何预设画风或跨媒介质量套餐 |

把风格视为视觉表达的译码器，不改写身份/功能事实。**保真度 ≠ 必须写实**：风格化作品可通过形态准确、光影一致、设计自洽达到高质量。

**双路径，同一编译器**：
- **仅文字**：先从用户语言提取媒介、具体技法和画面反应，而非凭空假设具体笔触；缺省维度保持开放。
- **参考图辅助**：先按用户指定角色提取视觉证据，再执行同一风格语法；必要时在 MJ 端保留风格图原生引用，文字只补充用户所需但参考图较弱的内容约束。
- **文字 + 参考图**：逐维调和，仅继承双方都兼容的特征；用户明确锁定的媒介、内容、比例、机位永远不被参考图改写。
- **统一风格验收**：基于能否从成品中识别指定媒介、关键处理语法和跨域内容身份，而非标签数量或抽象“漂亮”程度。

# 16. Stability / Regression Protocol｜跨案例稳定性

修改 Skill 后，应以内容类型不同的新场景检验，而非反复让某一熟悉主题代替泛化测试。

推荐在同一组测试条件下比较：
- **Identity Accuracy**：类别、结构、比例与核心锚点是否正确。
- **Functional Coherence**：连接、邻接、行动/使用过程是否合理。
- **Camera Fitness**：机位是否清晰、符合要求并帮助识别主体。
- **Composition / Cinematic Quality**：主次、视觉路线、光影是否匹配指定目标；电影化只评价在被要求时的执行情况。
- **Style Fidelity**：是否忠于本轮风格，是否跨媒介污染。
- **Repeatability**：同配置多次生成的关键要求保持率。

对照时固定用户指定的模型、参数、画幅、seed（如有）。每次仅针对实际失败层修改主要变量，记录观察结论；未验证的假设不得直接升级成强制默认。测试结果中的具体形象、场景和错误不进入通用 Skill 正文。
