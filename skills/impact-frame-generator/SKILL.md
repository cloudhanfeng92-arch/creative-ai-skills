# 冲击帧与意向帧生成

输入一张攻击即将发生的画面，产出一组可直接交给剪辑软件的独立静态图片。核心是：原构图建立连续性 → 高反差图形突变 → 有含义的意向画面 → 回到原动作。

## 范围与输入

- 必需：可查看的攻击前一帧图片。先实际查看图片；仅有路径时打开原图。无法取得图片时，请用户提供图片，不凭文件名猜人物或动作。
- 可选：攻击方向、下一步动作、受击对象参考、意向主题、配色、输出数量、画幅、像素尺寸、生成平台和保存目录。
- 缺少可选信息时直接采用下述默认值；只在无法辨明主参考、或用户要求特定但未提供参考的角色身份时提出必要问题。已有图可用于不依赖缺失信息的部分。
- 用户调用本技能要求生成图片，即执行图片生成；不额外设置“先确认提示词”的通用关卡。用户明确要求先审方案、只写提示词或禁止生成时，停在相应阶段。
- 创建或修改本技能不等于执行一次生图。视频生成、视频剪辑、发布不属于默认任务。

## 1. 建立原图约束

用简短记录明确以下信息，之后写入每张图的实际提示词：

- 主体身份、可见服装、人数；武器或接触物的数量、轮廓、握持方式。
- 人物位置、身体朝向、手部与武器相对位置、透视、景别和原图宽高比。
- 可见攻击走向、能量形状、主要受力点及留白；不把静止画面无法证明的运动说成已知事实。
- 配色优先级：用户指定 → 原图明确的能量或主题色 → 红黑与紫黑示例配色。原图为普通自然色、没有明确能量色时可采用示例配色。

输入含黑边时，默认保留整体画幅与主体位置，不擅自裁切；用户要求去黑边时，先确定有效画幅并让整组统一采用它。字幕、播放按钮等截图叠层不属于场景，不写入生成画面。

人物冲击图保持原图姿势、构图和轮廓，仅改变图形化表现与配色。主体也可以是非人角色或物体，沿用其原有结构，不强行改成人形。允许把背景概括成黑色块面和有方向的笔触，但不镜像角色、不换手、不换武器、不挪动攻击焦点。不要把示例的剑客、黑夜、怪物或旋涡当作必需元素。

意向帧可以改变构图、抽象空间和能量形状，但须围绕同一次动作。用户未给出敌人或下一步剧情时，选用原图主体的力量剪影、攻击轨迹、压力集中或即将破裂的抽象图形，不凭空新增一个具体敌人或宣告胜负。

## 2. 规划独立图片

默认生成下列六张；数量与主题可由用户覆盖。每个资产是一张完整图片，不用一张六宫格代替六个文件。

| ID | 类型 | 默认画面职责 |
|---|---|---|
| IF01 | 人物冲击图 | 原图轮廓，大面积黑底，主强调色撕裂笔触，第一次强烈突变 |
| IF02 | 人物冲击图 | 同姿势同构图，第二强调色与少量白色锐边，形成色彩跳变 |
| IF03 | 人物冲击图 | 同姿势同构图，黑白块面对撞，少量强调色，形成亮度跳变 |
| IN01 | 意向帧 | 沿攻击方向聚集的轨迹、压力或能量场；旋涡只在原图或用户设定支持时采用 |
| IN02 | 意向帧 | 叙事峰值：可见或有参考的受击对象、明确下一动作；无此信息时用原主体力量剪影或抽象压力峰值 |
| IN03 | 意向帧 | 同一能量或运动母题的释放、撕裂或扩散，为回到动作提供视觉衔接 |

先向用户简述本次实际数量的资产方案和默认假设，然后继续执行已获授权的生图。不要为了等待可选配色答复停住全部任务。

## 3. 写提示词并生成

写提示词时读取 [提示词配方](references/prompt-recipes.md)，按当前图片填入真实信息；删除不适用的句子，不能把占位符直接交给模型。

- 默认中文。英文仅在用户需要时独立编写，保持身份、动作和空间事实一致，不用机械逐句翻译代替适配。
- 用户没有指定平台时，使用当前可用的内置 `image_gen` 生图工具。若环境有 `imagegen` 技能，按其当前工具与保存规则操作；没有该技能时，本文件仍提供必要流程。
- 一图一次调用，每次明确参考图的角色。IF01–IF03 都以原始图片为编辑目标，不把上一张生成结果层层当作唯一来源，以免姿势和身份累积漂移。
- 对包含可辨认角色的 IN 图，传入对应真实参考；纯抽象 IN 图以原图作为运动、色彩或构图参考，并明确无需复现人物。
- 工具支持本地参考路径时传入实际存在的路径。只能引用近期会话图片时，按工具支持的数量包含全部所需参考；不要混入无关图片，也不要把 Markdown 文件链接当成已传入图片。参考超出工具可引用范围时说明缺项并取得参考后再执行依赖它的图片。
- 默认满画幅、不透明输出，保留原图比例；用户指定透明、其他比例或尺寸时按要求调整并检查。不能把提示词中的“4K”当作实际分辨率。
- 用户指定其他平台时，使用其真实可用能力与已有授权，不擅自更换模型、发起付费试验或突破预算。内置工具不可用时保留已完成内容与提示词，说明缺少能力；不静默改用需要 API 密钥或额外计费的方式。
- 出错先确认任务状态与已有输出，再决定是否重试，防止重复提交。局部质量问题优先单张修复；默认每张至多一次针对性修正，仍不合格则保留版本并标注具体问题，后续追加按用户范围和预算执行。

## 4. 逐张验收

实际查看每张输出，再记录结果：

- IF 图与原图的人物位置、姿势、武器、手部关系、左右方向及攻击焦点一致。
- 本次 IF 图之间存在明确的颜色或黑白块面差异，不只是微小调色；仅一张时检查其与原图的风格突变。
- IN 图有清楚的动作、情绪或能量意图；角色依据来自实际输入，抽象画面没有无意生成的新脸、新手或新武器。
- 缩小查看仍有清晰主体与力的方向；大片纯色、锐利轮廓和有组织的飞白可读，没有随机细碎噪点。去噪不抹掉设计性撕裂笔触。
- 每张为独立完整画面，无额外分格、字幕、示意编号或软件 UI；不把参考中的水印当成需扩展的风格元素。
- 检查实际像素尺寸、比例以及需要时的透明通道。比例或尺寸不满足要求时标记差异并修正，不拉伸人物、不伪称已达标。

生成成功、已保存、已视觉检查、用户已确认是不同状态。未经用户验收不要标成“用户已确认”。

## 5. 交付

将完成的图片保存到用户指定目录；未指定则在工作目录建 `impact-frames/`，已有同名文件时使用新的批次子目录，不覆盖旧图。保留原图与被替换版本。

仅提示词模式交付 `prompts.md` 与规划清单即可；清单明确图片尚未生成，图片文件路径和实测尺寸记为 `null`，将计划画幅另列，不能使用“已保存图片”或“已视觉验收”等状态。

交付以下内容：

1. 按 ID 命名的独立图片，如 `IF01.png`、`IN01.png`；保留真实编码与扩展名一致，不仅改后缀。
2. `prompts.md`：实际执行提示词、各图参考来源、简短原图约束与所用平台。
3. `manifest.json`：每图 ID、类型、文件路径、实测尺寸、生成与检查状态、已知问题，以及建议播放顺序。只有工具原生输出而没有可读取路径时，如实记录，不捏造本地文件。
4. 原生图片预览或可点击文件，并简短说明用途。总览图可附加，不能替代独立图片。

默认顺序建议：`IF01 → IN01 → IN02 → IF02 → IF03 → IN03 → 回原动作`。按本次实际数量与意图调整顺序，只引用本次已交付的图片 ID。这是可调整的节奏示例，不声称已完成视频剪辑。

用户需要剪辑参考时，可给出教程样例的 30 fps 节奏 `2 / 1 / 2 / 1 / 1 / 2 帧`，合计 9 帧约 0.30 秒；明确是参考样例而非固定规则。换帧率需重新换算，下一动作与接触时点未知时不能承诺精准衔接。说明可压短后续拖沓片段，但未经视频编辑请求不改动原视频。
