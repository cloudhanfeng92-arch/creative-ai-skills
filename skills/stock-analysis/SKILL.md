# 股票投资分析

一个入口覆盖综合研判及七类专项研究。默认中文，以 A 股为主，按证券实际上市地适配港股和美股。先判断数据是否适合当前决策，再解释证据如何支持观点、反证和行动条件。

## 共同规则与数据入口

先读 [共同研究规则](references/research-core.md)，执行其中的数据时效、来源、适用性和行动边界；本次已读过时直接沿用。

- 选择已授权工具时读 [MCP 分工与路由](references/mcp-routing.md)。
- 首次使用本地数据能力或取数失败时读 [连接指南](references/connection-guide.md)；默认无需数据账户、Token 或新增 MCP。
- 第一次使用数据源、取数失败或切换市场时读 [数据源与时效](references/data-sources.md)。
- 需要指标、估值或仓位计算时，只读 [分析方法](references/analysis-method.md) 中相关部分。

核对公司、代码、交易所、证券类别和币种。相同公司不同上市地或 ADR 不合并价格。标的不唯一时先澄清；未提供投资期限时先做一般研究，并区分短期交易条件与长期价值判断。连接存在不代表行情实时或数据授权完整，以实际工具和证据验证为准。

### 默认免密取数

1. 使用宿主搜索和网页读取核验新闻、政策、公告原文。已有适合任务的行情工具可以复用；本次分析共享已核实数据。
2. 运行 `python3 <技能目录>/scripts/free_market_data.py doctor`，离线检查运行环境。缺依赖时，用已有 Python 3.11+ 执行 `scripts/setup_free_data.py`，只在独立环境初始化一次；宿主自带 Python 可作为 `--python` 参数。安装不需要数据 Key，不修改系统 Python 或 MCP 配置，正常分析不重复安装/升级。
3. 通过 `free_market_data.py` 的 quote、daily、financials 按问题取数。CN 走 AKShare（含腾讯报价后备），HK/US 走 yfinance（失败时可用新浪历史降级）；参数以 `--help` 为准。输入明确代码和市场，不能用猜测代码代替身份核对。财报三表分别查询，仅取需要的数据。
4. 同时检查 `status`、非空结果、`limitations`、源时间与返回口径。`partial`/truncation 不是完整覆盖；timeout/provider_error/no_data 不算成功。失败后按 [连接指南](references/connection-guide.md) 降级；不反复重试同一失败接口，不自动改用需要账户的服务。
5. quote 的 `metadata_checks` 只核验已提供元数据；默认 120 秒只是诊断阈值，应另按任务确定时效要求。未知时间/市场状态继续查交易日历、停牌和源说明；不能把快照、Yahoo 日线或接口名称当成已验证实时。HK Yahoo 通常延迟 15 分钟，US 实际延迟仍按证券与返回证据判断。
6. 保留 `market_data.py` 作为 Tushare **可选增强**：只有用户明确选择或已有适用授权时调用。没有 TUSHARE_TOKEN 不阻断默认分析，也不引导用户必须购买权限。其他可选接入见 [增强连接](references/optional-connections.md)。

没有宿主网页工具时，可用 `scripts/web_data.py` 的 search/extract，优先已有 Tavily key，否则尝试 keyless；额度失败后停止该路径并说明正文缺口。不要在聊天里索要密钥。

## 综合分析流程

以下流程用于综合研判和股票比较，按任务裁剪：

1. **建立数据快照**：核实报价、交易状态和数据年龄；取相关最新财报、公告、近期事件及足够的同口径历史行情。行情、财报、研报、宏观分别标记时间，不把低频数据伪装成实时。
2. **市场与行业背景**：看相关指数、板块与政策，区分行业共振和公司自身变化。市场弱不自动等于个股必须卖出。
3. **业务与财务验证**：将盈利驱动与营收、利润、现金流、资产负债核对，找出持续性和异常项。不能只凭单个增长数字判断投资价值。
4. **估值与预期差**：解释当前价格隐含哪些增长假设；利好是否已披露或已被定价。券商目标价仅作有日期、有假设的外部观点。
5. **事件与价格结构**：核对催化事项与执行进度，再用有效行情检查趋势、量价、波动和流动性。技术信号描述价格状态，不能独立保证未来方向。
6. **反证与行动**：主要观点形成“事实及日期 → 影响盈利/估值/价格的机制 → 反面解释 → 失效条件”。长期看好但入场条件不佳时，给出等待条件，不强行推荐买入。

供应商“主力资金”等衍生指标须解释计算口径，不能直接当成真实机构净买入。不同工具可能复用相同底层源，不按工具数量投票，也不把同一研报转载当成多份证据。

宿主支持子代理且独立任务有实益时，可并行查询财务、事件和行业资料，共用标的身份、分析截止时点及币种，再统一核对冲突。不能让各模块反复抓相同数据，也不能用多个代理的一致意见替代证据。

## 建议与交付

优先输出一份整合结论，按问题裁剪：

1. **观点**：回答用户的问题；涉及投资建议时给可考虑买入 / 持有 / 观察 / 减仓 / 回避、适用期限和原因。证据缺失时明确暂不能判断的部分。
2. **数据基准**：标的、市场、币种、价格类型、报价时间及时区、延迟状态、分析时间；专项财务问题保留相应披露时点和期间。
3. **核心依据**：最重要的经营、财务、估值、事件或价格证据，原文链接放在对应判断旁。
4. **行动条件**：用户需要时说明何时考虑行动、区间如何得到、何时失效；精确盘中建议发出前再次取价。
5. **反面证据与下一检查点**：最可能推翻结论的事项、关键缺口及下次应核查的公告或价格条件。

目标区间是注明假设和期限的情景，不是必然到达的预测。证据充分度用文字说明，不伪造胜率。具体个人仓位须有用户风险预算、可用资金和已有敞口；缺少时仍完成研究，不用问卷阻塞全部工作。

股票比较统一时点、期限和口径；候选筛选说明实际股票池，不能只查几家公司就宣称“全市场最佳”。遵循共同规则中的不下单、按需保存和显式调度边界。
