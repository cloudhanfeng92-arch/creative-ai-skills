# 主题科普动画 · 简化流程

把一个主题制作成内容清楚、艺术方向鲜明、排版与动效有惊艳感的原创知识动画。先以动画导演的判断设计观众如何发现问题、追踪变化并理解结论，再用代码实现；把视觉论点、构图、时间、物性与声音共同用于解释。默认连续完成必要的事实核查、脚本、视觉设计、代码动画与导出，交付 MP4、可双击播放的 HTML、一张代码绘制的 PNG 封面和可编辑源码。用户只要方案、某种格式或局部修改时，按其范围完成。

## 默认选择

- 中文、普通成年观众、约 90 秒、16:9、1920×1080、30 fps；用户指定优先。时长由内容、文字阅读和画面节奏决定，不沿用其他项目或基础模板的 15 秒默认值。
- **默认不朗读、不生成 TTS。** 「旁白」「解说文案」「字幕」「歌词」默认是屏幕文字内容，用代码呈现。只有明确要求配音、口播、朗读或念出来时才生成语音；音乐、音效和所选歌曲中的已有歌声仍可使用，不额外念歌词。
- **默认用 JavaScript 合成原创 BGM 与适配音效。** 按主题、叙事情绪、时代文化与视觉语言选择声音，不按题材套固定曲风；音乐随知识推进发展，音效对应画面事件，推理与阅读段落减少密度、保留留白。离线输出真实音轨供 MP4 与 HTML 共用，保留合成源码；用户要求静音或指定现成音轨时优先遵循。
- **默认自主选择适合主题的视觉方向并继续制作。** 不要求 A/B/C 三选一，不在风格、脚本、样片之间停下来确认；用户明确要求先看方案、选风格或审核时才按其安排。
- **按主题自动选择 JavaScript + Canvas / WebGL、SVG / DOM 或 Three.js。** 根据解释过程、排版、空间与效果选型，必要时混合，复用已有工程和 `code-motion-video` 的可用工具。网页预览按需，不是制作 MP4 的必需步骤；需要浏览器时，优先且只用 Codex 内置浏览器的官方工具，先核对实际能力，不假定支持任意 JavaScript、seek、批量采帧、下载或离线验证。
- **禁止外部浏览器及间接启动。** 不使用 Google Chrome、Chrome for Testing、独立 Chromium，不改浏览器路径、不连接个人 profile/CDP、不用 Playwright/Puppeteer/Remotion 间接启动，也不通过系统 `open` 或桌面录屏绕行。内置不能完成视频导出时，才复用项目已有且确认不启动浏览器的原生 Canvas/Skia/SVG 等后台入口输出帧，再用 FFmpeg 编码；FFmpeg 不能直接渲染 HTML。没有兼容入口就保留源码和已有产物，说明 MP4 未完成。默认单任务、保守编码线程；内置也使用本机资源，不保证更省 CPU/GPU。
- 每次只处理当前这一条视频，按本主题原创字体、色彩、材质、镜头与动作。参考用于理解设计和节奏，不默认复刻、批量制作或上传发布。

## 按主题自动选型

- 二维机制、几何变化、手绘图解或常规粒子：优先考虑 **JavaScript + Canvas 2D**。
- 动态文字、路径、精细标注或公式：考虑 **SVG / DOM**，也可叠加到 Canvas / WebGL 主视觉。
- 大量粒子、连续场、光影或着色器形变：考虑 **JavaScript + WebGL**，二维效果同样适用。
- 真实三维结构、材质灯光或相机运动：考虑 **Three.js（WebGL）**，减少手写场景基础设施。

根据具体画面选择，不机械按题材套技术。兼顾视觉表现、已有依赖、导出耗时与离线打包，在分镜中简述选型理由后继续；不要求用户选择技术栈，也不先实现多套方案比较。技术服务于鲜明的排版与动效，不能为使用新工具削弱内容或增加无关步骤。

## 连续制作

1. **理解主题与关键事实。** 提取核心问题、受众与应带走的结论，复用已有工程和资料，只问无法合理推断的关键缺失信息。核对决定讲稿正确性的事实、数字、公式和历史表述，记录简短可追溯来源；区分事实、争议解释、教学示意与艺术表现，不编造引语和引用。
2. **确定视觉论点与动作分镜。** 先写清观众要发现什么，以及哪个可见机制、比较或空间变化支撑结论；选择一套视觉方向后继续。在现有分镜中简记「时间 / 文案 / 关键构图 / 主动作与响应 / 阅读落点 / 下一段承接」，不要另建审批文件。核心场面明确起势、变化重音、结论落点及视线流向；用一个主题母题组织全片的建立、变奏与回收，不做静态卡片轮播。新创作在确定分镜时读取 [创意与分镜](references/creative-direction.md) 的设计判断；局部修改只读相关部分，沿用已成立的设计。
3. **安排文字与声音时间轴。** 将文案拆成可读的句子或词组，按阅读停留与镜头设置 start/end，在现有分镜中记录配乐段落、关键音效 cue 及对应画面事件；声音风格、主次和同步按 [制作与交付](references/production.md) 的声音段编排。完整保留要表达的含义，不缩成只有几个标题词。歌词有现成音轨时按实际演唱安排；明确要求配音时才生成 TTS、测量实际音频并回填时间，其他情况不为字幕寻找配音工具。
4. **实现动画、声音与必要素材。** 用选定的 Canvas / WebGL / SVG / DOM 或 Three.js 绘制主视觉，字幕和公式可用清晰文字层或文字纹理，HTML 保留可定位的 `seek(t)`，与可用视频入口共用时间轴和纯绘制逻辑；该页面接口不代表内置工具可直接调用，输出能力与资源就绪后再导出。同一时刻应得到同一画面，随机效果固定种子。用 JavaScript 离线合成原创 BGM 与音效，导出最终混音并接入项目配置；指定音源或静音按用户要求处理。优先程序图形和现有素材，事实敏感的图片明确来源或示意性质。实现、音轨和输出细节按需读 [制作与交付](references/production.md)。
5. **完整输出并观察实际动效。** 实现中用允许入口或已有输出的少量关键静帧检查字形和排版；有实际可用导出路径时完整渲染一次 MP4，并打包同一时间轴的可播放 HTML。在一次轻量检查内，结合少量代表帧和从正式导出抽取的短时连续片段，实际观察承载核心解释的动作与关键交界：注意力能否接力、机制能否看懂、重音后能否阅读、空间是否连贯。静帧不能替代动作观察，不另设默认样片、低清全片或逐镜检查。用代码复用本片视觉元素，独立设计主题标题与主视觉的静态构图，单帧输出 `output/cover.png`；默认与视频同画幅、同分辨率，保留绘制源码。
6. **检查后交付。** 同一次轻量检查中，已有 MP4 做元数据规格检查，封面确认标题可读、无缺字或裁切。HTML 网页预览与播放验证按需，仅使用内置浏览器官方工具实际支持的访问和操作；不自动在系统浏览器打开，能力缺失或未执行时注明运行/离线行为未验证。视觉检查可从成片关键帧与连续片段完成，不强制打开网页。默认不穷举边界、不全片解码、不生成长验收报告。观察到缺字、遮挡、溢出、空白、过程失读或事实错误，只修复和检查受影响部分；封面修改只重新导出图片。没有实际观察动画时如实说明，不能凭脚本通过宣称观感已验收。

## 分镜节奏

- **动作镜约 2–4 秒，关键推理镜约 4–6 秒，公式镜约 6–8 秒。** 区间指包含动作和理解停留的整镜时长，是灵活参考，不是硬性限制。依据内容难度、文字密度、受众和音轨调整，不平均分镜、不机械交替，也不为满足类型而添加公式。
- 以「起态 → 核心变化 → 结论停留 → 承接」帮助规划，不把它变成每镜同样的四拍模板。动作镜突出一个变化，推理镜分步建立条件与结果，公式镜逐步关联符号、图解、变换和结论。决定动作何时发生及各时刻变化多少，主次动作按因果错时；较长镜头通过信息递进保持发展，推理和阅读时让关键区域稳定。
- 关键文字与图解完整就位后，留出普通观众读完并理解的时间；入场与转场不能占满整镜。默认无口播，过密信息应拆分或延长；用快慢、疏密与景别变化形成有呼吸的节奏，不以频繁切镜或持续运动替代设计。方法直接落实到现有分镜，不增加审核步骤。

## 字幕、排版与动效的设计标准

- **以可见的解释建立记忆点。** 让开场提出问题或暴露反常现象，核心动作兑现解释；字体、配色、材质与运动性格共同支持视觉论点。同一母题随知识推进改变作用、关系或尺度，结尾回收时应增加理解。表现力来自准确的变化、大胆构图与节奏反差，不以霓虹、闪烁或粒子数量代替。
- **排版本身承担构图。** 用大小字反差、非对称重心、负空间与疏密变化组织视线，允许文字跨栏、绕物、被遮挡后揭示或成为主视觉。相邻段落随内容改变构图关系，不整片复用一张标题卡。字体体系与对齐逻辑统一，不固定底部字幕、金色高亮或深色背景。
- **先设计关键状态，再编排动作。** 起始张力、变化重音和阅读落点都应有明确重心；运动中的留白、遮挡和文字位置随注意力重新分配。镜头跟随、推近或拉远须揭示关系，阅读时可以停住，不能用整页漂移充当运镜。
- **让文字参与解释。** 中文按语义分组，关键字可以成为连接、边界、标尺或事件参与者，说明文字可以稳定呈现。保留完整含义，后出现的词也有阅读时间；标题、图解、公式和声音不同时争抢重音。
- **动作有因果与物性。** 主体发起、相关对象响应，路径、加减速和错时体现关系；真实物体按其动力学与结构运动，抽象图形遵守已经建立的视觉规则。预备、重音、收势是表现手段，不将统一回弹或同一缓动套在所有物体上。
- **镜头交界也属于设计。** 关键转场沿共享物件、轮廓、路径或动作交接注意力，处理锚点位置、速度趋势、尺度和遮挡；共享对象保持身份，必要时重叠承接，不能每段清空后重新启动。叙事需要的硬切仍可用，不强制一镜到底。
- **按主题原创，避免模板感。** 借鉴参考的节奏和设计思路，不照搬字效、轨迹或物件；文史也可大胆构图，科学也可用精巧视觉隐喻。工程模板只复用播放器、时间轴和渲染接口，重写示例场景的构图与动作，不能只换文案与配色。具体方法见 [创意方向](references/creative-direction.md)。
- **形式不能改写事实。** 配色含义、概念形象、比较基准、图表尺度和时间倍率保持一致或清楚交代变化；区分数据编码、物理机制、历史事实与视觉隐喻。来源、公式、图例和必要的“示意”说明清楚可读；跨尺度或跨时代的顺畅转场不能冒充因果证据。英文副标仅在有表达价值时使用。
- **不添加无关文字。** MP4、HTML 与封面不出现“原创科普／代码绘制”“AI 制作”、技术栈、制作说明、自我宣传标签、调试信息或模板占位文字。署名、品牌水印仅在用户明确要求时加入；必要来源和“示意”等说明仍服务于内容。
- 将设计直接落实到现有分镜与代码，不增加风格评分、审美报告或确认关卡；优先做好关键构图和动作，避免为装饰增加重型依赖与制作耗时。

## 交付与效率

- 默认给出可点击的 `output/final.mp4`、`output/作品名.html`、`output/cover.png` 和源码路径，源码包含封面绘制实现；封面单独交付，不默认插入视频时间轴，用户指定平台尺寸时重新排版。保留实际用到的简短事实来源，素材来源有需要时记录，不强制建立大量空文档。
- HTML 是真正运行代码动画的作品，优先单文件离线播放，支持播放/暂停、重播、进度和按需开启声音；不以截图、仅嵌入 MP4 或需要开发服务器的入口替代。MP4 与 HTML 共用内容和时间轴；打包不代表运行验证完成，HTML 页面模式也不授权启动外部浏览器采帧。
- 无口播是默认完成形态，默认原创配乐与适配音效仍应实际合成进成品；只有用户要求静音时才省略。声音生成失败、指定音源或素材缺失时说明具体缺口；浏览器能发声也不代表 MP4 已有音轨。
- 复用现有环境、模板和工具前先核对底层是否启动浏览器；旧 `render-preview.mjs` / `render-video.mjs` 已禁用，不调用或改路径绕过。`validate-video.mjs`、`export-html.mjs` 等无浏览器校验/打包仍可用；环境未知或出错时只诊断具体依赖，不安装浏览器或重复整套检查。
- 已有 `video.project.json` 则按需更新，较长任务可记录真实阶段、文件和待办；不中断流程创建审批记录。局部修改保留其他有效内容，不从头重做核查、素材和工程。
- 输入示例见 [examples/prompts.md](examples/prompts.md)，使用说明见 [README.md](README.md)，仅需要时读取。严格审核或额外确认只按用户要求执行；知识正确性和用户明确要求仍需满足。
