# 视频生成路由与执行

在展示确认包前完整读取本文件：第 1–3 节只用于只读能力预检与设置选择，不创建任务、不上传无关素材；第 4–6 节只有在用户明确批准最新确认包后才能执行。目标是把已确认的图片映射和提示词忠实提交给一个当前真实可用的参考生视频模式，而不是在执行阶段重新创作。

## 1. 运行前能力检查

按此顺序检查：

1. **平台**：用户明确指定的平台优先；未指定时，在当前可用工具中选择支持所需参考模式的平台。
2. **模式**：确认它支持首帧、首尾帧或多模态参考中的目标模式。
3. **模型**：从平台的实时模型列表、命令帮助或参数 schema 验证，不凭记忆发明模型名、ID 或能力。
4. **规格**：验证时长、分辨率、画幅、参考图数量与格式；若用户要求声音，或平台会默认生成原生音频，再验证音频开关与实际能力。默认 15 秒只有在平台明确支持时才能提交。
5. **成本**：查询可得的积分、Credit、Stamina、可用余额或费用估计。若无法估价，确认包必须直说本次提交仍可能扣费，用户确认即接受未知消耗风险；若查询结果与确认包中的数字或范围有实质差异，更新确认包并重新等待。
6. **登录和素材**：只读检查并复用已有登录；确认前不上传素材。确认后只上传本次确认包列出的原始图片，不要上传无关素材。

如果参考图超过平台上限，不得静默丢弃、合成或降级。列出超限图片和可选处理方案，让用户选择后重新确认。

未指定平台时，优先选择已登录、能以最直接命令完成目标模式、且已实时验证能力的后端。一次直接生成不必为了工具丰富度强行引入画布；只有用户需要 LibTV 画布、可复用节点或其模型选择时再优先走 LibTV。

## 2. 模式选择

| 输入与目标 | 首选模式 | 说明 |
|---|---|---|
| 一张图，同一世界内 FPV 探索 | 首帧图生视频 | 图像1负责精确开场，结尾由提示词约束 |
| 两张图，图像1开场、图像2为明确结尾 | 首尾帧视频 | 只有平台与模型明确支持时，才可承诺首尾图约束 |
| 两张图，图像2是目标世界但不一定是字面终帧 | 首尾帧或多图参考 | 根据模型能力与用户对终帧精度的优先级选择，并披露差异 |
| 两张图，图像2只负责身份、产品、动作、场景或风格 | 多图参考 | 在提示词中限定图像2的属性角色，不得把它绑定成末帧 |
| 三张以上图片，包含途中世界、人物身份、产品细节或材质 | 多模态全能参考 | 在提示词中给每张图唯一角色；不要把风格图自动当作时间节点 |

首尾帧模式通常更有利于开场和结尾构图；多模态参考更适合多身份、多场景和复杂入口，但不一定保证像素级首尾帧。不要把“视觉参考”表述为模型无法保证的“逐像素复制”。

若用户同时要求“精确首尾帧”和额外身份、风格或途中世界参考，而当前平台没有同时满足两者的模式，先让用户选择端点精度或多参考一致性哪个优先。切换模式属于实质设置变化，必须重新确认。

三张以上图片只有在用户明确把它们定义为按顺序必须经过的关键帧，且平台确实支持相应多帧模式时，才考虑多帧视频。多帧故事模式通常按段转场，不应静默当作严格的一镜到底 FPV；必须披露其连续性限制。

对“飞入屏幕、门窗、镜面或物体后进入图像2世界”的双图请求：若首尾帧模式支持确认的时长和规格，优先使用首尾帧，并用提示词约束目标世界先在入口表面内以微运动出现；若只能使用多模态参考，必须在确认包中说明末帧只能尽量匹配图像2。

若单次生成不支持用户要求的时长，不要自动拆成多段，因为拼接不是真正的一镜到底。提供两个清楚选项：缩短为平台支持的单条时长，或把它改成多段后期衔接方案；后者必须说明连续性限制并逐次确认成本。

## 3. 平台路由

### Dreamina / 即梦

先加载并遵守 `$dreamina-cli`：

- 每次以 `dreamina -h` 和相关子命令的 `-h` 为当前权威来源。
- 一张开场图使用当前可用的 `image2video` 路径。
- 两张精确首尾图优先检查 `frames2video`。
- 多图片或全能参考优先检查 `multimodal2video`；本 Skill 只绑定确认过的图片。不要把 `multiframe2video` 当作可自由选择模型和文本导演提示词的等价替代。
- 不硬编码模型支持。确认子命令是否真的接受所选模型、时长、比例和分辨率。
- 生成命令返回 `submit_id` 或 `gen_status=querying` 只代表已受理。保存 ID 并用查询命令跟踪；只有 `gen_status=success` 才算成功，`fail` 时报告真实 `fail_reason`。

### SeaArt

先加载并遵守 `$seaartai`：

- 使用实时模型发现与参数查询确定模型 ID、版本、模式、时长、分辨率和画幅；不要硬编码或猜测。
- 一张或两张首尾图使用 `image2video`，并按当前 CLI 要求绑定 first frame 与可选 last frame。
- 多图参考使用 `reference2video`，把确认过的图片按当前 CLI 规定嵌入提示词占位符；不要改用旧的通用 `--image` 语义。
- 保存任务 ID、终态、返回的结果链接和实际返回的资源消耗；平台未返回的字段写明未知，不要编造。

### LibTV

先加载并遵守 `$libtv-cli`：

- 所有画布、素材、节点和模型操作都通过 `libtv` CLI；不要自行拼 HTTP 请求或绕到网页端。
- 以 `libtv --help`、相关子命令帮助、模型搜索结果和模型 schema 为准，确认参考模式和每个字段。
- 先确认目标画布或工作区，再上传确认过的原图、创建匹配的模型节点并运行；保存画布、节点和任务标识。
- 若模型 schema 不支持确认包中的参考绑定、时长或规格，停止并重新向用户说明，不要猜参数。
- `libtv node ... --run` 是同步等待命令：直接等待它输出终态 JSON 并退出。不要后台运行、不要自行加 timeout、不要看到 taskId 就停止，也不要在外部再包一层轮询或重新提交。

### 其他平台

只有在当前环境确实存在对应工具并能验证能力时才使用。遵守该平台自己的 Skill、帮助和确认门。不得为了“完成任务”而编造调用、任务 ID、结果链接或已生成状态。

## 4. 图片绑定与提示词提交

- 绑定顺序与确认包完全一致。保存一份 `图片编号 → 原始路径或上传资源 ID → 角色` 映射。
- 使用原图，不做美化、重绘、去字、压缩、裁切、补边、转码或换画幅，除非接口强制且用户已确认影响。
- 若工具必须转码但不改变视觉内容，可执行最小格式转换；记录转换，并确认分辨率、方向和色彩没有实质变化。
- 提交确认过的完整提示词。只允许做接口要求的引号转义、资源占位符或编号语法转换；任何创意删改都必须重新确认。
- 若平台有独立负面提示词字段，可将确认包中明确列出的负面约束移入该字段；保留一份实际提交的正向与负向文本。
- 不擅自开启音频、配乐、旁白、歌词、字幕、插帧、延长、高清修复或额外变体。只有确认包明确包含的设置可以提交。
- 用户未要求音频时，默认不添加旁白、配乐、歌词或字幕。若平台无法关闭原生音频，在确认包的“音频”和“能力限制”中明确披露，用户确认后才能提交。

提示词过长而接口有长度限制时，不要直接截断。先压缩重复修饰语，保留顺序为：图片角色和身份锚点、时间轴与空间路径、入口匹配、结尾构图、核心负面约束。展示压缩后的实际版本并重新确认。

## 5. 任务状态与停止条件

- 每次授权最多发起一次新的生成提交。
- 保存平台、命令或工具、模型、模式、参数、任务 ID、提交时间和实际提示词。
- 对异步平台使用有界轮询或平台状态查询，直到明确成功或失败；LibTV 的 `--run` 按上文同步等待例外执行。排队、处理中、提交成功和普通 shell 退出码 0 都不是成片成功，只有平台终态或 LibTV 终态 JSON 才算数。
- 遇到登录、授权、内容审核、积分不足、队列限制或模型不可用时，报告原始可理解错误和下一步。不要换账号、换模型或再次提交。
- 如果工具或当前运行环境无法继续等待而任务仍无终态，将它明确标为“生成尚未完成”，交付任务 ID、当前状态和继续查询方式，不得声称交付完成；后续只恢复查询同一任务，这不授权重新提交。

## 6. 成片验收

若本地拿到视频并且 `ffprobe` / `ffmpeg` 可用：

1. 用元数据核对时长、分辨率、画幅和是否包含意外音轨。
2. 默认 15 秒查看约 `0.2s、3s、7s、10.8s、11.2s、14.5s` 的关键帧，并额外查看穿越前后紧邻帧；其他时长按确认包中的四段边界等比例取样。
3. 必要时低速观看整个镜头，确认没有被单张关键帧掩盖的切镜、黑帧、闪烁、瞬移或主体重置。

硬性失败包括：参考图角色错误、开场或目标世界缺失、明显切镜或黑场、相机穿过非入口实体、入口无法解释、人物或产品身份严重漂移、终点冻结或重置、严重解剖/几何错误、时长或画幅错误。轻微节奏、光色或末帧偏差应如实描述，但不要自动重做。

不合格时按以下格式报告，并等待新的授权：

```text
验收结果：未通过
具体问题：<可观察到的失败>
最小修正：<只改动必要的提示词或设置>
再次生成设置：<平台、模型、模式、时长、画幅、数量和预计消耗>

如需按修正版再生成 1 次，请明确回复“确认重新生成”。
```
