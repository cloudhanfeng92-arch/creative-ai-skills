# 剧本生成短剧一键

## 目标与范围

将完整剧本转成可执行、可验收的短剧制作工程，并在已授权范围内生成资产与视频。
本技能继承 viral-video-breakdown-replication 的剧情保护、表演控制、一致性锁、
生成分段和两个确认节点，但以用户剧本为依据，不要求上传参考视频，不逆向还原原片。
本文件与所链接模板足以独立执行，无需加载原技能。

最高优先级：完整剧情、完整台词、人物关系、剧本明确的时间要求、角色与场景一致性、
动作因果、故事和情绪连续性。未经用户要求，不润色或增删台词、不改结局、不增加出镜角色，
不以“更电影感”或“更适合 AI”为由改变故事。

本技能的创建、审阅或修改请求，只处理技能文件，不触发媒体生成。
用户只要求解析、分镜或提示词时，只完成对应方案，不主动生图或生视频。

## 输入与默认设置

- 必需：完整剧本，含角色、对白与剧情动作；可来自文字或可读取文档。
- 可选：角色面部/全身图、场景图、道具图、画风图；逐一标明用途与对应 ID。
- 有参考图时先查看。只提供面部图时锁定身份，缺失服装、身材和鞋等作为“制作补全”列明。
- 没有参考图也能执行：依据剧本设计资产，不虚构已看过用户参考图。
- 优先级：用户当前明确要求 > 已确认剧本与资产 > 参考图在其指定用途内的信息 > 制作补全。
  核心身份、关系或剧情与参考图冲突时，提出具体冲突并先推进不受影响的分析。
- 未指定画幅时，短剧视频默认 9:16；资产资料卡默认横向 16:9，便于排列多视图。
- 所有新生成图片默认 **2K、中质量（medium）**，包括角色图、场景卡和可选关键首帧。
  默认交付尺寸横向 2560×1440、竖向 1440×2560；如工具的原生 2K 档不同，记录实际尺寸。
  先查工具参数；不能把提示词里的“2K/medium”当成实际参数已经生效。
  不支持 medium 时使用最近的受支持档并说明，不暗中升到高质量/4K。
  不将低分辨率插值放大冒充原生 2K；如需后处理，明确记录原始与交付尺寸。
- 模型与平台遵循用户已有选择；原技能未固定模型，不无依据绑定新的供应商。
  用户指定 LibTV 时加载 libtv-cli，通过官方 CLI 操作，核实模型及参考模式；
  有明确 Seedance 2.0 或 Lib Image 2.5 偏好时继承，不擅自换成其他版本。
  LibTV 下载图片和视频一律使用 VIP 无水印通道；通道不可用则报告，不偷偷用普通下载代替。

## 工作流程与确认

1. 读取完整剧本及参考图，解析故事、人物关系与情绪走向。
2. 建立角色、场景、空间、道具、对白与跨段连续性锁。
3. 将剧本转成完整时间轴，区分镜头规划和视频生成段。
4. 写出全部角色四视图、场景多视角资料卡和逐段视频提示词，给出 MODE A/B 判断。
5. **Gate 1：生图前确认。** 提供可审阅方案、资产数量、图片规格、模型与已知成本，
   等待用户确认。建议询问：“已整理剧本解析、时间轴、角色四视图、场景资料卡和视频提示词，
   是否按这份方案生成 2K、中质量的角色与场景参考图？”
6. 生成角色四视图并检查，再生成每场景一张空场景资料卡并检查，建立主参考资产集。
7. 必要时使用已确认角色图和场景卡制作关键首帧；若未包含在生图授权范围，先展示新增范围。
8. **Gate 2：生视频前确认。** 展示已生成资产、关键帧（如有）、生成段和最终视频提示词，
   等待用户明确确认采用 MODE A 或 MODE B 生成视频。
9. 按故事顺序生成视频，继承上一段结束状态；对照剧本检查，针对失败段修复。
10. 在用户要求成片时完成剪辑、字幕、声音同步和最终导出；只要求提交时如实交付任务状态。

“一键”表示自动解析和编排，不默认取消两个确认节点。已经收到针对同一具体范围的明确授权，
无需反复询问；用户明确覆盖默认确认流程时尊重其指令，但不扩大授权范围。
工具缺失不伪造完成：先交付可执行方案、提示词和实际完成资产，说明具体阻塞阶段。

## 剧本解析与时间规划

先回答“整个故事讲了什么”，再写提示词。输出题材、视觉风格、画幅、目标/估算时长、
场景和实际出镜角色数量，以及起因、冲突、升级、高潮、反转（如有）、结局和核心情绪。
完整复述谁在何处、谁先说话/行动、主动权如何变化、什么对白或动作推动转折。
没有反转的剧本不要硬加反转。标明每项是剧本明确、参考图确定还是制作补全。

- 角色按 CHAR_A、CHAR_B 编号，别名合并，不随镜头换身份。
- 场景按物理地点去重成 SCENE_A、SCENE_B；同一房间换角度不算新场景。
- 每句对白建立 LINE_001 等唯一 ID，逐字保存说话者、原文、顺序、画内/画外与对应剧本段落。
  只在台词提及但不出镜的人物不生成角色资产、不加入画面。
- 缺少口头对白的剧本不擅自添加台词；未写明镜头时可补充摄影和剪辑设计。
- 时间为导演规划而非实测原片。标注“估算”，根据对白朗读、停顿、动作、反应和转场估时；
  可先用普通中文对白约每秒 3—5 字粗估，情绪语速与停顿另算，后续以实际音频核验。
- 用户给出明确时间码时保留。未给时长时按完整剧情估算，不强制压成一分钟。
  若指定时长容纳不了原对白，明确冲突并提供延长时长或用户批准压缩的选项，不能偷偷删词或极端加速。
- 时间轴从 0 连续覆盖计划结束，无缺口/重复；每条有时段、SHOT ID、场景、镜头动作、对白及表演。
  每句 LINE 必须有落点，无对白镜头也明确写出停顿和声音。
- 区分故事时间、镜头时间、CLIP 局部时间与模型实际生成时长；整数时长补齐用于头尾余量，
  不能因此挪改台词或在拼接中重复一句话。

固定时间轴表：

| 时间 | 镜头与动作 | 台词及表演 |
|---|---|---|
| 起点—终点；SHOT/SCENE ID | 景别、焦段感、机位高度/方向、构图、空间、动作和运镜 | LINE ID、角色、原文、语气、视线、表情、停顿和声音 |

## 一致性锁

使用稳定 ID 写入资产清单，详细字段与提示词参见 [references/production-templates.md](references/production-templates.md)。
准备 Gate 1 方案和实际生图/视频提示词时读取该模板。

- CHARACTER_LOCK：身份、文化背景、年龄、性别、身高体型、五官肤色、发型发色、妆容、服装材质颜色、
  鞋、首饰、气质及身体状态。中国题材保持自然中国演员特征、真实年龄和肤质，避免无依据混血化或过度磨皮。
- SCENE_LOCK：时代、室内外、建筑尺寸、墙地顶、门窗家具、道具、前中后景、时间天气、光源方向色温、材质色调。
- SPATIAL_LOCK：用场景坐标/东南西北或固定墙面编号锁定物体和人物站位，单独记录各机位的屏幕左右。
  反打改变屏幕左右是透视结果，不能为了“永远画左”移动家具；保持 180 度轴线与视线匹配。
- PROP_LOCK：颜色、形状、尺寸、材质、纹样、数量、位置、持有者/左右手、状态变化。防止增殖、消失或换手错误。
- DIALOGUE_LOCK：每句角色、全文、起止时间、语速语气、停顿重音、音量、画内外和固定音色特征。
- STORY_CONTINUITY_LOCK：每段起止人物位置/朝向/视线/情绪/持物/衣服/伤势、门窗道具状态、最后一句和最后动作。

资产确认后全片复用。剧本明确换装、昼夜变化、受伤或物件移动时建立显式状态版本，
继续使用同一身份和物理空间，不把剧情必要变化误判为漂移。

## 图片资产：每角色一张四视图，每场景一张资料卡

### 角色四视图

每个实际需要固定身份的角色输出一张横向四分区资料卡：
**正面全身 / 同侧侧面全身（明确左或右）/ 背面全身 / 正面面部特写**。
前三格同一比例、同一地面线、头脚完整；第四格清晰展示五官、发际线与首饰。
所有分区是同一人、同一年龄与造型，简洁中性背景、均匀可读光线、自然姿态。
不出现其他角色、剧情动作和复杂布景。参考图存在时锁脸；无参考时从 CHARACTER_LOCK 设计。
不要把四视图误做成四张独立图片，也不要用四个头像代替全身三视角。
角色图只锁身份，不是剧情首帧。

### 场景多视角资料卡（Location / Scene Bible）

**一个物理场景只生成和交付一张最终多视角资料卡**，默认横向 16:9、2K、中质量。
在一次生成中呈现专业影视排版，主视角占较大区域，各角度有清晰简短标注。
必要视角：

1. 主视角：主要摄影方向。
2. 反打视角：同一表演轴的反向摄影方向。
3. 前视角：入口向空间内部。
4. 后视角：主要背景向外。
5. 左视角：从空间左侧向内。
6. 右视角：从空间右侧向内。

有空间连续性需求时在同一张卡追加俯视平面图、建立镜头、道具细节区、产品区或角色动作区。
动作区仅用空场景区域/地面标记表示，默认不画演员。与已有角度相近时标明方向和用途，
不用凭空增加房间来制造差异。各分区为同一空间的不同摄影机视点，固定门窗、家具、物件数量、
坐标、材质和世界光源方向；禁止镜像空间。昼夜等状态变化以卡内标注或小分区表示，
除用户另有要求不额外增加同场景卡。

默认不生成或交付六张独立方向图再额外生成总览。确需内部裁切用于视频参考时，
从已确认资料卡无损提取合适分区作为中间参考，保留父资产来源，不另行设计新场景。
多视角卡仅为环境参考，禁止视频把边框、分格、标签或俯视图当成剧情画面。

## 镜头表演和生成段

每个镜头写出景别/焦段感、机位高度/角度/方向、构图与前中后景、人物站位、视线、
手和身体动作、表情、停顿、台词角色/语气/重音、硬切/连续镜头/运镜、环境运动、声音及剧情作用。
用 Face（眉眼口下颌）、Eyes（看向谁）、Body（重心/手/呼吸）、Timing（微反应/停顿/爆发）
描述表演，不只写“生气”。动作按准备→发力→执行→接触→对方反应→结束状态描述。

当前只有指定角色开口，其他人闭嘴反应；画外音镜头明确画面角色不对这句台词口型。
剧本明确同时说话才允许重叠；不得默认让所有人一起说。音色跨段保持一致，不能只锁画面不锁声音。

镜头规划不等于生成任务划分：

- **计划成片 ≤15 秒：一个完整视频生成任务**，内部可以硬切多个镜头，不拆成几个短段后拼接。
- **计划成片 >15 秒：优先每段 12—15 秒**，依完整对白、动作、对话轮次、情绪阶段或转场切段。
- 不截断同一句对白，不把动作准备与接触/反应分开；不机械每 15 秒切。
- 4—10 秒段仅用于关键复杂高潮、完全换场、明显时间跳跃、阵容大变或模型稳定性确需；
  尾段先尝试与邻段重新平衡，确无法避免的短尾段记录原因。
- 不凭空填充拖延以凑时长。若一段完整对白或关键动作超过当前模型上限，明确约束冲突，
  选择可承载的受支持模型或提出可审阅调整，不默默删词或违背整段原则。
- ≤15 秒的项目即使使用关键首帧也仍是一个生成任务；当前模型不支持时报告能力不符。

## MODE A / MODE B 与执行

MODE A 默认优先：模型支持多图/多主体参考，且站位和动作可稳定描述时，
使用对应角色四视图 + 场景资料卡 + 完整 CLIP 提示词直接生成。
每个 CLIP 只引用实际需要的角色和场景，不把全项目所有图片全部传入。
在提示词中说明四视图只表示一个人，场景卡只表示一个地点，禁止拼贴、重复人或复制标签。
若模型不适合直接读资料卡，用已确认卡的对应分区作为中间参考，不扩大资产生成范围。

MODE B 用于多人复杂站位、关键首镜、遮挡/动作复杂或 MODE A 持续站位失败。
先用已确认角色图与场景卡生成构图首帧，再检查身份、空间和持物；不可先造首帧再反推角色。
身份图、环境图与构图图职责分开。模型允许时同时提供首帧 + 角色 + 场景，
每个 CLIP 最多一个主要首帧，不给每个 SHOT 都默认生成一张。

每段视频 Prompt 必须独立可执行，包含基础规格、具体参考 ID/作用、角色和环境锁、站位与轴线、
实际允许出镜者、仅被提及不出镜者、从 0 到段尾的局部时间轴、全部对应对白与表演、机位/硬切、
动作音/环境音/音乐、音色与口型排他规则、起止状态及负向限制。
硬切只改变摄影机，不改变人脸、年龄、服装或房间。明确是多镜头剪辑还是连续运镜。

Gate 2 后按 CLIP 顺序生成，核验上一段结束状态再定下一段的参考和衔接。
记录实际工具参数、节点/任务 ID、状态、输出路径与真实时长，遵循工具自身等待规范，
状态未知时先查原任务，不重复提交造成重复消耗。

## 验收与修复

逐段对照用户剧本及 LINE 清单核验：对白全文/顺序/角色/口型、剧情动作、人物关系、造型、
场景空间、道具状态、镜头顺序和时长、声音、表演情绪、高潮结尾和跨段连续性。
真实查看画面并听取或转写音轨。只查分辨率和是否有音轨不能声称对白或表演已验收；
不可访问的项目标注“未验证”。生成后用实际音频回校时间轴，不倒过来删改剧本适配成片。

问题分类：DIALOGUE / CHARACTER / SCENE / POSITION / ACTION / ACTING / CAMERA /
CONTINUITY / PHYSICS / MODEL_LIMIT / REFERENCE_IMAGE / PROMPT。

- 台词优先修：明确时间、说话者和旁人闭嘴/画外音，减少无关动作；不直接删除失败台词。
- 角色漂移：加强正确身份参考，删无关参考，强化角色锁，减少无关转身遮挡。
- 场景漂移：固定房间坐标、门窗、家具与光源，强调硬切只变机位。
- 动作失败：明确阶段、接触和反应顺序，减少并行动作；仅符合长片例外条件才缩短段长。
- 表演不足：指定视线、眉眼唇颌、呼吸、重心、停顿和情绪爆发点，不堆砌抽象形容词。

仅修失败资产/片段，保留成功版本和问题记录。每个失败项默认最多一次针对性自动重试，
仅在现有生成授权/预算覆盖时执行；仍失败则展示证据与调整方案，不无限消耗。

## 输出与交付

Gate 1 方案顺序：基础信息与估时依据 → 完整剧情 → 人物关系/权力与情绪变化 → 一致性锁 →
完整时间轴 → 各角色四视图提示词 → 各场景资料卡提示词 → CLIP 规划 → 每段完整视频提示词 →
MODE A/B 推荐及原因 → 具体生图确认。

交付目录按项目组织：

```text
项目/
  剧本解析与时间轴.md
  生成提示词.md
  资产与任务记录.json
  characters/CHAR_A_四视图.png ...
  scenes/SCENE_A_多视角资料卡.png ...
  keyframes/（仅 MODE B 需要时）
  clips/CLIP_01.mp4 ...
  final/（用户要求成片时）
```
