# 故事讲解视频生成

## 1. 任务与执行边界

将用户的故事种子或参考图转为完整可播放的视频：

**Narrative → Truth & Dramatic Engine → Narration & Dialogue → Asset Bible → Beat/Shot/Clip → Image → Video → Voice → Master Timeline → Edit → Final QC。**

优先级依次为：故事完整、史实或故事逻辑正确、人物关系与情绪弧线清楚、解说与画面同步、角色/场景/道具一致、角色声音一致、动作和表演可信灵动、镜头服务剧情、视觉统一、音频清晰、完整观看体验。电影感不能成为篡改事实、结局或人物关系的理由。

- 默认制作成片，须实际生成授权素材、剪辑、混音、导出并检查；只有提示词、片段或剪辑说明时不得宣称成片完成。
- 用户仅要方案、文案或某阶段时，执行到指定范围并保留可续作状态，不扩展为未经授权的生成。
- 免费分析、文案、提示词、时间轴、素材检查和本地剪辑可以连续完成。消耗积分、Credits 或实际生成资源的调用遵守第 4 节，包含免费试生成、音色试听、返工和升级画质。
- 分阶段展示结果；等待生成确认期间继续不依赖该结果的分析。不要反复询问已批准且未改变的同一批次。
- 本文件包含独立使用所需的核心规范。随附数值校验脚本用于提高可靠性，缺少脚本时按第 10 节逐项校验；不能因脚本通过就跳过听审和视觉检查。
- 进入故事解析、资产拆解、分镜/图生视频、配音同步或剪辑验片时，读取 [references/directing-playbook.md](references/directing-playbook.md) 的对应小节。它提供执行细节，但不覆盖本文件的权限、模型实测、生成确认和项目状态规则。

## 2. 输入、默认值与工具就绪

接受纯文字、一张图、多张图、图文组合。保存原始要求及参考文件，先读取或观看再使用，不仅依据文件名猜测内容。

| 输入项 | 处理方式 |
| --- | --- |
| 主题、情节、人物或参考图 | 至少一种；仅图时先描述可见内容，不能仅凭长相认定真实人物、具体身份或真实生平 |
| 故事性质 | 区分史实、争议、文学改编、神话传说、原创；不能确定真实身份而用户要求真实传记时，询问姓名或来源，继续整理视觉档案 |
| 受众、语言、口吻 | 用户指定优先；未指定时面向普通观众、中文旁白，依题材选择语气 |
| 总时长 | 默认 30–120 秒；简单故事约 30–60 秒，事件约 60–90 秒，传记约 90–120 秒，仅为规划参考 |
| 镜头与生成段 | Shot 按叙事需要决定；单镜生成段通常约 4–6 秒，多镜连续表演段在模型支持时通常约 8–15 秒，不为凑数量截断台词、动作或情绪 |
| 画幅与导出 | 用户或平台要求优先；无要求时 16:9、1920×1080、25 fps、48 kHz，生成规格依模型实际支持，放大输出记录来源分辨率 |
| 生图模型 | 默认 **Lib Image**，用于角色四视图、必要空场景/道具图及生成段关键帧 |
| 视频模型 | 默认 **Seedance 2.0**；按实测能力选择角色/场景多参考直出或关键帧增强的图生视频模式 |
| 配音、音乐、音效模型 | 不虚构默认名称；检索实际可用能力后选择并在批次中展示 |
| 风格与参考 | 参考图优先；多图冲突时标注各自用途，重要身份或风格冲突待用户选择，不擅自混脸 |
| 字幕 | 默认生成画面无文字、无字幕、无 LOGO、无水印；成片默认不烧录字幕，用户要求时在剪辑层统一制作 |
| 预算、已有素材 | 沿用用户预算；复用适合且通过检查的已有素材并记录来源，不重复收费生成同一资产 |

非关键偏好缺失时先给出合理假设继续工作，不进行长问卷。关键身份、故事版本或指定结局不能可靠推断时再询问。

### 工具接入

1. 只读检查可用的图片、视频、TTS、Voice Reference、音乐、音效、语音对齐、媒体探测和剪辑工具，写入 `capabilities.json`，包含版本、限制、检查时间。工具不存在时不假装已经生成。
2. 使用 LibTV 时，先查找并阅读当前环境的 `libtv-cli/SKILL.md` 及相关命令文档。LibTV 的画布、模型、节点和上传均通过官方 `libtv` CLI，不编造 HTTP 接口或改用网页步骤。无该技能时使用 CLI 自带帮助。
3. 实际运行前用 `libtv model search --type image "Lib Image"`、`libtv model search --type video "Seedance 2.0"` 检索，再用 `libtv model "实际匹配的模型名或键"` 读取 schema。保存真实名称、键、允许时长、画幅、尺寸、参考图数量、音频输入及输出能力；不猜参数，不把默认名称当作当前可用保证。
4. LibTV 的 `-s model=...` 使用实际 `modelName`，不能直接填 `modelKey`。参考素材必须真实上传或连接为上游输入；在提示词里写“参考图”不等于完成绑定。
5. 在当前故事项目目录中绑定画布，或为命令显式指定真实项目 UUID；不修改无关项目。节点使用资产 ID 与版本命名，提交前查询是否已存在。创建、设参和连接不带 `--run`；审批成立后才运行 `libtv node <node> --run`。
6. `--run` 会等待终态。执行工具返回进程会话时等待同一进程，不因日志出现任务 ID 就重交任务，不另起生成轮询器、不自行加超时。中断恢复见第 13 节。
7. 提示词先保存 UTF-8 文件，用结构化参数或 Python `subprocess.run([...], shell=False)` 传递完整内容，避免引号、反引号或 `$()` 被 Shell 执行。日志不保存密钥或登录凭据。
8. 模型缺失、不支持所需参考方式、时长或声音控制时，完成可做的方案，说明限制并展示可行替代。更换模型或增加生成成本须更新批次确认，不静默替换。没有导出工具时交付可恢复工程并标注未完成，不能把方案称为成片。

## 3. 项目状态、版本和资产关联

创建独立项目根目录；中间文件放当前工作区 `work/<project-slug>/`，用户已有项目时沿用其约定；最终交付按当前环境输出目录规则保存。仅在用到时创建资产子目录，无对白等不适用项在清单记 `not_applicable` 及原因。

根目录维护：

- `project_state.json`：项目 ID、目标、默认值及覆盖值、当前阶段、阶段状态、脚本/画风/时间轴版本、下一步、阻塞原因、更新时间。
- `assets.json`：Asset_ID、种类、关联角色/镜头/音色、版本、依赖版本、原始路径、远程结果地址、SHA-256、实际参数、模型、任务/节点 ID、实测媒体信息、审批批次、QC 状态。地址失效不等于允许重新生成。
- `approvals.jsonl`：批次与逐项审批；`jobs.jsonl`：提交意图、实际提交、任务 ID、结果、费用及错误；追加记录，不覆盖历史。
- `capabilities.json`：实际能力；`decisions.md`：假设、史料争议、用户修改、取舍和未解决事项。

固定标识：项目 `PRJ_001`；时间轴 `TL_001`；剧情节拍 `BEAT_001`；镜头 `SH_001`；生成段 `CLIP_001`；角色 `CHAR_001`；场景 `SCENE_001`；道具 `PROP_001`；变体 `CHAR_001_YOUNG`；音色 `VOICE_CHAR_001`、`VOICE_NARRATOR`；素材如 `IMG_SH_001_v001`、`VID_CLIP_001_v001`、`AUD_NAR_001_v001`。删去对象保留 tombstone，不把旧 ID 分配给不同内容。

阶段顺序：`ANALYSIS → SCRIPT_TIMELINE → ASSET_BIBLE → CHARACTER_SCENE_PROP_REFS → STYLE_LOCK → SHOT_IMAGES → VOICE_REFS → VIDEO_CLIPS → NARRATION_DIALOGUE → MUSIC_SFX → EDIT → FINAL_QC → DELIVERED`。没有角色、对白、关键道具或重复场景时跳过相应生成并记录理由。风格草案在参考资产生成前建立，`STYLE_LOCK` 是参考资产审核后的锁定。

阶段状态为 `draft / awaiting_confirmation / approved / running / review / passed / blocked`；生成任务为 `prepared / approved / submitted / running / succeeded / failed / unknown`。服务返回 `succeeded` 不表示素材审核通过。

续作先读状态、审批、任务和资产，核对已有文件、依赖版本及未结束任务，从最早未完成且依赖已通过的项目继续。每次状态变化写盘，快照采用临时文件加原子替换。禁止把“继续”理解成重跑全部。

修改传播到依赖：改脸/服装→相关关键帧与视频；改音色→参考声音与相关台词；改旁白→语义时间轴、配音与剪辑；改切点→音频事件、EDL 与同步报告。只使受影响资产失效，保留原件和仍适用的批准项。失效素材可作为草稿，不能进入最终导出。

## 4. 用户确认与积分控制

执行顺序固定为：**完整提示词和参数 → 用户明确确认 → 执行已批准项目 → 展示结果。**

每轮生成前形成版本化批次卡，逐项列出：

```text
Batch_ID / Batch_Revision / 本轮目的
Item_ID / 关联 Character_ID、Scene_ID、Prop_ID、Shot_ID、Generation_Clip_ID、Voice_ID
完整提示词；音频须含逐字文本、读音和表演要求
实际参考图片/音频预览、文件或资产链接、用途与版本
模型真实显示名、模式、尺寸/画幅、时长、数量
预计积分或费用、来源与查询时间；未知就明确写未知
本轮总量、已知费用上限、重试额度（默认 0）
本轮输出及授权范围
```

- 多项生成先完整展示本轮每项提示词；长内容可写入完整可打开的提示词文件，聊天中提供目录和逐项链接，不能只给摘要而隐藏执行内容。
- 用一个简洁请求允许“全部确认”“仅确认 SH_001–SH_003”“修改第 2 项”。只执行明确同意的项；改文案、夸赞、沉默、超时不构成确认。
- 审批记录含确认原文或可核验消息标识、时间、批次版本、选中项目、提示词 SHA-256、参考资产哈希、模型参数、数量/时长、预算上限、已用次数。提交必须与批准快照一致。
- 已确认的未变更批次可连续执行，不逐项重复询问。提示词、参考内容、模型、数量、收费时长或费用上限有实质变化时，仅对变更项重新展示并确认。
- 初始“帮我制作视频”不批准尚未展示的所有生成。“全部确认”只覆盖本轮已展示内容，不覆盖未来视频、配音、音乐或重试。
- 查不到价格不猜数字；明确“费用未知，确认按所列模型和数量生成”。用户明确接受未知费用才可按该数量提交；已有硬预算却无法判断是否超额时保持待定。
- 默认没有额外重试、变体或放大授权。用户事先批准了具体重试数量及预算，可在范围内执行同参数重试；改提示词的返工仍需展示修改内容。
- 本地分析、读取、剪辑、测量、下载已完成结果及查询状态不增加生成额度，不因此再次询问生成批准。

## 5. 故事、旁白与初版时间轴

### 5.1 分析与依据

输出故事性质、年代、背景、主次人物和关系、起因、发展、转折、高潮、结局、视觉场景与叙事主题。传记可采用出生/背景→关键经历→转折→成就→结局；事件采用背景→起因→冲突→发展→高潮→结果与影响；成语采用人物→情境→行动→转折→结果→含义；原创采用目标→行动→冲突→高潮→结果。按内容适配，不机械填空。

自动建立 `Story_Bible`，将内容标记为 `FACT / INFERENCE / DRAMATIZATION`，并列出用户不可改动项。再提取剧情发动机：主角目标、阻力、失败代价、不可逆选择、高潮触发、结局变化和主题。建立人物 `Relationship_Arc`、`Power_Arc` 与 `Emotion_Arc`，逐段记录谁掌握主动权、冲突如何升级、权力何时反转、谁先产生情绪变化。不能只做事件摘要就进入分镜。

历史人物、事件、文学出处和引用名句须用可用的搜索/浏览工具核实关键事实，优先史料、原著、博物馆或学术机构来源，保存标题、URL、访问日期与支撑事实。核对时间、年龄、人物关系、地理、服饰、建筑、武器、交通、家具和用品。争议写明采用版本及理由；无法核实则标不确定，不伪装为史实。神话和文学情节不当作历史事实；原创补写或创作性对白标“戏剧化演绎”，不伪造原话。

参考图逐张分析外貌、视觉年龄与性别表现、发型、五官、服饰、比例、可见身份线索、场景、年代线索、建筑、道具、色彩、光线、构图及原图画风；区分可见事实与推测。仅图且没有真实身份要求时，可明确按原创角色提出故事，不捏造真实传记。

根据输入自动选择叙事模式：`传记时间弧 / 事件因果弧 / 成语寓意弧 / 神话任务弧 / 文学原著弧 / 原创冲突弧`。模式只决定组织方式，不强制固定幕数。开场优先使用危险问题、反常画面、冲突结果或关键决定形成钩子，随后尽快补足理解所需信息；不得为了“爆款”制造虚假事实或改变用户指定结局。

### 5.2 完整文案与时长预算

先形成 `Beat_Sheet`，再写完整可朗读旁白和必要的剧情对白，最后按语义分镜。每个 Beat 只承担一个主要叙事变化，覆盖钩子、建立、升级、转折、高潮与收束。文案须有清晰关系、因果推进、情绪递进和结局；信息过密时删枝节、保留因果与结局，不能只留名词和年份。

中文可暂按每秒约 3–4 个可读汉字估算，数字、年代、人名按实际读法计数，另计停顿；这只是规划值，不是真实音频时长。为对白、呼吸、关键动作及结尾留空间。保存 `estimated` 状态与估算方法；音频未生成时真实时长为 `null`，不用 0 冒充已测量。

旁白负责画面无法自行说明的时间、背景、动机、因果和意义，不逐字复述可见动作。每个 Narration_Cue 提取人物、地点、动作、事件、时间、指代对象、语义中心和必须出现的 `Visual_Evidence`。一句可跨多镜，一镜可容纳多句；按语义绑定时间，不按标点机械切镜。如“十八岁的霍去病……率八百骑兵深入大漠”，应展示青年霍去病、汉军骑兵、大漠和远征，不抢先展示下一句的战果。

对白只在推动行动、暴露关系、触发反转或制造必要情绪停顿时加入。每句记录 Dialogue_ID、说话者、对象、逐字文本、表层目的、潜台词、权力位置、情绪起止、语速、停顿、重音、画内/画外和反应者。语言须口语化、可表演、符合时代/年龄/身份；避免说明式长台词和机械轮流发言。历史创作性对白明确标记“戏剧化演绎”。

### 5.3 分镜规划

建立 Master Timeline 初版，依次拆成 `Beat → Shot → Generation Clip`：Beat 是剧情变化单位，Shot 是摄影机连续观察单位，Generation Clip 是一次模型调用的连续表演单位，可包含一个或多个 Shot。不能把“一镜一条视频”或“固定 15 秒一段”当成普遍规则。

- 模型支持内部切镜且身份稳定时，同场景、同一冲突单元优先组合为约 8–15 秒生成段，保护完整台词、动作链、反应和情绪落点。
- 单镜复杂动作、模型不擅长多镜切换或身份易漂移时，采用约 4–6 秒单镜生成段。
- 场景彻底变化、明显时间跳跃、人物阵容大变或复杂高潮单独成段；不在一句台词、动作接触或情绪爆发中间切段。
- 每个 Generation Clip 保存 `Input_State` 与 `Output_State`；后一段必须继承人物位置、朝向、表情、伤势、服装、手中道具及环境状态。

每镜完整记录时间、对应 Beat/旁白/对白、地点与时代、角色和变体、空间位置、动作因果、表演、景别、机位、构图、光线、环境运动、关键道具、情绪、镜头运动、声音、视觉证据窗口和下镜衔接。每次切镜至少必须新增关键信息、改变情绪强度、推进因果、展示必要反应或完成空间重定位之一。

展示总览：`时间 | Beat | Shot / Clip | 解说词/对白 | 视觉证据 | 画面 | 镜头 | 表演与动作 | 音频`；详细字段保存在分镜文件，不为表格简洁丢失信息。衔接说明角色方向、道具状态、空间位置与情绪如何承接。展示故事、完整文案、时长依据和分镜计划后继续准备首批资产提示词，到生成前统一请求确认。

## 6. 全局风格、资产圣经与连续性锁

### 6.1 Global Visual Style

在任何角色图生成前提出风格草案：艺术风格、摄影风格、色彩体系、光线来源与方向、镜头质感、材质、对比度、景深、颗粒和时代感。参考图优先；无参考时可按历史选电影历史写实、古代故事选东方历史电影、神话选东方史诗奇幻、儿童选绘本或动画、战争选史诗战争摄影。

完整风格记录为 `STYLE_001_v001`，角色参考通过后锁定。保持电影构图、丰富细节、可信环境、有来源的光线和统一材质；禁止无因由的风格切换、现代穿帮、文字乱码、字幕、LOGO、水印。神话和绘本中的“真实”指世界内部空间及物理规则自洽，不强行改为照片风格。

### 6.2 角色视觉档案与四视图

贯穿多个镜头的每个重要角色，先建独立档案并生成一张四视图设定图，再生成该角色的故事关键帧。四视图为 **正面全身、侧面全身、背面全身、正面面部特写**，不是四个不同角色。用户已有完全满足四视图的图且审核通过时登记复用；只有单张人物图时，用作身份参考补成四视图，生成前同样确认。

每个档案包含姓名、年龄、性别设定、身份、身高、体型、脸型、五官、肤色、发型、胡须、服装、鞋子、配饰、武器、标志道具、性格、常用表情和身份特征。没有史料依据的精确身高等注明“视觉设计设定”，不宣称为史实。角色 A/B/C 分开建档、分开出图，不混合五官、服饰和配饰。

角色提示词写明单角色、四区域布局、同一年龄/面孔/体型/套装、全身不裁脚、正侧背角度正确、面部特写清楚、简洁背景、统一光线材质及参考图用途，保持无文字标签。四视图布局与影片画幅可以不同，以模型支持及可辨识度为准。

角色通过后锁定面部、发色发型、年龄、身高身材、服装配饰、武器与身份。剧情需要青年/中年/老年或换装、伤势、湿衣时，建立明确变体及生效镜头，继承同一身份基础，不能随机改变人物。每镜记录入镜/出镜状态、朝向、所持道具及服装状态。

流程：档案与完整提示词→批次确认→生成四视图→逐视角视觉审核→展示结果并确定角色基准→锁定风格。未通过角色不进入下游。返工先指出具体失败部位、调整提示词并处理授权。可将已展示角色基准的接受与下一轮生成批准合并，避免重复询问。

### 6.3 场景、空间、道具与状态锁

完成 Beat Sheet 后自动建立 `Asset_Bible`，逐项标记已有、可复用、缺失、需要生成或不需要生成：

- `SCENE_LOCK`：时代、建筑、空间尺度、墙地顶、门窗、家具、前中后景、时间、天气、光源方向、色温、主色调、材质和主摄影方向。
- `SPATIAL_LOCK`：每个角色与关键物体的左右、前后、高低、朝向、视线、出入口和移动范围。除非剧情有移动，不得镜间左右互换或随机重排。
- `PROP_LOCK`：材质、尺寸、数量、初始位置、持有者、状态变化和剧情用途；避免突然消失、变色、变形、换手错误。
- `STATE_LOCK`：每镜/每段结束时的人物位置、朝向、表情、伤势、衣物、手中物、门窗和环境状态，直接作为下镜/下段输入。

同一场景跨镜复用或空间关系重要而缺少参考时，优先生成**不含主要人物的空场景参考图**，避免复制人物、角色融合和动作锁死。关键道具会被持握、交换、破坏或触发剧情且缺少参考时，再生成独立道具图。所有提示词、参考绑定和 QC 均使用真实 Asset_ID 与版本。

四类锚点职责必须分离：角色四视图锁身份，空场景图锁环境，道具图锁物件，关键帧锁构图和动作起点。不要让一张图同时承担全部职责，也不要仅在文字中声称绑定了模型实际没有接入的参考图。

## 7. 逐镜画面设计与关键帧生成

每个 Shot 都自动产出独立画面设计；是否实际生成图片按 Generation Clip 与模型能力决定。约 4–6 秒单镜生成段默认一张关键帧；可稳定承载多镜硬切的 8–15 秒生成段默认一张主要起始关键帧，只有多人复杂站位、首镜构图关键或模型需要额外控制时才增加构图锚点。不要把“每个 Shot 有画面设计”误解为“每个 Shot 必须额外生一张图”。

关键帧描绘**动作开始前或刚开始的可运动状态**，不提前呈现本镜或下镜尚未发生的结果。角色四视图、空场景图和道具图必须先于依赖它们的关键帧确认；关键帧使用这些已通过资产作为真实参考。额外场景/道具图只在连续性或模型输入确有必要时创建，纳入费用明细。

每镜完整生图提示词按以下顺序组织，可适配模型但不能丢失关键约束：

```text
Shot_ID / 时间段 / 对应解说词 / 关键帧在动作中的位置
主体：角色及变体，逐一展开身份、脸部、头发、服饰、道具锁定
场景：时代、地点、建筑、空间布局、时段、天气、环境细节及 SCENE_LOCK
空间：角色与物体的前后左右、高低、朝向、视线及 SPATIAL_LOCK
表演起点：姿态、身体重心、视线、微表情、人物关系、权力状态与即将发生的动作
摄影：景别、机位、构图、前中后景、焦点、光源、色彩与材质
全局风格：展开本镜需要的锁定风格，不只写“同上”
结束继承：本关键帧所属 Clip 的 Input_State；需要与上段结尾一致的状态
约束：身份不混淆、不改变服装道具和空间、不出现时代穿帮；无文字/字幕/LOGO/水印
模型与参数：Lib Image 或用户指定的已验证模型、画幅、尺寸、数量
真实参考绑定：参考 Asset_ID、角色/场景用途、版本与实际文件/节点
```

展示镜头号、旁白、完整提示词、角色参考、风格、实际模型后等待批次确认，不先生成再补提示词。将通过的角色图作为实际输入；模型不支持多参考时，提出可执行的参考组合或分步编辑方案并更新批次，不在文字里假装多参考已生效。

生成后逐张看图，核对脸、年龄、服装、道具、时代、空间、主体数量、画风、权力关系和动作起点，记录 `image_qc=passed/failed`。同时建立本批 `MASTER_REFERENCE_SET`，明确角色、空场景、道具与关键帧各自用途。所有依赖关键帧审核完成并经用户确认接受后，才能生成视频。可将图片接受与下一轮视频批准合并，但必须清楚展示图片。

## 8. Voice 系统、图生视频与旁白

### 8.1 固定声音身份

给旁白和每个有对白的角色建立 Voice_Profile：逻辑 Voice_ID、所属 Character_ID 或 narrator、实际服务商、模型、服务原生 voice/speaker ID、语种、音域、音色、语速、停顿、情绪、发音词典、参考音频 Asset_ID/版本及实际绑定方法。

旁白可按历史选沉稳叙事、战争选低沉厚重、神话选神秘史诗、儿童选温柔亲切、悬疑选克制紧张。一个角色全片复用同一声音身份；剧情年龄改变可定义声音变体，不随机换声。

模型支持 Voice Reference 时，可先生成 5–10 秒短参考，文本足以听辨声音且不承担额外剧情；完整文本、表演提示、模型及成本先确认。采用已可用且稳定的原生 voice ID 时可免去参考生成。逻辑 `VOICE_CHAR_001` 仅用于项目关联，不能当成服务商可调用的实际 ID。

核对参考时长、采样率、语言和模型输入限制，实际传入音色 ID 或参考文件。同一段文字描述不能保证固定音色；工具不支持稳定声音控制时，标注限制并在制作前选择可验证方案。没有对白时该角色的声音生成记 `not_applicable`。

### 8.2 台词与可见口型

旁白主导信息与因果，对白承担人物欲望、关系、冲突和反转。对白须简短自然、符合时代和身份、能被演员表演；不用大量说明式对白挤占讲解。历史名句核对出处；创作性台词标为“演绎台词”。每句有 Dialogue_ID、Character_ID、Voice_ID、说话对象、逐字文本、表层目的、潜台词、权力位置、情绪起止、语速、停顿、重音、计划时间和反应者。关键台词后保留微反应或沉默，避免角色像轮流播报台词。

配音方案在视频生成前确定：默认视频不生成旁白、BGM 或不可控制的角色声音，后期加入统一音轨。无法关闭模型音频时保留原片，剪辑中分离音轨并弃用冲突声音。

需要可见角色说话时，验证模型是否能绑定参考音频、稳定音色和控制口型。支持时把 Voice Reference 或正式台词音频作为真实输入并逐句检验；精确口型若必须由正式台词音频驱动，将该句配音作为已展示、另行确认的前置依赖，完整旁白仍可在视频后生成。不支持时用背影、侧后方、反应镜头或画外对白，或展示后续口型同步方案及费用待确认。不能用任意嘴部开合冒充已同步。

所有对话时段执行口型排他：只有当前指定角色开口；其他可见角色嘴巴闭合，以眼神、呼吸、手部、身体重心和微表情反应。画外对白标记 `Speaker_Visibility=off_screen`，当前画面角色不得误说该句。说话者切换必须给出自然停顿或反应时间。

### 8.3 图生视频提示词

根据 Generation Clip 的真实参考、所含 Shot、对应旁白/对白、上下段状态、权力关系、情绪和环境，为每个 Clip 写一份独立完整提示词。一个 Clip 可以是 4–6 秒单镜，也可以是模型实际支持的 8–15 秒多镜连续表演；无论哪种都从局部 `0.0s` 开始并完整覆盖，不把多地点或多个独立事件强塞在同一段。

每个关键 Shot 至少设计三种有因果的运动：推动剧情的 `Primary Motion`、另一角色或环境的 `Reaction Motion`、符合现场条件的 `Secondary Motion`。关键表演使用 `Face / Eyes / Body / Timing` 四层，把“愤怒、震惊、悲伤”等抽象词转成眉眼、嘴唇、下颌、视线、呼吸、重心、手部、停顿和爆发时点。重要动作按“预备姿态→重心与发力→动作路径→接触/触发→反应→余势→结束状态”书写；同一时刻通常只保留一个主要动作。

```text
Generation_Clip_ID；全片时间段；本地时间段；包含的 Beat_ID / Shot_ID
对应旁白/对白及 Visual_Evidence；实际参考预览、Asset_ID、版本与用途
模型与模式；生成时长与预定使用时长；画幅和规格
角色、场景、空间、道具及身份锁；允许出镜者和仅被提及者
Input_State：开场构图、位置、朝向、视线、手中物、伤势、情绪和动作准备
0.0–a 秒：Primary Motion 启动；Face/Eyes/Body/Timing；摄影机动机
a–b 秒：动作发展与接触/触发；Reaction Motion；对白及口型排他
b–结束：动作余势、情绪落点、Secondary Motion、视觉证据和必要切镜
摄影机：每个 Shot 的起始机位、路径、速度、跟随对象、焦点变化、切镜和终止构图
声音：对白逐字文本、时间、语气、画内/画外、Voice Reference/实际 Voice ID；现场声与动作声落点；旁白/BGM 的后期说明
Output_State：用于下段继承的位置、朝向、表情、伤势、服装、手中物和环境状态
限制：稳定身份/服装/道具/空间，可信物理，硬切只改变摄影机，无随机人物/切景，无文字/字幕/UI/水印
```

运动具体且可由起始参考实现，不能只写“人物轻微移动”，也不为热闹给无火场景加火、给室内强加风雨。推、拉、摇、移、跟拍、环绕、升降、俯冲、低机位、高空下降、手持、轨道及遮挡转场必须有叙事动机，一镜通常只有一个主要运镜意图，不堆叠炫技。静止或长凝视也可使用，但必须服务压迫、等待、悲伤或点题。结合主体、反应、环境和摄影机，使画面像演员正在经历事件，而不是电子相册。

### 8.4 视频生成

提交前执行 `SYNC_01_PRE_VIDEO`。展示本轮每个 Generation Clip 的全片时间、所含 Shot、旁白/对白、Visual Evidence、角色/空场景/道具/关键帧真实参考、完整导演提示词、实际计费秒数、模型、角色 Voice Reference（有则展示）及费用，取得明确批准后提交。

优先选择能真实维持身份、空间和表演连续性的模式：模型稳定支持角色/场景多参考和内部切镜时，可用多图参考直接生成一个连续表演段；首镜构图关键或多人站位复杂时加入关键首帧；只有 schema 支持且方案已展示时才用首尾帧或更多参考。可生成时长不等于所需时长时，选择支持的时长并预留裁剪，批次显示完整计费秒数，不能提交不存在的时长参数。

保存原始视频，不覆盖或截断原件。媒体探测读取实测时长、帧率、分辨率和音轨；抽查首/中/尾帧并完整播放动作，核对人物、物理动作、穿帮和衔接。全部视频完成后执行 `SYNC_02_POST_VIDEO`，将真实可用区间写回时间轴。服务成功但画面失败的片段不能标可交付。

### 8.5 正式旁白与角色对白

视频完成后，按已锁定完整文案与实际可用画面时长生成正式旁白；口型模型需要的正式对白按第 8.2 节前置。提交前展示逐字文案、Narration_Cue / Dialogue_ID、Voice_Profile、读音、情绪、语速/停顿、目标时长、分段策略、模型及费用并确认。工具需要分段时按语义和呼吸划分，复用同一声音与参数，听审接缝；不机械逐镜换音色。

中文人名、多音字、年号、数字和引文在发音词典中明确。情绪随起因、高潮、结局变化，不为赶时长牺牲清晰度。对白采用锁定身份，生成前同样确认；前置步骤已完成的正式台词不重复生成。

音频生成后探测实际时长，听全文并核对漏字、错读、重复、噪声及角色声音。对最终语音做文本强制对齐（工具可用时），或听审逐句标注真实入点/出点；仅以字数均分不能标记 `measured`。保存对齐方法及置信度，低置信度处复听。每个 Narration Cue 建立 `Visual_Evidence_Window`：关键词被听到时，人物、地点、动作、道具、结果或反应必须正在画面中可辨识出现，不能只满足“整镜主题大致相近”。

更新 `Narration_Audio_Duration`、`Dialogue_Audio_Duration` 与 Audio_Events；对齐内容出现时间，不只是总秒数。执行 `SYNC_03_PRE_COMPOSE`。超长/过短按第 10 节修复，涉及新生成时重新处理授权。

## 9. Master Timeline 数据规范

`03_master_timeline/master_timeline.json` 是唯一权威时间轴，剪辑 EDL 从它派生，不维护两个独立真源。变更增加 `Revision` 并保存上一版。时间为秒，从 0 开始、采用半开区间 `[Start_Time, End_Time)`；镜头边界按 FPS 对齐。显示用 `mm:ss.mmm`，不拿时间码字符串计算。

顶层结构：

```json
{
  "Timeline_ID": "TL_001",
  "Revision": 1,
  "FPS": 25,
  "Duration": 60.0,
  "Shots": [],
  "Audio_Events": []
}
```

以上是结构示意，执行前填入真实镜头，不把空数组当作可用时间轴。每个 Shot 至少包含：

| 字段 | 类型与规则 |
| --- | --- |
| Shot_ID | 唯一、稳定字符串 |
| Beat_ID / Generation_Clip_ID | 关联剧情节拍与实际模型调用段；同一 Clip 可包含多个连续 Shot |
| Start_Time / End_Time / Duration | 有限数值秒，Duration = End − Start，镜头连续覆盖全片 |
| Narration_Text | 本镜关联旁白文本；跨镜句通过 cue 关联避免重复播放 |
| Narration_Audio_Duration | 未生成为 null；生成后为本镜与旁白事件交集的播放秒数之和；确无旁白为 0 |
| Character_Dialogue | 数组，每条有 Dialogue_ID、Character_ID、Voice_ID、Text；无台词为 [] |
| Dialogue_Audio_Duration | 未生成为 null；测量后为本镜与对白事件交集秒数之和；无对白为 0 |
| Image / Video | 未生成为 null；成功后为引用对象，至少含 Asset_ID、Version、Path，保留实际参考及源片信息 |
| Camera_Movement / Character_Action | 摄影机路径及主体行动字符串 |
| Performance_Beat / Visual_Evidence | 可拍的表演变化，以及本镜必须为旁白/对白提供的可见证据 |
| Transition | 对象，Type、Duration、Handles、Next_Shot_ID；末镜 Next_Shot_ID=null |
| Music / SFX | 音频事件 Audio_ID 数组；无则 [] |
| Character_IDs | 本镜全部参与角色（可见及画外说话者）的 Character_ID 数组 |

扩展字段：Narration_Cue_IDs、Scene_ID、Character_Variants、Visible_Character_IDs、Offscreen_Character_IDs、Semantic_Tags（人物/地点/动作/事件/时间）、Power_State、Reaction_Motion、Secondary_Motion、Scene/Emotion/Props、Spatial_Lock_ID、State_Lock_ID、Source_In、Source_Out、Playback_Rate、Target_Duration、Measured_Duration、Input_State、Output_State、QC_Status、Notes。视觉角色匹配使用 `Visible_Character_IDs`，不能把画外发言者当成画面已出现的人。角色对白与音频事件使用相同 Dialogue_ID。

每个 Audio_Event 至少包含：

```text
Audio_ID: 唯一事件 ID，同一素材可被不同事件引用
Kind: narration | dialogue | music | sfx
Start_Time / End_Time: 最终视频中的播放区间
Shot_IDs: 实际覆盖的镜头列表
Text: 对应逐字文本，音乐/音效可空
Timing_Status: estimated | measured
Voice_ID: 旁白/对白必填，非语音可为 null
Character_ID: 对白必填，其他可为 null
Asset_ID / Path: 素材关联，尚未生成为 null
Source_In / Source_Out / Playback_Rate: 源音频范围和播放倍速
Dialogue_ID / Narration_Cue_ID: 按事件种类关联脚本
Speaker_Visibility: on_screen | off_screen（对白时）
Visual_Evidence_Windows: 旁白/对白关键词与可见证据的一个或多个时间窗口
```

语音事件绑定完整文本与真实播放区间；跨镜句用一个事件关联多镜，不能在每镜重复铺设完整音频或重复累计全段时长。每镜统计的是交集。默认旁白与对白错开，音乐/SFX 可重叠混音。声音桥接可跨视觉切点，但内容必须有语义对应镜头，不能以“桥接”为错位辩解。

画外对白记录 `Speaker_Visibility=off_screen`，发言者同时进入关联镜头的 `Offscreen_Character_IDs` 与 `Character_IDs`；视觉审核使用可见角色子集，避免误判为缺人。对白发言者必须存在于角色档案与 Voice 映射。

源片满足 `(Source_Out − Source_In) / Playback_Rate = 使用时长`，倍速为正数，音频同理。文件须存在可读，源范围不超过实测时长。工程保留相对项目路径，工具调用解析为实际绝对路径。

故事镜头区间连续不重叠。叠化通过额外源片 handles 在剪辑轨上覆盖边界，保留全片 Duration；不能拼接时又减一次叠化秒数。没有足够 handles 则缩短或硬切，重算 EDL 后校验。

## 10. 三次强制同步校验与修复

必须保存以下三份检查报告，另在成片后最终复核；不把规划检查当作实测通过：

| 检查点 | 时机与依据 | 通过条件 |
| --- | --- | --- |
| SYNC_01_PRE_VIDEO | 参考资产/关键帧已通过，视频未提交；估算旁白/对白及计划动作 | 人物、地点、空间、动作、事件、年代语义正确；Clip 不截断完整台词、动作链或情绪；估算状态明确 |
| SYNC_02_POST_VIDEO | 全部视频完成；源片实测及真实可用动作区间 | 视频覆盖计划使用段，身份/空间/动作/表演符合脚本，Input/Output State 可衔接，切点可执行；未生成音频仍标待实测 |
| SYNC_03_PRE_COMPOSE | 正式旁白/对白完成且已对齐，合成前 | 语音按实际音频落位，每个 Visual Evidence Window 有对应画面，语义/动作/口型/声音四层同步，总时长正确 |

报告分别保存至 `21_quality_check/`，记录 Timeline_ID、Revision、输入资产版本/哈希、依据是估算还是实测、每镜结果、错误、修复和复查状态。修改脚本、资产或时间后，受影响报告失效并重检，不复用旧版本的通过结果。

每次至少核对四层同步：`Semantic Sync`（关键词与视觉证据）、`Action Sync`（动作动词与发生时点）、`Dialogue Sync`（说话者、口型、表情、反应）、`Sound Sync`（脚步、接触、门响、爆炸等声音落点）。还须检查提及人物和指代、视频是否覆盖语音、画面是否提前切走、上一句是否错落到下一镜、语音是否无意重叠。按每个 Cue 和 Dialogue_ID 检查，不只查镜头首尾或全片总时长。

数值校验：ID/引用有效、秒数有限且非负、首镜从 0 开始、镜头无缺口或重复、末镜等于总时长、媒体存在且足够长、音频不越界、语音在绑定镜头中完全覆盖。帧边界和总时长容差为 1/FPS；不能靠增加容差放宽语义检查。

随附脚本可这样执行，命令中的路径占位须替换为真实路径：

```bash
python3 <skill-dir>/scripts/validate_timeline.py <project>/03_master_timeline/master_timeline.json --stage pre_video --output <project>/21_quality_check/numeric_pre_video.json
python3 <skill-dir>/scripts/validate_timeline.py <project>/03_master_timeline/master_timeline.json --stage post_video --output <project>/21_quality_check/numeric_post_video.json
python3 <skill-dir>/scripts/validate_timeline.py <project>/03_master_timeline/master_timeline.json --stage pre_compose --output <project>/21_quality_check/numeric_pre_compose.json
```

脚本只辅助检查公共字段、Beat/Clip 关联、同一 Clip 的 Shot 是否连续、时间数值、事件覆盖及对白角色是否属于关联镜头；提供源片区间和倍速时也检查使用时长公式。**不会探测媒体、听声音、看画面或验证史实，也不是第 9 节的完整 schema 验证器**。Agent 必须另查 Image/Video 的 Asset_ID、Version、Path 及阶段完整性，Transition 的字段、衔接与 handles，Visual Evidence 的真实可见性，以及 Dialogue_ID、Character_ID、Voice_ID、Text 在镜头、音频和声音档案间的一致性。`post_video` 还须探测并观看实片；`pre_compose` 还须听审对齐证据。不能直接复制数值结果作为整个 SYNC 报告。脚本统计的是本镜内相应语音事件交集，`pre_compose` 无该类语音时必须填 0，不能保留 null。

错位优先按顺序修复：在实际素材可用区间内调整镜长/切点→重排语义对应镜头与音频事件→适度视频变速→调整旁白停顿或保调变速→必要时改写、重录或重生成。改叙事内容返回文案审核，新增资源生成走批次确认。

小幅变速可先尝试约 0.90–1.10 倍并听审/看动作；只是编辑起点，不是质量保证。不能裁掉词尾、跳过重要动作、用长黑场或循环静帧掩盖不足。严重不匹配时重新设计该段，不硬拉秒数。结尾保留有叙事目的的余韵与音乐收束，避免无说明的长静默，也不误删有意义的留白。

## 11. BGM、音效与实际剪辑合成

为配乐规划完整情绪曲线及入出点，优先无人声器乐。按画面选择环境、风雨、马蹄、战场、武器、火、水、城市、人群、鸟鸣、脚步、衣物、门、车辆等声音，不给每镜堆满音效。

生成音乐/SFX 前完整展示风格、乐器、节奏、时长、情绪段落、循环要求、禁用内容、模型和费用，再确认。已有素材登记来源与使用信息后按授权范围复用。所有声音成为 Audio_Events；打击、门响、脚步落在动作发生点，不只登记文件名。

从 Master Timeline 编译 `19_edit_timeline/edit_timeline.json` 或实际编辑器的工程/EDL，按 Shot 使用每个 Generation Clip 中通过 QC 的区间，记录源路径、源入出点、轨道、时间轴入出点、速度、增益、转场和效果；不能把生成文件顺序直接当成最终剪辑。使用 FFmpeg 或现有剪辑工具**实际渲染**，不能在此停为“用户自行剪辑”。

1. 用 ffprobe 或等效工具探测输入，统一画幅、像素比例、帧率、编码及音频采样率。保持人物比例，避免裁掉面部和关键道具；保留原片，按需创建代理或中间文件。
2. 按源片入出点 trim，视频重置时间戳并按 Playback_Rate 处理后拼接；语音 trim/保调变速后按事件位置铺轨。转换后以实测时长复核公式。
3. 默认自然硬切，按剧情使用动作匹配、视线匹配、构图匹配、遮挡或声音桥接；关键台词前给进入时间，台词后保留反应，高潮后保留短暂释放。少量淡入淡出和叠化服从第 9 节时长规则，避免花哨转场。
4. 分离原视频音轨，只保留审核通过的现场音，去除重复旁白、冲突对白及突兀音乐，不把模型配乐与新 BGM 直接叠放。
5. 以旁白和对白合并总线驱动 BGM 的 ducking/sidechain，或用逐事件音量包络实现。起点可在说话区间降低 BGM 约 8–14 dB，并保留自然进出；先听再调整，不能只设固定音量就声称完成 ducking。声音冲突时优先级为关键对白/旁白→关键动作声→情绪音乐→装饰性环境声。
6. SFX 与环境声用于建立空间和动作因果；脚步、接触、门响、爆炸等落在真实可见事件点，并避开重要辅音和台词。淡入淡出消除接缝；检查静默、爆音、截断、重复、左右声道及 BGM 起落。可将全片约 −16 LUFS、真峰值不高于 −1 dBTP 作为网络视频制作起点，用户平台规格优先；参数只是目标，导出后必须实测。
7. 用户要字幕时，基于最终对齐文本生成统一字体、字号、安全边距，修正错字再烧录；不让模型在画面内生成文字。其他情况保持纯净画面。
8. 输出内部审片版本，最终 QC 后再标为成片。通常使用 H.264、yuv420p、AAC、MP4、faststart，实际编码依工具和交付要求调整，保存渲染命令或项目文件及日志。

不用 `-shortest` 或“取较短流”掩盖音画溢出；先使各轨有效结束点一致，再明确导出时长。全片解码和时长检查通过后，仍须观看最终合成版本。

## 12. Final QC 与交付

检查最终渲染文件，不只检查原素材。先全片解码/媒体信息检查，再完整观看和听审，针对所有镜头及切点记录时间码和发现：

| 类别 | 必查内容 |
| --- | --- |
| 故事 | 起因、发展、转折、高潮、结局、主题完整，无剧情断裂、遗漏、伪造重要史实或未标记演绎 |
| 角色 | 面孔、发型、年龄、身材、服装、配饰、武器一致，人物不混淆，变体按剧情生效 |
| 场景 | 时代、建筑、物件、空间、朝向、动作因果正确，无无因由跳变 |
| 表演 | 角色有明确行动意图、微反应与情绪落点；重要动作具备准备、发力、接触、反应和结束状态，不僵硬、不无因乱动 |
| 视觉 | 画风、光线逻辑统一，镜头运动有叙事动机，无明显 AI 畸形、额外人物、乱码、无意文字或水印 |
| 声音 | 旁白/台词逐字完整、读音正确、角色声音对应且固定，画外音归属正确，BGM 不遮声，无爆音或突兀接缝 |
| 时间轴 | 每个 Cue 的关键词在 Visual Evidence Window 中可见，动作/SFX 时点正确，对白说话者、可见口型和反应同步，首尾和切点无错位 |
| 技术 | 文件完整播放，排除无意黑场/静帧/丢帧，画幅帧率/音频规格正确，实测总时长与时间轴相差不超过一帧 |

抽帧可辅助检查脸和穿帮，不能代替完整动态检查。不能播放/听审时记录具体未验证项并标 `review_pending`，不声称通过完整 QC。

旁白画面错位、关键事实错误、角色混淆、台词缺失/错人/多人误对口型、动作物理顺序错误、主要声音身份改变、资源缺失或播放损坏为阻塞项：禁止输出为最终成片，先修复、重跑受影响同步检查并观看最终版本。轻微无关背景瑕疵等非阻塞项记录时间码，不隐瞒。

通过后保存 `final_qc.json`，绑定时间轴版本、资产版本、成片 SHA-256、导出参数、三次同步报告、最终检查证据和已知限制。所有必需生成项与阻塞检查完成才设 `DELIVERED`。

最终回复提供可播放/下载的成片、实测时长/分辨率/画幅、文案和时间轴、完整工程/素材清单、QC 报告链接；简述实测通过情况及已知限制。停在确认或阻塞时，写清已完成资产、未完成内容和下一项所需输入，不把中间片段当成成片。

## 13. 错误处理与恢复

| 问题 | 执行动作 |
| --- | --- |
| 超时、进程中断、任务未知 | 保存 unknown 及已知任务/节点 ID，查原进程或已有结果；查明未提交或失败前绝不重复 --run。unknown 任务的旧节点不得原地改参；提示词修改另建素材版本和节点，原任务与计费单独保留。无可查 ID 时保持未知并说明，不能重交试探 |
| 服务失败 | 保存错误、已知计费与失败项，只修对应项。按批准重试额度执行，否则展示新批次确认；不能假定失败免费 |
| 下载失败或结果 URL 过期 | 重取原任务结果或重下同一资产，不重新生成；校验文件、哈希及可解码性 |
| 角色/场景/空间/道具漂移 | 记 QC 失败，检查相应 Lock、参考图真实绑定和 Input/Output State，只将依赖该资产的下游置为失效 |
| 动作失败或表演僵硬 | 将动作改写为预备→发力→接触→反应→落点，补 Face/Eyes/Body/Timing 和反应者，减少同一时刻的主要动作；只返修失败 Clip |
| 台词漏错、错人或误对口型 | 锁定台词时间和说话者，强化口型排他与画外音，降低无关动作复杂度；不得为方便删除剧情台词 |
| 音色不稳、错读或漏字 | 核对真实 Voice ID/Reference 绑定和读音词典，修对应音频，重生成先确认，重做对齐和混音 |
| 素材不足、旁白溢出 | 按第 10 节调整切点、镜长、速度或重做局部，不截断重要内容或用黑场填时长 |
| 模型/工具不可用或不兼容 | 继续独立分析和工程整理，写清能力差距、替代和成本，等待确认替代或必要素材 |
| 配额不足或硬预算将超出 | 暂停未提交生成，保存已有资产，提出减镜、复用或改规格的具体改版，不自动切账号、充值或超预算 |
| 合成失败 | 查输入、路径、编码、时间戳、流映射、滤镜，复用素材修复重渲染，不重做所有 AI 生成 |
| 只批准部分 | 执行批准且依赖满足的项，其余待定，不因部分成功把整个阶段标完成 |
| 用户修改已通过内容 | 增版本、保留旧资产及记录，依赖传播失效、重算时长并更新受影响批准项 |

恢复后从第一个未通过依赖继续，不删除用户素材、旧结果或记录来“重置项目”。并行仅用于依赖通过、各自明确批准的独立项；Master Timeline 和状态由单个协调者串行合并，工具有会话或并发限制时遵守实际限制。
