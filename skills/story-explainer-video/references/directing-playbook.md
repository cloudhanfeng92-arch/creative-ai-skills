# 故事导演、动态表演与音画同步手册

本手册服务于 `story-explainer-video` 的故事解析、资产拆解、分镜导演、图生视频、配音与成片阶段。只读取当前阶段相关小节；不得用本手册绕过主技能的生成确认、费用、工具能力检查或事实核验。

## 1. 自动故事解析与解说生成

### 1.1 先建立故事真值层

把输入拆成三层并保存，后续改写不得混淆：

- `FACT`：用户明确给出的事实、经可靠来源核实的史实、原著明确情节。
- `INFERENCE`：为理解因果所作的合理推断，必须可回退。
- `DRAMATIZATION`：为了可视化而补写的过场、动作或对白；历史题材不得伪装成原话。

先列出人物、时间、地点、事件、因果、结局、主题与不可改动项。历史、文学、神话、民间与原创采用不同真值标准；历史要核实，文学优先原著，神话/民间注明采用版本，原创以用户设定为真值。

### 1.2 提取剧情发动机

故事不能只按“发生了什么”拆分，还要回答：

```text
主角想要什么？
谁或什么阻止他？
失败的代价是什么？
哪一次选择让局势不可逆？
高潮由哪个动作、决定或台词触发？
结局改变了谁的处境或认知？
观众最终应该理解或感受到什么？
```

建立 `Relationship_Arc` 和 `Power_Arc`：每个段落记录谁掌握主动权、谁试图压制谁、谁处于弱势、权力何时反转、谁的情绪首先变化。成语与寓言还要把“故事结局”与“寓意”分开，先让观众看懂因果，再点题。

### 1.3 形成四层脚本

按以下顺序自动生成，不能从梗概直接跳到生图提示词：

1. `Story_Bible`：真值层、人物关系、世界规则、结局、主题。
2. `Beat_Sheet`：钩子、建立、升级、转折、高潮、收束；每个 Beat 只承担一个主要叙事变化。
3. `Narration_Script`：完整可朗读解说，负责信息、因果和主题。
4. `Dialogue_Script`：仅在能推动行动、暴露关系或触发反转时加入；负责人物当下的欲望与冲突，不替旁白讲百科。

开场优先使用冲突结果、危险问题、反常画面或关键决定形成钩子，随后尽快补足理解所需信息。不能为了“爆款”虚构事实、提前泄露用户指定悬念或改变结局。

### 1.4 旁白写作与时长预算

- 先写完整通顺版本，再为目标时长删枝节；保留人物关系、因果链、转折、高潮和结局。
- 旁白要提供画面看不出的时间、背景、动机、因果或意义；不要逐字复述正在发生的可见动作。
- 每个 `Narration_Cue` 标注文本、语义中心、可见证据、预估时长、情绪、停顿、读音与绑定 Beat。
- 中文初稿可以每秒约 3–4 个可读汉字估算，但数字、人名、年代、停顿须按实际读法折算；正式音频生成后立即废止估算值。
- 旁白与对白默认错开。需要重叠时必须有明确导演理由，确保两者都可懂，并在混音中验证。

### 1.5 台词设计

每句对白至少记录：

```text
Dialogue_ID / 说话者 / 对谁说 / 完整文本
表层目的 / 潜台词 / 权力位置 / 情绪起点与落点
计划开始与结束 / 语速 / 停顿 / 重音 / 音量
画内或画外 / 其他角色的反应 / 是否要求口型同步
```

对白应口语化、可表演、符合时代、年龄、身份和当下处境。优先短句与不完整口语，避免每人都说完整说明句。关键台词后为反应和停顿留时间。历史题材的创作性对白标记 `DRAMATIZATION`，引文须核实出处。

## 2. 自动资产拆解与连续性锁

### 2.1 Asset Bible

完成 Beat Sheet 后自动生成资产清单，而不是等写提示词时临时补：

- `CHARACTER_LOCK`：身份、视觉年龄、脸型五官、肤色、发型、体型、服装、鞋、配饰、标志道具、气质、声音；按年龄/换装/伤势建立显式变体。
- `SCENE_LOCK`：时代、建筑、空间尺度、墙地顶、门窗、家具、前中后景、时间、天气、光源方向、色温、主色和主摄影方向。
- `SPATIAL_LOCK`：角色与关键物体的左右、前后、高低、朝向、视线、出入口和可移动范围。
- `PROP_LOCK`：材质、尺寸、数量、初始位置、持有者、状态变化和剧情用途。
- `STATE_LOCK`：每个镜头结束时的角色位置、朝向、表情、伤势、衣物、手中道具、门窗及环境状态，作为下镜输入。

每个资产使用唯一 ID，明确首次出现、复用镜头、变体生效区间和来源。台词提及但不出镜的人物进入 `Offscreen_Character_IDs`，不得因此生成额外人物。

### 2.2 四类视觉锚点职责

```text
角色四视图 = Identity Anchor，锁定人物身份
空场景参考图 = Environment Anchor，锁定空间与光线
道具参考图 = Prop Anchor，锁定关键物件
关键帧 = Composition Anchor，锁定某个生成段的起始构图和动作起点
```

不要让同一张图同时承担四种职责。空场景图默认不含主要人物，避免人物复制和动作锁死。已有参考图若只覆盖一种职责，仍需评估其他锚点是否缺失。

### 2.3 生成资产的最小充分原则

自动列出“已有、可复用、缺失、需要生成、不需要生成”五类：

- 贯穿多镜的重要角色缺少稳定身份图时，生成四视图。
- 同一场景跨镜复用或空间关系重要时，生成空场景图。
- 关键道具会被持握、交换、破坏或触发剧情时，生成道具图。
- 每个 Shot 都必须有画面设计，但不等于每个 Shot 都必须额外生成一张图片。
- 一个生成段默认使用一个动作起点关键帧；多人复杂站位、首镜构图关键或模型直出失败时再增加构图锚点。
- 模型若能稳定绑定角色、场景和道具多参考，可以直接生成；不能支持的参考方式不得只写在提示词中假装已绑定。

## 3. Shot、Sequence 与 Generation Clip

必须区分三层：

```text
Beat：剧情信息或权力关系的变化单位
Shot：摄影机连续观察单位
Generation Clip：一次视频模型调用的连续表演单位，可包含一个或多个 Shot
```

先按剧情拆 Beat，再按可视化需要拆 Shot，最后按模型能力和连续表演完整性组合 Generation Clip。不能把“一镜一条视频”当成固定规则，也不能为了少调用把多个地点和事件强塞入一条。

### 3.1 Generation Clip 分段规则

- 先保证完整台词、完整动作链、完整反应和情绪落点，再考虑模型时长。
- 模型支持多镜头硬切且身份稳定时，优先让一个 8–15 秒生成段容纳同场景、同一冲突单元的多个 Shot。
- 单镜复杂动作、身份容易漂移或模型不擅长内部切镜时，使用约 4–6 秒单镜段。
- 场景彻底变化、明显时间跳跃、人物阵容大变或复杂高潮可单独成段。
- 不在一句话中间、动作接触前后或情绪爆发中间切段。
- 每个生成段记录 `Input_State` 与 `Output_State`，后一段必须继承前一段状态。

### 3.2 切镜判断

每次切镜至少满足一项：新增关键信息、改变情绪强度、推进因果、展示必要反应、完成空间重定位。否则不切。

参考节奏：

| 段落类型 | 推荐镜头密度 | 导演重点 |
| --- | --- | --- |
| 环境建立/时代交代 | 1–3 镜 | 快速建立空间，不沉迷空镜 |
| 情节推进 | 2–5 镜 | 行动与因果清楚 |
| 对话/权力交锋 | 2–4 镜 | 主说者、对象、反应和停顿 |
| 冲突/高潮 | 3–7 镜 | 准备、爆发、接触、反应、落点 |
| 结局/寓意 | 1–3 镜 | 允许留白，让旁白完成意义 |

这是导演参考，不是硬数量。切镜密度要形成“积累 → 爆发/反转 → 短暂释放”的波形。

## 4. 电影化且灵动的画面设计

### 4.1 每镜必须有三种运动

1. `Primary Motion`：推动剧情的主体动作。
2. `Reaction Motion`：另一角色或环境对主动作的可见反应。
3. `Secondary Motion`：服装、发丝、烟尘、水面、树叶、群众、光影等符合现场条件的次级运动。

三者不必都剧烈，但必须有因果。不能靠无意义风吹、眨眼、随机推镜制造“灵动”。静止和长凝视可以使用，但必须服务压迫、等待、悲伤或点题。

### 4.2 表演四层模型

关键表演按四层描述：

- `Face`：眉、眼睑、鼻翼、嘴唇、下颌的具体变化。
- `Eyes`：看向谁、何时移开、回避或直视。
- `Body`：重心、肩、手、呼吸、前倾、后退、转身。
- `Timing`：微反应、停顿、积累、爆发、恢复的时间点。

不要只写“生气、悲伤、震惊、戏剧性”。把情绪翻译成可见、可拍、带先后顺序的行为，并给听者或对手安排反应。

### 4.3 动作因果链

重要动作按以下链条写，删去不适用项但不能颠倒物理因果：

```text
预备姿态 → 重心与发力 → 动作路径 → 接触/触发 → 对方或环境反应 → 余势 → 结束状态
```

同一时刻控制一个主要动作；复杂动作拆为连续阶段，不让多人同时执行互相冲突的高难动作。动作音必须落在接触或触发帧附近。

### 4.4 摄影机必须有动机

- 推近：揭示、逼迫、意识到某事。
- 拉远：失去、孤立、展示后果。
- 横移/跟拍：跟随行动或揭示空间关系。
- 环绕：权力转换、犹疑或角色关系变化。
- 手持微动：危险、混乱或主观紧张。
- 静止：压迫、庄严、等待、不可逆时刻。
- 遮挡、动作匹配、构图匹配：用于自然转场，不作为炫技。

每镜写起始机位、路径、速度、跟随对象、焦点变化和终止构图。镜头运动与主体动作不要无意义互相抵消；一镜通常只有一个主要运镜意图。

### 4.5 图生视频提示词最小结构

```text
Generation_Clip_ID / 全片区间 / 本地 0 秒至结束 / 对应 Beat、Shot、旁白和对白
真实参考绑定：角色、空场景、道具、关键帧的 Asset_ID、版本和用途
角色、场景、空间与状态锁；允许出镜者与仅被提及者
开场状态：构图、位置、朝向、视线、手中物、情绪、动作准备
逐时段动作：主体动作 + 表演四层 + 反应 + 次级运动 + 动作因果链
逐时段摄影：景别、机位、运动、焦点、切镜及切镜后的身份/空间继承
对白：说话人、逐字文本、语气、重音、时间、画内/画外、口型要求
声音：现场声、动作声、环境声；旁白/BGM 的后期处理说明
结束状态：用于下段继承的全部 STATE_LOCK
负向限制：身份/服装/道具/空间稳定，可信物理，无随机人物、随机切景、文字、字幕、UI、水印
```

## 5. 对白、口型与声音身份

- 当前时段只有指定说话角色开口；其他可见角色嘴巴闭合，以眼神、呼吸、手部和身体反应表演。
- 画外音必须标明 `off_screen`，当前画面角色不得误对口型。
- 说话者切换时留出自然停顿或反应，不把多句台词挤成连续机械播报。
- 模型支持正式音频驱动口型时，先生成并确认该句正式对白，再作为真实输入；否则采用侧后、背影、遮挡、反应镜头或后期口型方案。
- 同一角色全片绑定同一实际 Voice ID 或同一 Voice Reference；逻辑 ID 不能替代服务商真实输入。
- 生成视频自带不可控对白时，后期弃用冲突音轨；不可同时保留模型随机对白和正式配音。

## 6. Cue 级音画同步

### 6.1 Visual Evidence Window

每个 Narration Cue 至少定义一个 `Visual_Evidence_Window`：观众听到关键词时，画面必须出现能证明该句的人物、地点、动作、道具、结果或情绪反应。不能只检查整镜“主题相近”。

例如旁白说“他把信投入火中”，同步窗口必须覆盖信接近火焰、点燃或燃烧的可辨识阶段；只展示人物站在火旁不算通过。

### 6.2 四层同步检查

1. `Semantic Sync`：听到什么，画面就在证明什么。
2. `Action Sync`：动作动词与动作发生时点一致。
3. `Dialogue Sync`：说话人、口型、表情、反应与台词一致。
4. `Sound Sync`：脚步、撞击、门响、爆炸等落在可见事件点。

对白、旁白、动作和音乐有冲突时，清晰度优先级为：关键对白/旁白 → 关键动作声 → 情绪音乐 → 装饰性环境声。

### 6.3 正式配音与对齐

- 初版时间轴使用估算时长；视频可用区间确认后生成正式旁白与对白，除非口型模型要求正式对白作为前置输入。
- 配音按语义和呼吸分段，不逐镜机械切句；跨镜句保持一个音频事件。
- 用强制对齐或逐句听审获得真实词级/句级时间；仅按字数均分只能标 `estimated`。
- 正式音频超出可用画面时，依次尝试调整切点、重新绑定语义镜头、轻微视频变速、调整停顿或保调变速、最后才改写或重生成。
- 不截断词尾、重要动作或反应，不用黑场、循环静帧或过量慢动作填补。

## 7. 实际剪辑与最终验片

### 7.1 剪辑节奏

- 从 Master Timeline 编译 EDL，按 Shot 组织剪辑，不直接把生成文件顺序等同于成片顺序。
- 优先动作匹配、视线匹配、构图匹配、遮挡转场和声音桥接；默认自然硬切，少用无动机转场。
- 关键台词前给进入时间，台词后保留反应；高潮之后允许短暂释放，结尾留足主题落点。
- 只使用每个源片通过 QC 的可用区间，保存原片与 handles；变速后重新测量。

### 7.2 声音与混音

- 旁白和对白先建立清晰人声总线，再铺 BGM 和 SFX。
- BGM 服从全片情绪弧线，在人声期间做 ducking，不能持续同一响度。
- 环境声建立空间连续性；动作声准确落点；不要为了“丰富”给每个镜头堆满音效。
- 字幕只从最终对齐文本生成，跟随真实语音时间；模型画面内不生成字幕。

### 7.3 最终阻塞项

以下任一存在时不得标记成片完成：

- 故事因果、结局或历史关键事实错误。
- 角色身份、年龄、服装、空间、道具或状态无因由改变。
- 关键动作缺少准备、接触、反应或落点，或物理顺序错误。
- 对白错人、漏词、多人误对口型、画外音误开口。
- 旁白关键词出现时没有相应视觉证据，或声音落到下一段错误画面。
- BGM 遮住人声、音频截断、爆音、明显接缝、成片损坏或时长不符。

最终 QC 必须观看并听审渲染后的成片，按时间码记录问题；抽帧、脚本校验和媒体探测都不能替代完整观看。
