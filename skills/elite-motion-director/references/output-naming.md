# 成品统一按视频名称命名

## 唯一标题来源

读取本条 `motion.project.json` 的 `title`。用户提供正式片名时使用正式片名；只提供主题时，创作时自行提炼一个与内容一致的短标题，不因此增加询问或审批。禁止把大段提示词、英文工程slug、模型名或“未命名作品”当片名。

例如配置：
```json
{
  "title": "光的旅程",
  "output": "output",
  "outputRevision": null,
  "overwriteOutputs": false
}
```

这只是命名字段片段；实际配置还须有宽、高、帧率、时长和画面入口等现有字段。实际输出：
```text
output/
├── 光的旅程.mp4
├── 光的旅程.html
├── 光的旅程_封面.png
└── 光的旅程_源码.zip
    └── 光的旅程_源码/
        ├── motion.project.json
        ├── visual.js
        └── ...
```

ZIP里的目录不是嵌套ZIP；上图末级表示打开源码归档后看到的根目录。用户最终收到的是前四个成品文件。内部 `src/`、配置、渲染日志、输出清单等仍可使用稳定工程名，不把内部泛名文件当成正式交付。

## 名称清理与版本

`scripts/artifacts.mjs` 统一完成命名。保留中文和可用标点，不把标题翻译成英文、不自动加品牌或宣传词。先做Unicode NFC规范化，将路径/文件名非法的半角符号映射为相应全角符号；移除控制字符、整理空白和末尾点号，处理保留设备名，按UTF-8字节上限安全截短，避免目录穿越或切断Unicode字符。

可见HTML `<title>` 保留视频原始标题，文件名才做必要清理。例如“光/影: 为什么?”在文件系统里成为“光／影： 为什么？”，语义不变。禁用“final、motion、index、source”作为自动降级标题。

默认不附加版本和时间戳。同一项目更新原片可以复用已登记文件。确需保留多个版本时，在同一配置设置 `outputRevision:"v2"`，同时得到 `光的旅程_v2.mp4`、`光的旅程_v2.html`、`光的旅程_v2_封面.png`、`光的旅程_v2_源码.zip` 和同名源码根目录。

输出目录内的 `artifact-index.json` 只记录本项目文件归属，防止覆盖不属于本项目的同名文件。遇到冲突，保留旧文件，为整组选择一个未占用的版本后缀后重试；不要默默覆盖，也不要每个脚本分别挑新编号。`overwriteOutputs:true` 仅用于用户已允许覆盖的情况。

## 工程中的使用

`config()` 给所有脚本返回统一的 `c.names` 与 `c.files`：
```js
c.files.video       // output/视频名称.mp4
c.files.html        // output/视频名称.html
c.files.cover       // output/视频名称_封面.png
c.files.source      // output/视频名称_源码.zip
c.names.sourceRoot  // 视频名称_源码
```

`pack-html`、`verify`和`package-source`使用这些路径；内置工具实际可用的导出或项目已有兼容原生入口也应沿用同一组命名。旧`render.mjs`和外部浏览器入口已禁用，不是当前导出路径。`bundle-manifest.json`记录标题、整组文件名和配置摘要；标题或配置变化后先更新HTML包，不要只改链接或给旧内容换新片名。只有真实产物才能登记完成。

改名是轻量工程修改：更新title并重新打包、按受影响的步骤导出；无需重新策划或多轮样片，也不得为改名安装、启动外部浏览器。旧版本文件由用户决定是否删除。
