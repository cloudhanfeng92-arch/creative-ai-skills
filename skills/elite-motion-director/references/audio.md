# 默认无朗读，但有音乐与适配音效

## 声音策略

默认 `tts=false`、`music=procedural`、`sfx=procedural`。未明确要求配音时，绝不生成朗读音轨，不把旁白稿送入TTS，也不在HTML调用speechSynthesis。

用户提供音乐/已有歌声并要求使用：保留其声音，不生成新的朗读，不用默认合成曲替换。用户仅给歌词，没有要求演唱或朗读：歌词以动态文字显示，可有无声乐的合成BGM。用户要求静音：所有声音关闭，正式影片可合法无音轨。

## 先确定本片的声音语言

声音设计与视觉概念一起确定，不在画面做完后随手垫一段音乐。先判断本片要让观众理解什么、感到什么，以及画面的材质、运动性格、时代/文化语境和叙事视角，再选择音色组合、节奏或自由脉动、音域、和声张力、织体密度与空间感。BGM负责跨镜头的情绪与结构；音效负责具体事件的触感、因果和注意力，氛围层只在能建立空间时加入。

在已有`direction.md`中用几句写清“为什么这组声音属于这条片子”，以及应避免的错配；在现有分镜动作旁补必要cue，不新增独立审批表。风格词必须转为可实现的选择，如“柔和起音、稀疏中低音、短促事件声、逐渐展开的和声”，不能止于“高级、治愈、史诗”。题材不是固定曲风预设，同为金融主题，平静的机制解释和金融危机叙事需要不同声音。

以下是判断示例，不是自动套用的配乐包：

| 主题与对应画面 | 可以怎样设计声音 | 需要避免的错配 |
| --- | --- | --- |
| 情感沟通：两条线收紧、打结后逐渐松开 | 克制的柔和音色与留白；随张力增加织体或不协和程度，连接恢复时舒展；图形摩擦、拉伸采用一致的抽象触感 | 用胜利号角给一方“判赢”；不分语境地煽情；把每个字做成提示音 |
| 金融机制：付款标记保持不变，估值结构发生变化 | 用稳定的声音动机对应不变的付款，在估值变化处改变相关声部或空间关系；公式阅读段减密度 | 金币、收银声铺满全片；上涨永远庆祝、下跌永远恐吓；声效与被解释变量无关 |
| 八卦文化预告：爻线组合、自然意象、结构揭示 | 经主题判断选用克制的拨弦/钟磬质感、呼吸与疏密发展；组合落定时清楚点题，尺度揭示时打开声场，结尾归静 | 一律玄幻恐怖；廉价电子蜂鸣冒充真实古乐器；只因出现传统符号就套同一段“五声音阶”循环 |

## 配乐随叙事发展，音效随画面发生

用少量可辨认动机贯穿全片，让它随内容发展改变配器、音域、节奏重心、和声和密度；不是只调同一个循环的音量。开场建立声音身份，推理与阅读段给理解空间，揭示或高潮前有预备，结尾有完成感或符合预告片意图的悬念。音乐可有节拍，也可无固定拍点；转场可跨越乐句，不能为卡点牺牲文字阅读或真实因果时序。

每个重要cue在分镜中明确“对应对象/事件 → 叙事作用 → 起音/重音/衰减时间 → 音色与力度”。时间来自共享动画时间轴，最后写入`score.json`实际支持的事件字段；设计说明留在`direction.md`，不能添加脚本不会读取的字段后声称已经生效。碰撞声的瞬态跟随接触，揭示音的重音对准发现而非机械对齐镜头起点，运动声覆盖运动区间，余音可跨镜头但不能遮蔽下一条信息。动画时序改变时同步更新相关声音事件。

真实对象的音效要体现材质、重量、作用力、速度与远近，声像和空间变化与画面相符；不要让软布发出金属撞击或让细小接触产生无缘由的爆炸声。抽象文字、线条与图形可用设计音效，但需建立可辨认的声音关系，同类事件保持同一家族，强弱随动作变化。不是所有移动都有声音：只强调有意义的动作，避免每次转场都是whoosh、每次落点都是kick、每个字都响。

音画可以有明确目的的反差，例如表面轻快与逐步显露的紧张；需在方向说明中写清其作用，不能用“反差”掩盖不合主题的随意配曲。不要把非写实配乐或声音隐喻描述成真实环境录音。

## 混音也要服务画面重点

先确定当前段落的听觉主角，避免音乐重音、低频冲击与多个音效同时争抢注意力。BGM与SFX通过频段、音域、包络、音量或必要的短暂压低相互让位；信息密集或细小动作段减少密集高频、强瞬态与厚重低频。明确要求配音时给语音留空间，默认无配音不等于必须把声音铺满。

空间感、混响尾音与画面的尺度和情绪一致，不无意义地左右乱移或用长混响糊住连续事件。头尾包络和最终峰值检查防止点击、削波与突断；先解决音色、编排和主次关系，再做必要的增益处理，不把“一律调小”当成混音完成。

程序合成是创作方式，不保证旋律绝不与世界上任何作品相似；不得复制参考片旋律并声称原创。保留本条乐谱/事件与合成源码。

## 实现路径

优先使用Node JavaScript确定性DSP离线写WAV，不需要声卡或浏览器，也不是实时录系统声音。已有Web Audio实现若需网页运行，只允许Codex内置浏览器官方工具实际支持的能力，不启动独立浏览器；不能通过只读evaluate触发合成或假定支持导出AudioBuffer。缺少网页音频导出能力时使用既有Node合成流程或明确未完成。

包内`scripts/synth-audio.mjs`是可运行的事件合成器，支持正弦/三角/锯齿/方波、FM、噪声、kick、whoosh和短拨弦风格。它是音色原语而非通用自动作曲模板，也不保证能直接模拟任意乐器或材料。Codex需为本条编写`score.json`或按声音设计扩展DSP，不直接沿用测试事件；多层音色需实际合成并混入交付文件。无法实现所选声音时，调整为仍符合主题的可用声音语言并说明限制，不交付占位蜂鸣或只在文案中声称拥有某种配器。

输入示例见`examples/score.example.json`：`duration`、`sampleRate`、`seed`、`notes[]`和`sfx[]`。事件时间单位秒，音高用MIDI号或`freq`，`amp`为线性幅度，`pan`为[-1,1]。可选`sectionGain`用于段落密度外的增益变化，复杂编排应在事件表完成。

```sh
node /真实Skill路径/scripts/synth-audio.mjs score.json audio/mix.wav
ffmpeg -y -i audio/mix.wav -c:a aac -b:a 192k -ar 48000 audio/mix.m4a
```

有现成音乐或歌声时，先按用户要求剪裁/对齐，与JavaScript生成的SFX用FFmpeg混合。使用明确的延时和音量，不擅自变速歌曲、截断人声或重复其开头来凑时长。需要侧链压低或响度规范时依据实际轨道处理，不为每条强制新增复杂母带步骤。

## 同一条最终音轨

只生成一次最终`audio/mix.m4a`或项目声明的其他兼容音轨。MP4用该M4A音轨`-c:a copy`封装；HTML内嵌同一文件字节。改变音乐/音效后两者一起更新。不得HTML临时随机生成另一套音乐，也不得MP4有声而HTML只附源码不实际播放。

HTML以`audio.currentTime`作为有声播放的主时钟；暂停、拖动、重播与动画共用时间。静音影片用performance.now锚定绝对时间。播放需首次点击是浏览器的自动播放限制，不是配音缺失；不要关闭安全策略来绕过。

所有轨道预留头尾包络，防点击噪声、削波和结尾突断。可用峰值/实际音轨时长做技术检查，但不凭数值声称听感优秀。结合实际音画检查主题情绪、段落发展、cue时机、材质感及阅读留白，避免只听音轨或只看波形就宣布声画匹配。没有试听或同步音画观察能力则分别记录未检查范围，不凭空通过；检查并入既有一次轻量自检，不增加样片审核或另开外部播放器。
