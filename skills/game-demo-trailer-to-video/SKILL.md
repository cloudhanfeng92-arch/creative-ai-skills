# 游戏演示宣传片生成

将游戏名称、可选角色图、指定画风与游戏设定，转化为一段有剧情结构、接近真实游戏实机演示的宣传片。适配 3D、2D、像素、卡通、写实、国风、科幻等风格；全片默认 30–120 秒，除非用户另行指定。

## 输入与边界

收集或合理推断以下信息：游戏名称、世界观/核心玩法、目标时长、用户指定画风、角色图片(可选)、角色音色偏好(可选)、平台/画幅(默认横版 16:9)。先以用户指定画风为最高优先级；仅在未指定时推荐画风，并在进入出图前请用户确认。

只生成符合已定世界观与分镜用途的素材。不得用无关概念图凑数，不得把静态生图提示词当作图生视频提示词，也不得在未经确认时调用任何会消耗积分的图片、视频、配乐或配音生成能力。

默认推荐 7–20 个场景镜头；每条视频片段固定 5–15 秒；片段总时长应落在 30–120 秒。用户已有角色图时，把它作为角色外形锚点，除非用户要求，否则不重做角色。

**素材数量核算**：静态图总数 = 单图镜头数 × 1 + 首尾帧镜头数 × 2。不得为了省积分而省略尾帧，也不得靠复用其他镜头的图片来凑数——每张图有且仅服务于它所属的那一个镜头。

## 贯穿全流程的锁定项

在第一阶段输出并固定以下基准；其后所有静态图、视频提示词、旁白和剪辑建议均要遵守它。

- 游戏定位：类型、核心循环、镜头/操控视角、受众与情绪基调。
- 世界观：主题、时代/地点、阵营、冲突、关键场景与剧情钩子。
- 角色锚点：外貌、服装、武器/道具、姿态气质；用户图优先。
- **画风锁定（含截图真实性）**：画风类型、色彩倾向、渲染材质、光影规则、特效语言、镜头/UI语言。无论选定哪种美术风格(写实/卡通/像素/国风等)，所有场景关键帧都必须呈现为**该风格下的真实游戏截图**——如同玩家本人正在游玩该游戏时实机截取的画面：模拟游戏引擎实机渲染的取景、景深、镜头畸变与画面颗粒感，不是电影海报式构图、经过精修的概念原画或插画式滤镜。这一条与画风类型并列锁定，后续每张出图提示词都要显式包含。
- **UI 锁定（含真实性）**：HUD 信息层级、位置、图标/字体气质、留白，且必须对照该游戏类型(卡牌/开放世界/像素RPG/国风仙侠/经营模拟等)在市面上的真实UI范式来设计——如血条/技能栏/小地图/背包图标/对话框/任务提示框等元素要符合该品类玩家的认知习惯，不能是凭空设计的抽象界面。画面中如 UI 容易失真，建议后期叠加静态 UI 层，不能靠提示词强行修复。
- **战斗节奏与玩法多样性锁定**：全片战斗类镜头(含基础战斗、Boss 战、QTE/终结技，合并计数)总数不超过 3 幕。其余镜头须结合该游戏的实际玩法设计非战斗向的探索/互动/经营/解谜内容(例如仙侠类锻造炼器、经营类选择经营策略、卡牌类抽卡养成、解谜类机关互动等)，以真实同品类游戏的玩法为准；若游戏本身不含战斗玩法，则不强行加入战斗镜头，战斗数可为 0。
- 声音锁定：音乐方向、旁白音色、字幕字体。旁白音色优先使用用户指定的音色；若用户未指定，则按游戏画风/题材选择匹配的音色(如国风仙侠选沉稳古风男声或空灵女声、科幻选冷静机械感音色、卡通选活泼轻快音色)。全片音色与字体统一，除非剧情有明确的设计性变化。

每个场景均维护角色、场景与光影锚点。生成后续静态图时，以上一张获确认的场景图作为**风格参考**（仅用于保持角色/光影/画风一致，不代表该图会被复用进多个镜头）。

## 素材单次使用原则（全流程强制）

- 每一张静态图（含首帧、尾帧、角色参考图之外的场景图）从生成起就绑定唯一一个视频镜头，只在阶段4被引用一次。
- 禁止把某镜头的尾帧直接作为下一镜头的首帧来省一次出图——即便两镜衔接紧密，也要为下一镜头单独生成属于它自己的首帧（可以用上一镜尾帧做**风格参考**，但不能作为**视频输入帧**复用）。
- 角色参考图（阶段2开头单独生成的主角图）例外：它作为跨镜头的外形锚点参考，不直接作为任何镜头的首尾帧输入，因此不算"复用同一截图做视频"。
- 阶段2清点资产、阶段3列出提示词清单、阶段4逐条生成前，均需再次确认"这条视频对应的图片是否此前已被其他镜头用作过输入"，如有冲突需重新生成。

## 阶段 1：游戏解读、世界观与场景规划

1. 分析游戏名称与设定所暗示的题材、玩法和情绪；如名称存在歧义，说明采用的解释。用户指定画风与参考图覆盖你的推荐。
2. 构筑适合"可游玩演示"的世界观，而非泛泛电影设定：明确主角目标、可探索区域、敌人/对手、核心机制与一条由进入世界到高潮收束的剧情弧。
3. 输出以下内容，随后暂停等待确认，不生成素材：
   - 游戏定位与世界观摘要；
   - 画风锁定六维度（含"真实游戏截图风格"要求）与 UI 基准；
   - 角色锚点；
   - 7–20 个场景总览：场景编号、标题、功能、玩法/剧情推进、时长(5–15 秒)、推荐视频模式(单图或首尾帧)，并在总览末尾标注"战斗类镜头计数：X/3"，确认未超限；非战斗镜头需注明对应的具体玩法(NPC 对话/任务领取/锻造/经营决策/解谜等)。
   - **对每个首尾帧镜头，额外给出"转场目标"**：一句话说明该镜头要从什么起始画面变化到什么结束画面（例如"从地图界面关闭 → 技能面板展开"、"从蓄力起手姿态 → 大招释放瞬间的特效爆发"）。这个目标将直接决定阶段2尾帧图要画什么内容，必须在此处先锁定，不要留到阶段3才补。
4. 默认优先采用如下节奏，并按游戏类型裁剪；不可为了凑齐而生成无关镜头：登录主界面、召唤/选人界面、城镇或据点 NPC 对话、任务领取对话、副本或开放区域/高概念探索、任务/组队与战前准备、基础战斗、机制解谜或环境互动、Boss 战与大招高潮、QTE/终结技、胜利结算与品牌收尾。可省略不适用项，或以赛车、策略、解谜、模拟经营等等价玩法替换；不适合战斗玩法的题材(如纯经营、纯解谜、纯叙事类)应整段跳过战斗相关镜头，改为该品类的核心玩法展示。
5. **趣味性与真实互动设计**：城镇 NPC 对话、任务领取对话等镜头不要只是站立空镜，要设计出可信的互动细节——例如对话框弹出、NPC 头像/表情变化、任务图标弹出动画的静止瞬间、角色点头/挥手等肢体反馈，让画面读起来像玩家正在真实操作游戏，而不是摆拍插画。
6. **战斗节奏控制**：呼应"战斗节奏与玩法多样性锁定"，规划阶段就要检查战斗类镜头(基础战斗+Boss 战+QTE/终结技)合计是否超过 3 幕；若超过，优先压缩或合并战斗镜头，把富余的镜头数换成该游戏品类对应的非战斗玩法展示(如锻造装备、经营决策、解谜机关、社交培养等)，具体形式以该游戏实际或同类型真实游戏的玩法为准，不臆造与题材无关的玩法。
7. **首尾帧优先原则**：除非画面本身是静态氛围镜头（登录/菜单/城镇闲逛/纯探索空镜等更适合单图轻微动态），默认为所有涉及状态切换、动作推进、战斗升级、NPC 互动的镜头选择首尾帧模式，以获得更明确、更可控的视频效果。单图模式仅用于确实不需要首尾状态差异的镜头。

## 阶段 2：静态分镜图（GPT Image 2）

目标是生成可作为后续图生视频参考的主角图和场景关键帧，而非独立插画集。**每一张出图都必须是该游戏画风下的真实截图效果**，而非概念原画或宣传海报。

1. 先列出待生成资产及原因：主角参考图优先；然后按镜头顺序列出每个已规划镜头需要的图——单图镜头 1 张，首尾帧镜头 2 张(首帧 + 尾帧)。用户图片已覆盖的角色不重复生成。明确标注每张图专属于哪一个镜头，不与其他镜头共用。
2. 为每张图先输出独立的 GPT Image 2 提示词。提示词必须包含：
   - 画面用途/场景编号(及"首帧"或"尾帧"标注)；
   - 主体与角色锚点；
   - 具体环境与可交互玩法元素；
   - 统一的画风锁定，**并显式写明"真实游戏截图/实机渲染效果，非概念原画、非海报构图、非插画滤镜"**；
   - 光影、第三人称或对应游戏视角、**符合该游戏品类真实范式的 UI 布局**(血条/技能栏/小地图/对话框/任务提示等按该品类真实游戏的位置与样式描述，不用抽象或凭空设计的界面)；
   - NPC 对话/任务领取等互动镜头需额外描述具体互动细节(对话框内容形态、NPC 表情/姿态、任务图标状态等)，避免空镜站立；
   - "无水印、无无关文字"；除登录/菜单等界面镜头外，不要求模型生成可读文字。
   - **尾帧专属要求**：提示词需体现阶段1锁定的"转场目标"结束状态，并注明"以已确认的首帧为风格参考，保持同一角色、光影、UI 与镜头体系，仅呈现该镜头结束时的画面状态"。
3. 以批次展示"资产清单 + 提示词 + 数量/预计积分消耗"，明确询问确认。未确认不得生成。获确认后才使用 GPT Image 2，按顺序生成：先出首帧，获确认后再以该首帧为参考出对应尾帧，避免首尾帧风格漂移。将用户确认的上一镜作为后续镜头的风格参考(仅供参考，不是复用)。
4. 检查结果：
   - 角色脸、服装、武器、色彩、镜头视角、HUD 位置与光影是否一致；
   - **是否呈现真实游戏截图质感**（是否误画成海报/插画/概念图，是否有多余的装饰性构图元素）；
   - **UI 是否符合该游戏品类的真实范式**（血条/技能栏/小地图/对话框等是否像凭空设计的抽象界面，而非该品类玩家熟悉的样式）；
   - NPC 互动镜头是否呈现出可信的互动细节，而非站立空镜；
   - 首尾帧一对图是否共享同一角色/光影/UI 体系，尾帧内容是否准确对应转场目标；
   - 不合格时先说明差异与重做方案，再为重做请求新的积分确认。

## 阶段 3：逐幕图生视频提示词

为每个场景输出一条、且只输出一条与它的 5–15 秒时长严格对应的视频提示词。提示词与静态生图提示词独立；要引用该场景**已确认且专属于该镜头**的图片，明确采用单图模式或首尾帧模式。

使用 `references/video-prompt-patterns.md` 的模板与禁忌。遵守以下规则：

- 单图模式适用于登录界面、城镇闲逛、场景探索、静态氛围镜头。动态集中在轻推镜、轻微镜头呼吸、衣袂/树叶/云雾/粒子/水面等环境元素，构图和 UI 位置不变。
- 首尾帧模式适用于界面切换、区域转场、战前到开战、小怪到 Boss、蓄力到大招等——按阶段1的"首尾帧优先原则"，这应是大多数动作/剧情推进镜头的默认选择。首尾帧必须先保持同一角色与美术体系，再用缓慢运镜、光照渐变、粒子与姿态的循序变化过渡，衔接阶段1锁定的转场目标；不要要求剧烈形变。
- 战斗镜头可以提高技能特效与动作强度，但仍以稳定第三人称实机录屏为准，不使用剧烈抖动、无故旋转、快速随机切换或大幅改变角色样貌的描述。
- 叙事上按"钩子 → 探索/目标 → 玩法展示 → 危机升级 → 高潮 → 胜利/召唤行动"推进。Boss 战应是最长或视觉最强的一段。
- **每条提示词只引用该镜头自己的首帧/尾帧图**，不得引用其他镜头已使用过的图片作为输入。

按以下格式输出每幕：

```
场景 X｜标题｜固定时长 X 秒｜[单图/首尾帧]
参考图：[首帧图(专属)；尾帧图(专属，如有)；角色参考图]
转场目标(首尾帧镜头适用)：[与阶段1一致的起始→结束状态]
图生视频提示词：[不超过 150 个中文字符。依次包含：运镜指令 → 过渡/动作逻辑 → 环境动态 → 锁定约束 → 游戏视角、画质与画幅。]
```

写完全部提示词后，展示"镜头、参考图、时长、模式、提示词、预计视频积分"清单，并注明每张参考图的专属归属，等待用户确认或修改。不要在此阶段调用视频生成。

## 阶段 4：按确认生成视频

严格按场景顺序执行。每次实际调用前再次展示该条的参考图(并确认该图未被其他镜头使用过)、完整提示词、模式、时长、模型/分辨率和预计积分；获得明确确认后，才以对应的单图或首尾帧参考图模式生成该条 5–15 秒片段。若用户只确认部分场景，只生成那些场景。

视频结果要核验：角色一致性、UI 稳定性、运动与场景因果、首尾帧镜头是否准确从首帧过渡到尾帧的目标状态、时长、画幅、与相邻片段的衔接。失败重试或变更提示词同样是新的积分操作，必须先确认；重试时若需要新的参考图，也要重新生成专属图片，不得借用别的镜头素材。

## 阶段 5：旁白、配乐、字幕与剪辑合成

输出可直接交给剪辑工具的成片方案：

1. 给出按时间轴的剪辑顺序、每幕起止、转场方式和对应视频文件；总时长保持在目标范围。
2. **旁白采用整段连续脚本，而非逐幕分句**：撰写一段完整、流畅、有起承转合的解说词，通篇串联世界观、玩法亮点、战斗/探索推进与结尾的 IP/行动号召，读起来像一条完整的游戏 PV 解说，而不是镜头说明的堆砌。写作时要同步核算语速与全片总时长(30–120 秒)是否匹配——按中文解说约 4–5 字/秒估算整段字数，确保整段旁白播完的时长与视频总时长基本一致，不需要靠拉长静音或加速语速来凑时长。
3. **旁白与镜头的对应关系**：在整段脚本上标注出每一句/每一分句大致对应哪个场景编号，作为音频与画面对齐的依据；正式生成语音后，需要按各镜头的实际时长智能切分/对齐这条连续音频(而非分别生成多段音频再拼接)，确保每一幕画面播放时，观众听到的正是描述该幕内容的那部分解说，衔接处不生硬。若切分后个别镜头出现旁白空白或超时，优先通过后续镜头的语速/停顿微调解决，避免破坏整段解说的连贯语气。
4. **旁白音色优先级**：优先使用用户明确指定的音色；用户未指定时，按已锁定的画风/题材从候选音色中选择匹配项(如国风仙侠选沉稳古风男声或空灵女声、科幻选冷静机械感音色、卡通选活泼轻快音色、写实战争题材选低沉有力音色)，并在展示脚本时一并说明选择理由，供用户确认或更换。
5. 字幕按整段旁白的分句切分，与音频对齐后逐句同步；可为阅读稍作精简；推荐一种符合题材的统一字体与安全区位置，全片不得频繁换字形。古风可用书法感衬线字，科幻可用几何无衬线，像素风可用清晰像素字体。
6. 给出配乐提示词：乐器、节奏、情绪曲线、进出点与需要避让旁白的片段。音乐应随探索、玩法展示、战斗、胜利递进，不压过解说，且不得抢过战斗镜头数量受限后新增的非战斗玩法段落的氛围感。
7. 若用户要实际生成 AI 配乐、旁白或最终合成，先展示完整旁白脚本(含镜头对应标注)、音色设定(及选择理由)、配乐设定和预计积分，并逐项等待确认；确认后才调用相应能力，生成整段旁白音频并按镜头时长智能切分对齐。将音频、字幕和片段按时间轴精确对齐后，合成为**一条完整、叙事连贯、有趣好看的游戏 PV 视频**，作为最终交付物——而不是若干互不关联的独立片段。

## 输出顺序与确认门

始终按以下顺序交付，每个需要积分的阶段在调用前暂停：

1. 【世界观与场景总览(含首尾帧镜头的转场目标)】→ 等待创意确认。
2. 【静态图资产清单(标注每张图专属镜头)与 GPT Image 2 提示词(含截图真实性要求)】→ 展示数量/积分并等待出图确认。
3. 【逐幕图生视频提示词】→ 展示专属参考图、模式、时长/积分并等待视频确认。
4. 【逐幕视频】→ 每条调用前再次确认参考图未被复用；仅生成已确认的条目。
5. 【整段旁白脚本(含镜头对应标注与音色选择)、字幕、配乐与剪辑时间轴】→ 若需 AI 音频或合成，展示积分并等待确认。

## 交付前自检

- 全片时长为 30–120 秒(除非用户另定)，每个视频片段均为 5–15 秒。
- 用户指定画风与角色图优先，全部镜头共享角色、光影、UI 和镜头语言锚点。
- **所有场景关键帧均呈现真实游戏截图质感，无一张被画成概念原画、海报或插画。**
- **每张静态图仅被一个视频镜头使用一次；没有跨镜头复用的首尾帧或场景图。**
- **首尾帧镜头优先于单图镜头；尾帧内容准确对应阶段1锁定的转场目标，且与首帧共享同一风格/角色/光影体系。**
- 每个静态图服务于已规划镜头；没有无关图、重复角色图或不必要的尾帧。
- 每条图生视频提示词仅覆盖自己的固定时长，参考图、模式与转场用途匹配。
- 单图镜头避免大动作；首尾帧镜头避免结构性变形；战斗镜头仍像真实游戏录屏。
- **战斗类镜头(基础战斗+Boss战+QTE/终结技)合计不超过 3 幕；不适合战斗玩法的题材允许为 0。**
- **非战斗镜头包含符合该游戏品类的真实玩法展示(NPC对话、任务领取、锻造/经营决策/解谜等)，且互动细节可信，不是空镜站立。**
- **所有画面的 UI 均符合对应游戏品类的真实范式，不是凭空设计的抽象界面。**
- **旁白为一段完整连续的解说脚本，整体时长与全片总时长匹配，并已按镜头智能切分/对齐音频；音色优先采用用户指定，其次按题材匹配。**
- 字幕、配乐和剪辑顺序均覆盖完整片段；字幕字体全片统一且符合题材。
- **最终交付物是一条完整、叙事连贯、有趣好看的游戏 PV，而非互不关联的独立片段拼接。**
- 每一次会消耗积分的图片、视频、配音、配乐或重试调用均已先向用户展示内容与消耗并取得确认。
