# 代码动态视频

先设计观众要看懂的变化、关键构图与动作，再用代码实现。默认交付 MP4、可直接打开播放的 HTML、一张代码绘制的 PNG 封面和可编辑源码。连续完成脚本、动画、需要的声音与导出，不在阶段之间要求审核或确认。用户明确只要某种格式、先看方案或只要代码时，遵循该范围。

## 默认选择

- 16:9、1920×1080、30 fps、H.264 / yuv420p；用户指定优先。简单动态图形未指定时长时按 15 秒；讲解片按文字阅读、画面叙事与音乐节奏安排时长。
- **默认不朗读、不生成 TTS。** 用户提供的「旁白」「解说文案」「字幕」「歌词」默认是屏幕文字内容，由代码制作成字幕或动态排版；这些词本身不代表配音要求。只有明确要求配音、口播、朗读或念出来时才生成语音。背景音乐、音效及用户选用歌曲中已有的歌声仍可保留，不额外朗读歌词。
- **默认用 JavaScript 合成原创 BGM 与适配音效。** 按主题、叙事立场、文化语境与画面风格设计配器、旋律、和声、节奏及段落发展；BGM组织情绪与结构，音效匹配具体动作、材质、重量、速度与远近。推理与阅读段保留听觉空间，不通用套曲，也不让所有转场使用同一种音效。用户要求静音或指定现成音轨时优先遵循，不额外叠加冲突配乐。通过离线合成输出真实音频，MP4 与 HTML 共用最终混音，不依赖前台浏览器实时播放或录音。
- **自动选择实现方式。** 以 JavaScript 驱动动画，根据主题的可见过程、排版、空间与效果需求选择 Canvas 2D、WebGL、SVG / DOM 或 Three.js，可按需混合；用户指定方案优先，已有适用工程继续复用。开发可保持模块结构，最终另提供可双击离线播放的单文件 HTML；复杂项目按 [HTML 交付](references/html-delivery.md) 打包。
- **网页预览按需，浏览器流程只用 Codex 内置浏览器的官方工具。** 网页预览不是 MP4 必需步骤，真实视觉检查可由成片关键帧和连续片段完成。先读取当前工具的实际能力，再决定可用的预览、操作或导出路径；不假定它支持任意 JavaScript、`seek(t)`、批量采帧、下载或离线验收。禁止 Google Chrome、Chrome for Testing、独立 Chromium 及其他外部浏览器，不通过改浏览器路径、个人 profile/CDP、Playwright/Puppeteer/Remotion 间接启动、系统 `open` 或桌面录屏绕行。
- **按实际能力导出。** 内置浏览器可完成的步骤用其官方工具；不能完成视频导出时，才复用项目已有且确认不启动浏览器的原生后台入口，例如 Node 原生 Canvas/Skia/SVG 离屏输出帧后交给 FFmpeg。没有兼容入口就保留源码与已有产物，说明 MP4 未完成；不声称任意 DOM/WebGL 都能无改写迁移。默认单任务、保守编码线程；内置浏览器和原生路径都可能使用本机 CPU/GPU，不保证更省资源。
- 非关键细节自行补全，复用现有工具与依赖。只对无法推断且实质影响结果的关键缺失信息提问。

## 按主题自动选型

- **JavaScript + Canvas 2D**：适合二维图解、手绘质感、几何变化、动态图表与常规粒子动画。
- **JavaScript + SVG / DOM**：适合文字排版、路径变形、精细标注与公式，可作为 Canvas / WebGL 的文字层。
- **JavaScript + WebGL**：适合大量粒子、连续场、光影、噪声形变和着色器效果；二维视觉也可选择，不以“有三维”作为前提。
- **JavaScript + Three.js（WebGL）**：适合真实三维结构、空间关系、材质灯光与相机运动，复用现有库处理场景。

按实际要呈现的画面选择，不按“科技／历史”等题材标签机械分配。兼顾视觉表现、现有依赖、导出耗时与离线打包，选能充分实现设计且复杂度合理的方式；必要时混合 WebGL 主视觉与清晰文字层。在简短分镜中说明选择及理由后直接制作，不额外要求确认，也不先实现多套方案做比较。

## 连续制作流程

1. **先设计，再写代码。** 用一句可见变化表达本片的视觉论点，选定从当前内容生长出的母题。简短分镜记录「镜号 / 文案或歌词 / 文字表现 / 主视觉与动作节拍 / 预计时长」；动作栏写明关键姿态、观众追踪的主动作、主次响应、阅读落点与下一镜承接物。简单动态图形可记在代码草图中，不需提交长方案。新创作在确定分镜时先读 [动态设计](references/motion-design-standard.md) 的构图、运动和产品判断；内容推进、宏观节奏和母题回收按需读 [分镜与节奏](references/storyboard-standard.md)。局部修改只读相关部分，沿用已成立的设计。科学数据、公式和年份核对关键事实并留简短出处；无法核实的内容改为有依据的保守表述。
2. **安排文字与声音时间轴。** 将文案拆为可读的句子、词组或歌词段，记录 start/end；按阅读停留与镜头安排进出场，在同一分镜中简记声音方向、段落变化和关键音效 cue：对应哪个对象/事件、起音与重音何时发生、怎样衰减及为什么采用这种音色，让原创音乐与画面共同定节奏。声音设计前读 [原创声音与可选配音](references/narration-and-audio.md)，直接落实为实际乐谱与事件，不只写“高级、震撼”等形容词，也不新增审批表；无需先做配音。用户明确要求朗读时，才生成 TTS 并以实际音频时长回填；歌曲或现成录音使用已有音轨时间。
3. **用代码实现画面与文字。** 按选定方式绘制主视觉，字幕、关键词和歌词可用 Canvas / SVG / DOM 叠加，或作为 WebGL 纹理参与场景；样式与主题统一，HTML 图层接入 `window.seek(t)`，可行时与视频入口共用纯绘制与时间轴逻辑，不只交付字幕文件；页面接口存在不代表内置浏览器工具能直接调用。需要动态文字或歌词表现时读 [文字动效](references/text-motion.md)。同一时刻应得到同一画面，异步定位返回 Promise；字体、素材与渲染初始化就绪后设置 `window.__VIDEO_READY__ = true`。设计坐标可用 1280×720，最终按 1920×1080 视口实际绘制。
4. **合成声音并后台导出。** 用 JavaScript 离线合成原创配乐与音效，保存最终混音并接入配置；用户指定音源或静音时按其要求处理，方法见 [原创声音与可选配音](references/narration-and-audio.md)。制作中按需抽取代表帧修正缺字、遮挡、溢出和空白；静帧只用于构图排错，不代表动作已通过检查。先确认内置浏览器官方工具实际支持的导出方式；不支持时才使用已存在、无浏览器的原生后台入口，按配置时间轴输出帧，交由 FFmpeg 编码并混入最终音轨。不运行旧浏览器采帧脚本，不默认增加样片轮次；缺少可用入口时保留 HTML、源码和音轨并说明视频缺口。
5. **输出 HTML 与代码封面，轻量检查后交付。** 将同一动画与时间轴打包为可直接打开的 HTML，保留动态文字、声音和轻量播放控件，见 [HTML 交付](references/html-delivery.md)。复用本片视觉元素，用代码设计并单帧导出 `output/cover.png`，默认与视频同画幅、同分辨率；标题与核心图形形成独立封面构图，绘制源码随项目保留，见 [代码封面](references/cover-delivery.md)。正式 MP4 做一次元数据与轻量观感检查：后台采样关键动作及交界的短时连续片段，实际观察注意力、动势、阅读落点；有实际音画观察能力时同时核对配乐的主题与情绪、音效材质、事件时机及听觉主次，未能试听或同步观察的部分如实说明；不接管桌面或打开前台播放器。HTML 网页预览与播放验证按需，仅在内置浏览器官方工具实际支持其访问与操作时进行；不自动在系统浏览器打开，无法验证则注明未验证。封面确认易读、无意外遮挡或裁切，然后按实际完成状态交付。检查方法见 [轻量检查](references/qa-checklist.md)。

## 设计判断

- **不添加无关文字。** MP4、HTML 与封面只展示服务于主题和叙事的文字，不出现“原创科普／代码绘制”“AI 制作”、技术栈、制作说明、自我宣传标签、调试信息或模板占位文字。署名、品牌水印等仅在用户明确要求时加入。
- **让变化承担含义。** 关键动作让观众看到关系或功能如何改变，文字补充命名与解释。若替换主题名和文案后，核心动作仍几乎无需变化，说明仍是通用模板，应重写核心可见变化。
- **构图在运动中成立。** 设计关键姿态之间的注意力路径、主次响应和物性；转场承接同一对象、动势或观看关系。阅读停留从信息完整就位后算起，不能由入场和转场代替。
- **按用途判断表达。** 产品在关键变化中仍可辨识，功能通过有依据的操作与结果可见；动态图形让语义与字形协作，歌词按乐句、呼吸和重点组织。方法按需读 [动态设计](references/motion-design-standard.md) 与 [文字动效](references/text-motion.md)，不照搬参考的具体场面。
- 同一概念保持颜色和形象一致，数据与公式不为造型失真。关键文字有足够对比和阅读停留，不用模糊、过小字号或持续抖动换取效果。设计直接落实到分镜和代码，不增加风格评分、审美报告或确认关卡。

## 工具入口

新项目可复制 [assets/project-template/](assets/project-template/) 到工作区独立目录。模板只复用时间轴、播放器和渲染接口；按主题重写示例场景的构图与动作，移除占位文案和演示角标，不能只替换标题或配色便当作成品。脚本路径相对于本 Skill，实际调用使用绝对路径：

```bash
node /path/to/code-motion-video/scripts/validate-video.mjs --project /absolute/project --video /absolute/project/output/final.mp4
node /path/to/code-motion-video/scripts/export-html.mjs --project /absolute/project --out /absolute/project/output/作品名.html
```

旧 `render-preview.mjs` / `render-video.mjs` 依赖外部浏览器，已由 `openRenderer` 拒绝，不作为可用入口，不尝试改路径或关闭保护。上列 `validate-video.mjs` / `export-html.mjs` 是不启动浏览器的校验与打包工具，不能据此宣称 MP4 已生成。HTML 导出适用于基础模板，复杂依赖按 [HTML 交付](references/html-delivery.md) 打包。导出前按 [渲染说明](references/rendering-standard.md) 核对实际工具能力与入口底层，不以“后台”或“无头”判断合规。

## 控制耗时

- 不要求逐镜审查、边界穷举、确定性审计、全片解码、量化评分、单独验收报告或逐阶段确认。
- 有可用导出路径时默认一次完整渲染，合并做一次轻量规格与观感检查；HTML 仅按内置浏览器的实际能力检查。观感检查复用成片短段，不另做默认样片或逐镜审批。HTML 打包无需再次编码视频。修改后只检查受影响部分，不重复整套流程。
- 遇到时间轴故障时，用允许的实际入口比较同一时间的输出；不要调用旧渲染器的 `--check-determinism`。视频解码故障或严格质检可用校验器的 `--full-decode`，按 [排错提示](references/qa-checklist.md) 定位受影响部分。
- 浏览器声音不会自动写入 MP4，默认配乐与音效应合成为本地音轨并实际混流；按配置检查音轨存在，发现具体声音问题时再局部处理。无口播不是缺陷，也不等于可以漏掉配乐；生成失败或指定音源不可用时如实说明，不为字幕制作额外寻找或调用 TTS。

交付可点击的 MP4、作品名.html、`output/cover.png` 与源码路径，源码包含封面的绘制实现；简短说明规格、HTML 的打开方式和仍存在的问题。HTML 应是实际运行代码动画的成品，不是静态截图、只嵌入 MP4 的播放器或需要开发服务器的预览入口；不把预览、渲染中或失败文件称为成片。
