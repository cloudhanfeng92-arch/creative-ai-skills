# JavaScript 原创音乐、音效与可选配音

制作音乐、音效或接入音轨时读取。默认用 JavaScript 合成原创 BGM 和适配音效；用户要求静音、指定音乐或已有歌曲时遵循其选择。文案里出现「旁白」「字幕」「歌词」不视为 TTS 请求，文字实现见 [文字动效](text-motion.md)。

## 声音风格从主题和画面中确定

先明确本片要表达什么、以什么立场和情绪表达，再结合产品/对象的材质、时代文化语境、视觉运动性格与段落结构选择音色、音域、节奏密度、和声张力和空间感。题材名称不能直接决定曲风：精密仪器的机制展示与游戏化产品发布可以同属科技，却不应自动用同一套电子脉冲。

在现有分镜或简短设计记录中写清声音方向与理由，不另建确认流程。把“高级、温暖、震撼”落实为具体选择，如柔和起音、稀疏中音、颗粒质感或逐步展开的和声。BGM负责跨镜头的情绪与结构，音效负责具体事件的触感、因果与注意力；环境氛围只在能建立空间时加入。音画反差可以有意设计，但要有明确叙事目的，不能将不合内容的随意垫乐解释成“反差”。

| 画面用途 | 声音如何与画面共同表达 | 避免 |
| --- | --- | --- |
| 产品与机械结构 | 按材质、重量与操作方式设计接触、卡合、驱动的声音；动作启动、接触和结果各有因果顺序，配乐在功能落点让位 | 按下按钮就无缘由地爆炸；用激昂音乐掩盖操作机制不清 |
| 动态文字、歌词 | 原歌声与乐句居前，字效沿呼吸和语义重点发展；额外音效只帮助有意义的动作，用户歌曲保留其情绪 | 每个字都滴答；加入冲突BGM；为卡字效随意拉伸、截断原歌声 |
| 抽象图形与图解 | 为同类关系建立一致的声音动机，随聚合、分离、尺度或张力变化而变奏；解释落点明确，阅读段减少事件 | 每镜同一whoosh；只调通用循环的音量；声像与物体位置无关 |

示例用于判断，不是固定曲风或每片必选的配器清单。

## 配乐发展与逐事件音效

- 用少量原创动机随叙事发展，改变配器、音域、节奏重心、和声与密度，不把短循环机械铺满全片。开场建立声音身份，动作段推动，理解段留白，高潮有预备和落点，结尾有完整收束或符合内容的悬念；不要为音乐强行加快读字或改变真实因果时序。
- 在现有分镜中将重要cue关联到“对象/事件—叙事作用—起音/重音/衰减—音色/力度/空间”。碰撞瞬态跟随接触，揭示重音对应发现，运动声覆盖实际运动，余音可跨镜头但不能遮住下一条信息。不是所有移动都有声音，切镜也不必落在鼓点上。
- 真实对象考虑材质、重量、力度、速度与远近，声音位置和空间变化要有画面依据。抽象图形采用一致的声音隐喻，同类事件保持音色家族、强弱随动作变化；不能把设计音效描述为真实录音或测量结果。
- 音符、配乐段落与音效使用共享时间轴，按项目实际实现的格式记录时间、时长、音高、增益与声像；`time/duration/type/pitch/gain/pan`仅是字段示意，不是所有工具通用的接口。说明写在分镜，事件必须转成合成器真正读取的字段；时序修改同步更新相关cue，随机噪声固定seed。
- 用JavaScript振荡器、噪声、包络、滤波、调制、延迟与混响等实现所选声音。原语不足时按需扩展DSP或选择仍符合主题的可用声音语言；不得拿默认蜂鸣、whoosh、kick冒充任何所需乐器与材质，也不只在说明里宣称存在未合成的配器。

## 混音中的听觉主次

每段明确听觉主角：情绪段由音乐推进，关键动作可由音效突出，歌词/朗读段让人声清晰；无朗读不意味着必须铺满声音。BGM、音效通过音域、频段、包络、声像、音量或必要的短暂压低相互让位，避免音乐重音、低频冲击和多种音效同时抢焦点。阅读与公式段减少密集高频、强瞬态和厚重低频。

空间感和混响尾音服从画面尺度与情绪，不无意义地左右乱移或用长尾音糊住连续事件。先处理音色、编排和主次，再做增益与峰值控制；“全部调小”不等于混音完成。用户提供的歌曲、已有歌声与静音要求始终优先。

## 离线合成并输出音轨

1. 复用当前环境，优先用 **Node.js 直接计算 PCM 并编码 WAV**。已有 Web Audio 音频图仅在 Codex 内置浏览器官方工具实际支持运行和取回结果，或现有不启动浏览器的音频实现兼容时使用 `OfflineAudioContext`；不能假定内置工具支持任意 JavaScript 或文件导出。不为音频启动外部 Chrome/Chromium、Playwright/Puppeteer，不实时录音，也不要求两种方式都实现。
2. 从统一 cue 表一次安排音符和音效，用采样时间计算状态；Web Audio 离线渲染使用其时间调度，不依赖 `setTimeout` 或实际等待整段片长。`OfflineAudioContext` 返回的音频缓冲仍需编码成 WAV 等真实文件，不能只保存发声代码。
3. 给声音起落加短包络以避免点击声，混音留出余量；延迟、混响和淡出尾音计入片尾设计，避免截断或为了尾音无意延长视频。合成采样率可统一为 48 kHz，最终混音保存为 `audio/mix.wav`，合成代码与 cue 表保留在源码中；分轨仅在有编辑需求时附送。
4. 将最终混音写入 `video.config.json` 的 `audio`，由现有 FFmpeg 流程合成到 MP4；HTML 优先内嵌或打包同一音轨，确保音色、段落与音效时序一致。不能只在页面里发声而交付无声 MP4，也不默认外找音乐素材或调用生成音乐服务。
5. `seek(t)` 负责画面定位，不在每次逐帧调用时重新启动振荡器或重复触发音效。HTML 声音由用户点击启用，随后随播放、暂停、重播与拖动定位；渲染模式关闭实时声音启动，音频由离线结果单独混流。

默认完成一次声音合成与混音，沿用成片元数据检查确认音轨存在；在既有轻量检查中，按实际音画观察能力核对主题情绪、段落发展、音效材质、cue时机与阅读留白。音轨存在、波形正常或仅听音乐都不能证明声画匹配；未试听或未同步观察时明确对应范围。具体异常再局部排查，不新增逐音符审核、多轮试听确认或前台播放器。实际未输出或混入音轨时，不声称声音交付完成。

## 明确要求朗读时才生成 TTS

1. 仅在用户明确要求配音、口播、朗读或念出来时执行本节。将需要朗读的文案拆为短句，每句为一个 cue，记录 id、text、audio；字幕含义与对应内容一致。
2. 使用可用 TTS 工具和已有音色配置；无指定时选择沉稳、略慢的中文男声。整片保持同一声音和语速。
3. 生成每句本地音频，接口允许时可适度并发，保持 cue 顺序，文本未改的音频直接复用。
4. 用 ffprobe 读取每句实际秒数：

```bash
ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 /absolute/cue-001.wav
```

5. 累加实测时长与自然停顿得到 start/end，句间可留约 0.15–0.35 秒，TTS 已有足够停顿则无需再加。留少量结尾停留，将总时长写回配置；不用字数替代实测，不为凑时长裁句尾。
6. 动画与字幕读取同一 cue 表；转场可交叠画面，人声按顺序播放。修改一句时只重生该句并更新后续时间。

cue 示例，时间应来自实测：

```json
{"id":"001","text":"为什么打碎的杯子不会自己复原？","audio":"audio/001.wav","start":0,"end":3.42,"pauseAfter":0.2}
```

## 音轨与 FFmpeg 混音

- 默认使用 JavaScript 合成的原创背景音乐和适配音效。用户指定歌曲时保留已有歌声，不另铺冲突 BGM，也不额外生成逐句念歌词的 TTS。
- 有明确要求的配音时，统一逐句音频采样率和声道，按 cue 起点拼接或延迟叠加；停顿与字幕时间轴一致。
- 配音可用 `loudnorm=I=-16:TP=-1.5:LRA=11`，以约 -16 LUFS 为目标；这不是给所有音乐强制套用的指标。默认单遍即可，要求精确响度时再使用双遍模式。
- 仅在需要衬托口播时，可先将配乐衰减约 18–24 dB 并按需压低；无口播或音乐主导的视频按曲风与听感设置音量。配乐按需补齐片长并淡入淡出，混音峰值必要时用 limiter 控制；歌词同步的歌曲不要随意拉伸、裁断或循环。
- 保存最终混音如 `audio/mix.wav`，在 `video.config.json` 的 `audio` 中引用，由实际可用的 FFmpeg 编码/混流入口接入画面，不调用旧浏览器渲染器，避免无必要地二次编码视频。
- -16 LUFS 是旁白目标，不是整条混音的保证实测值；单遍处理不声称通过精确响度认证。

默认合成声音失败或用户指定音源不可用时，如实说明具体缺口；无配音请求时无需查找 TTS，也不存在配音缺失。不要把浏览器能发声当成 MP4 已有声音。

交付 HTML 时接入与 MP4 相同的最终混音，首次声音由用户点击开启，播放、暂停、重播和拖动与画面同步。默认仍不朗读文案。确有交互需求时可另保留实时合成，但必须共用配乐与音效数据，并为 MP4 离线输出音频；普通播放不额外维护两套声音实现。
