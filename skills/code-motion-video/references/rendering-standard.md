# 配置、内置浏览器与后台导出

只在配置工程、依赖、音轨或排错时读取。网页预览按需，不是 MP4 必需步骤；真实视觉检查可用成片关键帧和连续片段完成。需要浏览器的流程优先且只允许 Codex 内置浏览器的官方工具；是否可以导出，以当前工具实际提供的能力为准。FFmpeg 编码已有像素帧，不能直接渲染 HTML。

## 浏览器边界与能力判断

- 先阅读本会话内置浏览器官方工具的能力说明，再使用实际支持的访问、预览、操作、截图或导出功能。不能因页面实现了 `seek(t)` 就假定工具能调用任意 JavaScript、逐帧定位、批量采帧、下载文件或完成离线验收。
- 禁止启动 Google Chrome、Chrome for Testing、独立 Chromium 或其他外部浏览器，无头也不例外。不修改浏览器路径/环境变量，不连接个人 profile/CDP，不使用 Playwright、Puppeteer、Remotion 等间接启动浏览器，不通过系统 `open`、前台播放器或桌面录屏绕行。
- 旧 `render-preview.mjs` / `render-video.mjs` 依赖外部浏览器，已由 `openRenderer` 直接拒绝；不要执行、改路径重试或关闭保护。现存浏览器二进制或历史成功记录都不构成本次可用入口。
- 内置工具能完成的步骤按其能力执行。若它不能完成视频导出，才复用项目**已有且经核对不启动浏览器**的原生后台入口，如 Node 原生 Canvas/Skia/SVG 输出像素帧，再用 FFmpeg 编码和混音。没有兼容入口则保留 HTML、源码、音轨和已有产物，说明 MP4 未完成，不声称已经切换或渲染成功。

## 配置

项目的 `video.config.json`：

```json
{
  "entry": "index.html",
  "width": 1920,
  "height": 1080,
  "fps": 30,
  "duration": 15,
  "audio": null
}
```

入口与本地最终混音路径相对于项目目录，宽高为正偶数。默认按文字与画面时间轴设置 `duration`；明确要求配音并完成生成，或使用已有歌曲、录音时，再按实际音轨安排同步。成片目标为 `output/final.mp4`。可用导出入口和打包后的 HTML 使用同一规格；不要假设历史渲染器的命令行参数适用于其他入口。

## 时间线与共同画面逻辑

- HTML 保留 `window.seek(t)`，按秒更新全部图层，异步定位返回 Promise；资源、字体和初始化完成后设置 `window.__VIDEO_READY__ = true`。这些是作品接口，不是内置浏览器工具的能力承诺。
- 所有画面状态由时间与固定输入决定，随机效果固定 seed；累积粒子或物理模拟使用解析状态、固定步长或预计算结果，不能依赖真实等待。HTML 播放、拖动和可用视频入口保持同一内容与时间轴。
- WebGL / Three.js 在更新相机、时间与场景后显式绘制，纹理、字体、着色器与初始化先就绪。历史 `window.__VIDEO_RENDER_CONFIG__` / `?render=1` 可保留为兼容接口，不能据此调用已禁用的外部浏览器渲染器。
- 已有原生逐帧入口按 `t = frame / fps` 取状态，总帧数为 `round(duration * fps)`，末帧时间为 `(总帧数 - 1) / fps`。需要改规格时同步配置，避免 HTML 与 MP4 分歧。

## 内置能力不足时的现有原生入口

先检查项目真实的启动命令、依赖和底层实现，确认没有间接启动浏览器；“后台”“无头”“离屏”这些名称不能证明符合约束。优先共用已有纯绘制与时间轴逻辑，由项目实际可用的 Node 原生 Canvas/Skia/SVG 或其他原生实现输出帧，FFmpeg 编码 H.264 / yuv420p 并混入最终音轨。

这些原生库不视为预装，也不保证任意 DOM、CSS、WebGL、着色器或字体行为无需改写就兼容。复杂效果只在现有允许路径确实支持时实现；保留核心设计，必要时局部适配，不另搭通用渲染引擎或自动安装整套框架。没有适用入口时如实保留未完成状态，继续完成可用的源码、HTML 打包和音轨部分。

扩展库、纹理、模型与字体按 [HTML 交付](html-delivery.md) 处理；HTML 可以保留浏览器代码，不为迁就尚不存在的原生入口删掉视觉设计。基础 HTML 打包器也不是通用网站或原生视频导出器。

## 不启动浏览器的现有命令

复用已可用的 Node.js 与 PATH 中的 FFmpeg/ffprobe；不安装浏览器或浏览器自动化包。将路径替换为实际绝对路径：

```bash
node /path/to/skill/scripts/validate-video.mjs --project /absolute/project --video /absolute/project/output/final.mp4
node /path/to/skill/scripts/export-html.mjs --project /absolute/project --out /absolute/project/output/作品名.html
```

- `validate-video.mjs` 只校验实际存在的视频，默认读取元数据，有元数据帧数时一并核对，缺失时保留未知；具体解码故障或严格检查才加 `--full-decode`。校验命令不生成视频。
- `export-html.mjs` 内联基础模板的脚本、配置和配置音轨，不启动浏览器、不重新编码视频，也不证明运行或离线播放已验证。扩展项目按 [HTML 交付](html-delivery.md) 使用已有打包方式。
- 静帧用允许且实际可用的内置截图/导出能力，或已有原生入口输出；也可从现有视频用 FFmpeg 抽取。正式导出后结合关键动作和交界的短时连续输出检查，不额外制作默认样片。
- 核对输出归属后再更新本项目文件；保留其他项目或未知归属的同名文件。不要将失败文件或历史产物当成本次成片。

## 性能、声音与真实交付状态

默认单任务，原生输出与 FFmpeg 使用保守编码线程，不同时启动多个重负载导出。性能取决于画面复杂度、分辨率与实际实现；内置浏览器也使用本机资源，原生路径不保证更省 CPU/GPU、零卡顿或快于实时。不要通过违规浏览器或桌面录屏追求提速。

声音按 [声音与可选配音](narration-and-audio.md) 输出真实本地最终混音，并由可用 FFmpeg 流程混入 MP4；`audio: null` 只用于用户要求静音。页面能发声不代表视频已有音轨。

HTML 继续交付可运行的动画源码，不自动在系统浏览器打开。运行、控件或断网行为仅在内置官方工具实际支持时验证；能力缺失则明确“未验证”。分别报告 MP4、HTML、封面、音轨和观感检查的实际状态，不增加审批关卡，也不把完成其中一项写成整组完成。
