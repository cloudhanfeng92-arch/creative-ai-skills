# 联网研究与证据安全替换

当输入不足以支撑某个槽位时，使用本流程自动完成设计。目标不是从互联网“补齐”一个商品，而是区分三件事：精确 SKU 事实、当前品类现实、可原创的视觉表达。

## 研究顺序

### 1. 精确 SKU 身份搜索

使用输入中已经确认的身份锚点组合查询：

- 品牌 + 完整品名。
- 品牌 + 品名 + 口味/型号。
- 品牌 + 品名 + 净含量/包装规格。
- 可读条码、企业名或许可证号只在原图清楚时使用。

优先打开品牌官网、生产商官网、品牌官方旗舰店、平台认证的品牌页面、政府或监管数据库。搜索摘要只能用于发现页面，不能直接成为证据。

把网页事实记为 `verified_web` 前必须满足：

1. 至少两个身份锚点与当前商品一致，其中必须包含品牌或生产主体、完整品名；有口味/规格时也必须一致。
2. 页面展示的包装版本没有与用户图片明显冲突；发生新旧包装、规格或配方冲突时，以用户当前素材为准并放弃该网页事实。
3. 来源是品牌/生产商官方、官方旗舰店、监管或其他可追溯权威来源。第三方店铺、聚合页、百科、UGC 和搜索摘要不够。
4. 记录有效的 HTTP(S) 直接 URL、页面标题、来源层级、信息主体、访问日期、匹配锚点、证据摘录或页面位置和允许用途；搜索结果页、无效文本和同页追踪链接不算来源。
5. 配料、比例、保质期、产地、工艺参数、认证、营养与功效等高风险字段，必须由用户提供/清晰包装标签直接确认，或由两个同版本精确 SKU 的权威来源交叉确认；否则只能内部记录，不能进入文字或视觉。净含量等正面可见字段以清晰用户包装为优先。

禁止把同品牌不同口味、同品类竞品、相似包装或旧版商品的信息合并到当前 SKU。

### 2. 当前品类与消费情境研究

搜索最近的目标品类页面、品牌案例、平台分类页、视觉趋势和消费决策研究。提炼：

- 当前常见但不过度同质化的色彩、灯光、镜头距离、材质与留白。
- 消费者在该品类下需要看到的证据：食品状态、份量尺度、开合方式、使用场景、可见纹理或包装细节。
- 常见食用时刻和非地域化场景；只有确定是安全、合理的场景时才可转为“搭配建议/食用灵感”。
- 用户指定目标平台时，查询该平台最新的尺寸、文字、白底图、促销和主图限制；未指定时只总结通用电商设计和合规原则。

这些结果一律标为 `category_research`，只能控制策略、场景、道具、版式和文字语气。不得据此写当前商品的原料、比例、产地、工艺、认证、营养、功效、规格或排名；视觉中也不能摆出某种原料、工厂、地域地标或证书来暗示这些事实。

网络参考图默认标为 `STYLE_ONLY`。只总结抽象模式并创作新的构图，不下载、临摹或拼贴竞品图片、包装、Logo、摄影作品和详情页版式。

### 3. 法规与平台规则

食品广告中的性能、功能、产地、用途、质量、成分、有效期限和引用数据必须准确、可验证；食品广告不得虚假或涉及疾病预防治疗。运行时应核对最新版本和目标平台规则，而不是把本文件当作永不过期的法律清单。

可作为研究入口的权威资料：

- 国家市场监督管理总局《中华人民共和国广告法》：https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_5474cf75173c45d6a0379730fb4e8d97.html
- 国家市场监督管理总局《中华人民共和国食品安全法》：https://www.samr.gov.cn/spxts/gzdt/art/2023/art_a54cbedacfd44ff5bd2b40504ea98649.html
- 国家市场监督管理总局《互联网广告管理办法》：https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_d93a579afd45413e8576e4623fab348f.html
- Google Merchant Center 商品图片要求示例：https://support.google.com/merchants/answer/6324350
- Baymard 关于场景尺度图的商品页研究：https://baymard.com/blog/in-scale-product-images

平台规则具有时效性。用户指定平台时必须查询该平台的官方帮助中心或规则中心并记录访问日期；没有指定平台时沿用用户要求的 1:1 与 3:4，同时至少使用一条监管机构或官方平台规则来源核对通用电商合规，但不擅自套用某个平台的专属文字禁限规则。UGC、普通品类页和品牌商品页不能充当平台规则来源。

## 研究记录

为每次任务保存研究摘要和 `research_sources`：

```yaml
research_status: completed | web_unavailable | user_forbade_web
exact_sku_status: verified | no_exact_sku_source | conflict_rejected | not_needed
platform_scope: generic_ecommerce | "用户指定的平台名称"
research_queries:
  - "品牌 完整品名 规格"
research_sources: []
```

`research_status: completed` 表示已完成本任务所需的精确 SKU、品类现实，以及适用的平台或通用电商规则检索，并不等于精确 SKU 已核验；两者必须分别记录。品类研究至少覆盖 `visual_strategy`，并覆盖 `scene_context` 或 `consumer_motivation` 之一，只有字体资料不能算完成。没有精确商品来源时使用 `no_exact_sku_source`，发现页面与用户素材冲突并弃用时使用 `conflict_rejected`。只有用户明确禁止联网时才使用 `user_forbade_web`。用户没有指定平台时使用 `platform_scope: generic_ecommerce`，不得因此询问用户、猜平台或套用某平台专属禁限规则。

每个来源记录为：

```yaml
- id: WEB_01
  url: "https://..."
  title: "页面标题"
  source_tier: official_brand | official_store | regulator | platform_rule | peer_reviewed | category_page | editorial | ugc
  source_authority: "规范到品牌所有者、生产主体或监管主体；精确 SKU 来源必填"
  retrieved_at: "YYYY-MM-DD"
  exact_sku_match: true
  identity_anchors: [brand, product_name, net_weight]
  evidence_excerpt: "只保留必要的短摘录或字段位置"
  allowed_uses: [specs, usage_copy]
  disallowed_uses: [ingredient_claim, origin_claim]
```

品类资料应把 `exact_sku_match` 设为 `false`，`allowed_uses` 只能包含 `visual_strategy`、`scene_context`、`typography`、`platform_compliance` 或 `consumer_motivation`。用于视觉、场景或消费动机的来源应是品牌/官方店案例、同行评审研究、品类页、编辑资料或 UGC；纯监管法规或平台规则只负责合规，不能单独冒充品类视觉研究。

高风险网页事实所称“两份独立来源”必须同时满足：不同规范化 URL、不同 `source_authority`。`source_authority` 写底层信息主体，不写发布渠道；例如“某品牌”与“某品牌官方旗舰店”仍是同一主体。同一网页的片段锚点、追踪参数（包括常见点击 ID）、默认端口、镜像链接、品牌官网与同品牌运营店铺不能拆成两份独立证据。

## 自动替换决策

缺资料时按照“最靠近原消费者问题、最少新增事实”的原则选择替代职责：

| 原槽位 | 有精确证据 | 无精确证据时的完成设计 | 禁止暗示 |
|---|---|---|---|
| 05 原料优势 | 真实原料英雄图 + 已确认优势 | 可见形态信任、包装开合、份量尺度或场景价值 | 未确认原料、农场、产区、精选、配比 |
| 07 核心差异 | 已确认差异事实 + 微距证据 | 可见结构证据、使用价值或选择理由 | 比竞品更好、领先、排名、虚假对照 |
| 09 多角度 | 真实多角度/结构参考 | 正面主视图 + 真实瓶盖/封口/材质/标签局部 | 伪背标、伪侧标、360°、不存在结构 |
| 10 制作工艺 | 已确认工艺时间线 | 使用过程、食用灵感或从包装到上桌 | 古法、手工、发酵时长、设备与参数 |
| 11 规格参数 | 完整已确认字段网格 | 商品信息速览：只列已确认字段，辅以包装形态、数量、尺度和使用场景 | 空字段、问号、同类常见值、伪法定标签 |

替换后的图片必须使用真实标题，例如“可见颗粒与油润光泽”“包装细节一览”“食用灵感”“商品信息速览”，不得仍写“原料优势”“制作工艺”“多角度”来误导。

### 低证据输入的证据预算

只有一张正面包装与一张盛盘图时，先为槽位分配互不重复的证据轴；下表是优先仲裁，不是要求虚构相机未拍到的内容：

| 槽位 | 优先证据轴 | 与相邻槽位的区别 |
|---|---|---|
| 01 | 整盘/整杯英雄视图、光线与构图钩子 | 负责停留，不做 04 的局部证据 |
| 02 | 真实包装 + 食品外观参考 | 只确认身份与形态；无 `portion_yield_confirmed` 时不暗示一包装满一盘 |
| 03 | 一个具体食用时刻或搭配关系 | 回答“何时/怎么享用”，不是泛生活氛围 |
| 04 | 已覆盖的表面、颗粒、稠度、附着或整体状态 | 负责近距离感官证据，不重复 01 整盘构图 |
| 05 | 尚未占用的整体形态、包装开合、可见尺度或便利价值 | 负责可信购买理由，不复用 04 同一微距 |
| 07 | 尚未占用的结构证据、包装细节或信息对照布局 | 负责解释选择理由，不复用 05 主证据 |
| 08 | 完整生活氛围与情绪代入 | 与 03 的具体食用任务区分 |
| 10 | 非参数化食用灵感片段或真实使用动作序列 | 与 03/08 区分为过程阅读；无官方说明时不得编号为操作步骤 |

规划阶段建立 `evidence_budget`，至少记录 `asset_id`、`evidence_axis`、`evidence_keys`、`shot_delta` 和与相邻槽位的区分。若两个资产的 `evidence_keys + shot_delta` 相同，必须先重构其中一个；不能靠换背景色、角落标题或裁切大小冒充不同内容。

## 文案资格

将每条最终文案标为：

- `product_fact`：来自 `confirmed` 或 `verified_web`。
- `visible_description`：只描述画面直接可见内容。
- `sensory_creative`：克制的感官或情绪表达，与食品类型和画面相符，不是检测结论。
- `serving_inspiration`：明确为建议/灵感，不冒充包装说明或唯一正确吃法。
- `category_context`：只用于内部策略，不直接写成商品属性。

如果一句话同时包含多个层级，按风险最高的部分校验。数字、比例、产地、工艺、认证、营养、功效和特定人群只能来自 `product_fact`。

## 无网或搜不到精确 SKU

- 不询问、不停工、不输出缺资料页。
- 使用输入中的 `confirmed` 和 `observable`，再用非事实性的品类场景与设计规律完成成图。
- 槽位采用 `evidence_safe_substitution`；只有包装/食品身份本身无法确认、但仍需表现该主体时才采用 `concept_render`。
- 清单记录研究失败原因，但不要把内部缺口文字放进用户可见成图。
