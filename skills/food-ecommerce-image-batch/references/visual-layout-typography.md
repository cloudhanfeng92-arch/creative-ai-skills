# 视觉主角、详情版式与字体系统

这份文件解决三个常见问题：包装重复贴满整套、详情图只有摄影没有电商设计、标题字形与产品定位不一致。先确定每张图的转化职责，再决定是否需要包装；不要反过来为了放包装而牺牲画面。

## 视觉主角与包装出现决策

`产品图`需要拆成两类理解：

- **包装母版**：瓶、罐、袋、盒等带品牌标签的商品包装。
- **食品实物**：开封后的内容物、盛盘状态、断面、蘸取、冲泡或烹调结果。

用户要求“产品不要出现在每张图”时，通常优先减少包装母版的重复；食品实物只在承担食欲、口感或使用证据时出现，也不能把同一盛盘母图抠出来贴满整套。场景、原料证据、工艺证据或规格布局可以成为独立主角，不必为“统一”硬塞产品。每个资产必须记录：

```yaml
visual_lead: food | package | scene | evidence | layout
supporting_subjects: [package, food, ingredient, hand, tableware]
package_presence: required | optional | omit
package_visible: true | false
package_presence_reason: "为什么本图需要或不需要包装"
package_variant: outer | inner | none
package_scale_role: hero | anchor | secondary | none
integration_plan: "透视、落地面、光向、色温、阴影、反射、景深、颗粒、遮挡"
```

默认决策如下；平台、用户要求或证据安全替换可以覆盖，但必须记录原因。自动替换后以真实 `delivered_role` 重算包装出现状态；例如包装开合证据可把 `05/07` 改为 `optional`，从包装到上桌动作可把 `10` 改为 `optional`，但不得与 `09` 重复同一包装画面。所有 `optional` 在生成前必须用 `package_visible` 落实为出现或省略：

| ID | 默认包装状态 | 视觉主角 | 决策理由 |
|---|---|---|---|
| 00 | `required` | package | 白底图负责确认商品身份 |
| 01 | `optional` | food | 点击首图优先用食品英雄镜头制造食欲；只有首图必须强化品牌识别时，才把包装作为次级锚点 |
| 02 | `required` | package | 负责说明实际收到什么；食品写入 `supporting_subjects`，可展示外包装与真实食品，或在有 `PACK_INNER` 依据时展示内包装特写 |
| 03 | `omit` | scene | 场景代入优先，避免包装破坏生活感；只有真实使用动作需要包装参与时才改为 `optional` |
| 04 | `omit` | evidence | 微距质感或断面负责证明口感，包装通常无助于证据 |
| 05 | `omit` | evidence | 已确认原料或配方证据做主角，包装通常省略 |
| 06 | `optional` | food | 首屏需要品牌锚点时可小比例出现，否则用食品与核心价值建立视觉记忆；文字布局不是第二主角 |
| 07 | `omit` | evidence | 差异证据优先，不重复包装 |
| 08 | `omit` | scene | 沉浸式食用场景优先 |
| 09 | `required` | package | 本槽位专门证明真实包装外观和结构 |
| 10 | `omit` | evidence | 已确认工艺或使用步骤优先 |
| 11 | `optional` | layout | 参数表是主角；仅在需要识别 SKU 时放小型白底包装锚点 |

不得为了满足一个机械数量配额而放包装。整套至少通过 `00`、`02` 和 `09` 建立稳定商品身份；其他槽位是否出现包装只由转化职责决定，最终 `package_visible: true` 的槽位不得超过 6 张。只有真实参考支持时，`02` 或 `09` 才可用内包装特写替代又一次外包装正面。同一包装母版不得在多个画面中以相同角度、大小、位置和阴影反复出现。

### 产品自然融合检查

当包装或食品实物以抠图/确定性合成方式进入场景时，成图必须同时满足：

- 产品尺寸符合餐具、手部、桌面和食品的尺度关系。
- 竖直线、水平线和消失点与承托平面一致，不像正面截图或盛盘图贴在斜桌面上。
- 主光方向、色温、明暗对比和环境反射与场景一致。
- 产品底部有可信接触阴影或反射，不悬浮、无白边、无硬切蒙版边缘。
- 景深、锐度、噪点和颗粒与所在空间一致；远处包装不能比焦点主体更锐利。
- 前后景遮挡合理；允许道具形成轻微自然遮挡，但不得遮住需要识别的品牌或品名。
- 包装作为 `anchor` 或 `secondary` 时面积和对比度明显低于本图视觉主角。

若无法自然融合且该槽位不是 `required`，把产品合成改为 `omit`。若包装槽位为 `required`，保留背景和构图，重新做确定性合成与阴影匹配，不让模型自由重绘标签。

## 五张主图的文字任务

五张 `qa_pass` 主图都必须在最终像素中包含两层精确中文：

1. **主标题**：4–10 个汉字，必要时最多 12 个；快速传达一个利益或购买理由。
2. **解释性卖点描述**：8–24 个汉字；说明利益如何被当前画面证明，不能只是换一种说法重复标题。

可选增加一个 2–8 字的事实标签，但只有存在 `confirmed` 或身份严格匹配的 `verified_web` 依据时才使用。五张图的文案任务应有明显差异：

| ID | 主标题任务 | 描述任务 |
|---|---|---|
| 01 | 让用户产生食欲并停留 | 描述眼前可见的香气、质感或食用满足感 |
| 02 | 说清真实形态或到手内容 | 描述开封、盛盘、颗粒、大小或包装与实物关系 |
| 03 | 给出明确食用时刻或搭配利益 | 描述怎么吃、何时吃或搭配后带来的便利与体验 |
| 04 | 提出口感结论 | 指向断面、表面、蘸取、流动等可见质感证据 |
| 05 | 给出可信购买理由 | 有原料证据时解释优势；没有时自动改成可见形态、包装结构、份量尺度或使用价值，并使用与替代职责一致的标题 |

禁止五张都用“好吃停不下来”“美味看得见”一类可互换空话。先写利益，再寻找相符的视觉证据；如果事实不足，收敛文案，不用夸张词补空缺。

## 六个 3:4 电商详情模块

详情图必须是独立的完成信息模块，不是“照片 + 左上角一句话”。每个 `qa_pass` 模块至少包括 4–18 个有效中英文/数字字符的清晰标题、不少于 8 个有效字符的解释层和视觉证据；符号或表情不计有效字数。需要数据时增加事实层。正文全部使用确定性排版。资料不足时自动更换内容职责和标题，仍交付完整模块；禁止待补、不可发布或空白占位页。

### 06 首屏核心价值：品牌主视觉模块

- 采用全幅英雄食品或大面积核心场景，建立第一眼价值。
- 信息层级：可选眉题 → 强标题 → 一句利益说明；只保留一个核心主张。
- 包装只有在承担 SKU 识别时作为锚点出现，不能与食品英雄争主角。
- 推荐版式：上文下图、左文右景或中央留白式 KV，禁止信息堆满。

### 07 核心差异：证据编辑模块

- 用一张微距主证据，或“主证据 + 1–2 个局部放大”解释为什么不同。
- 信息层级：差异标题 → 利益解释 → 已确认事实/视觉证据注释。
- 推荐版式：杂志式分栏、不对称切片、局部放大窗；不使用成排空洞图标。
- 没有已确认差异事实时，自动改成“可见结构证据”或“选择理由”：用表面、形态、包装细节、尺度或有依据的使用价值完成模块，不用比较级、排名或空口号。

### 08 场景氛围：沉浸式使用模块

- 以完整食用时刻、手部互动或桌面关系让用户代入。
- 信息层级：场景标题 → 一句使用或搭配描述；文字融入墙面、桌面或光影留白。
- 推荐版式：全幅场景 + 半透明低干扰文字区，或上下景别递进；默认不放包装。

### 09 多角度外观：真实结构模块

- 只能使用真实参考支持的角度、封口、瓶盖、窗口、标签局部和尺寸关系。
- 信息层级：外观标题 → 角度/结构说明 → 必要的细节注释。
- 推荐版式：一个主视图 + 两个真实局部，使用严格网格和统一比例；不得生成不存在的背标。
- 只有一个正面角度时，自动把用户可见标题改为“包装细节一览”，用正面主视图加瓶盖、封口、窗口、标签或材质的真实裁切完成设计；不要出现“多角度”“背面”或“360°”。

### 10 工艺制作：过程叙事模块

- 有证据时展示确认工艺；没有时自动改为“使用过程”“食用灵感”或“从包装到上桌”，不编工厂、设备、古法、手作、时间或温度。
- 信息层级：真实工艺或替代标题 → 一句价值解释 → 2–4 个确认步骤、可见动作或非参数化场景片段。只有资产证据键中存在 `confirmed` 或合规 `verified_web` 的 `serving_method`、`process` 或 `process_parameter` 事实时才写入 `steps`；仅有品类研究时字段必须命名为 `inspiration_panels`，不编号、不暗示唯一顺序。
- 推荐版式：纵向时间线、连续动作切片或大图配步骤带；步骤短而可扫读。

### 11 规格参数：购买决策模块

- 字段完整时使用精确网格排入已确认字段；字段较少时改题为“商品信息速览”或“下单确认”，不保留空字段、空标签或问号。文字与数字绝不交给生图模型。
- 信息层级：规格/信息标题 → 已确认字段 → 包装形态、数量、尺度、开合方式或有依据的场景说明；标签和值必须一一对应。
- 推荐版式：浅底卡片网格或左右双栏，留足行距；小型包装只可作为识别锚点。

### 自动替换的视觉完整性

- 替换不是删掉一页或把缺失状态放大，而是换一个仍能回答消费者问题的证据主角。
- 替换页继续沿用该套栅格、字体、品牌色和装饰语汇，并达到与标准页相同的图片完成度。
- 用户可见标题必须说出真实交付内容；文件名可以为兼容性保留原槽位名称。
- `category_research` 只可决定镜头、色彩、餐具、非地域化场景和排版，不得画出未经确认的具体原料、农场、地域地标、工厂或认证物件。

### 详情页共同版式约束

- 四边安全边距约为画面短边的 5–8%；核心信息不贴边。
- 建立 2–3 个文字层级：展示标题、解释文字、必要事实；同屏不超过一个主标题。
- 视觉内容通常应占画面主体，文字服务于阅读，不把画面切成 PPT 式大色块。
- 六张共享栅格、品牌色、字体组合和装饰语汇，但至少使用三种不同内容结构，不能复制同一角落模板。
- 使用高对比但克制的文字区；不得遮住包装、食品纹理、手部动作或证据细节。
- 以约 25% 缩略图检查标题和主视觉，再以原尺寸检查正文、边距和像素质量。

## 字体与产品定位

先判断产品的消费定位，再选一套字体系统。不要只因为“食品”就默认粗黑字，也不要在一套图中混用多种艺术字。

| 产品定位 | 展示标题方向 | 辅助文字 | 适合的版式语气 |
|---|---|---|---|
| 地方风味、传统手艺、酱料、老字号 | 克制的楷体或有笔触感的手写标题 | 清晰现代黑体 | 温润、有手作感，少量印章色或短笔触 |
| 现代便捷、即食、早餐、功能场景 | 粗而清爽的现代黑体 | 常规黑体 | 直接、高效、留白明确，短色条或信息标签 |
| 高端、精选、礼赠、洁净感 | 宋体或编辑感衬线标题 | 轻中等字重黑体 | 雅致、克制、细线和大留白 |
| 家庭、温暖、轻松零食 | 可读性优先的圆润手写或圆体标题 | 常规黑体 | 亲和、有温度，圆角标签或柔和下划线 |

同一套最多使用一种展示字形和一种辅助字形；装饰只选短下划线、印章色标签、细分隔线、浅色底托中的 1–2 种。禁止厚重多层描边、伪立体字、文字扭曲、发光字和一页多种艺术字。字体气质必须服务于产品定位，不能压过食品摄影。

在 macOS 使用 `scripts/render_text_overlay.py` 时，以 `--type-style modern-bold`、`craft-brush`、`premium-serif` 或 `warm-handwritten` 固定套系字体方向；只有确认目标字体已安装时才用 `--font-family` 覆盖。主图始终传入 `--headline`、`--subline` 与 `--require-subline`；详情模块可再用 `--kicker` 与 `--proof` 建立多层信息，但复杂网格仍优先使用 HTML/SVG 模板。若单行内容不适合所选安全区，缩短文案或改用居中布局，不得用过小字号强塞。
