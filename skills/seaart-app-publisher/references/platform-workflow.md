## 通道与能力发现

先发现当前工具，再执行。2026-09-12 本地 `seaart --help` 提供 account、models、parse、task、text2image、image_edit、text2video、image2video、reference2video 等，没有应用创建/发布/参赛命令。不能虚构 `seaart app create` 或私有 HTTP 接口。

需要素材 CLI 时，读取已安装 `$seaartai` 的实际路径及以下实时帮助，不硬编码用户名：

```bash
command -v seaart
seaart --help
seaart models list
seaart models params <从列表获得的实际model_id>
```

`<…>` 是说明占位，不可直接执行。找不到 CLI 时可走官方界面。不要复用未经核验的模型 ID、参数枚举或价格；CLI 与浏览器登录也未必是同一账号。不要导出 Cookie/凭证拼接请求。

浏览器按当前工具文档操作，每次变化后读取新状态；优先语义控件，必要时截图。上传使用实际文件选择机制，不把本地路径粘在普通文本字段当成上传完成。

## App Agent

1. 打开 App Builder，查看现有项目，复用匹配草稿；新应用才创建项目。
2. 提交具体搭建 brief，明确输入槽、固定提示、模型约束、输出与交互。
3. 等待生成，记录编辑 URL/ID。未提交输入或静态示例不算完成。
4. 检查 Preview 的输入数量、角色、选项和结果区。
5. 检查 App Details/Workflow 的真实生成节点、提示、上传连接、最终输出，排除固定样例。页签含义以当前界面为准。
6. 从 Trial run/当前等价入口完成真实应用试跑，检查配置确实作用于结果。
7. 进入 AI App Publishing/当前发布入口，读取字段、素材规格、审核和活动关联要求。

Agent 的文字承诺不是独立证据；实际配置与可运行结果才是。

## SeaArt Flow / ComfyUI

Flow 适合图像转换后生视频、多图合成或明确分支。先读取真实节点菜单，连通输入 → 提示/处理 → 模型 → 可见输出，绑定用户输入/选项。画布运行成功后仍需从当前应用封装入口创建并测试应用。只有模板分享能力时改走可完成需求的路径，不把工作流链接称为应用。

确需 ComfyUI 时可使用已安装 `$comfyui-workflow-builder` 并查海艺支持情况，核验节点、模型、扩展依赖和输入输出映射。本地导入成功不等于云端可运行；不能靠本地路径访问云端模型，不自行安装未知扩展。先在海艺运行，再封装并测应用。

## 发布表单和状态

进入表单才采集真实字段与限制：标题、简介、分类、标签、封面、样例、格式/尺寸/体积、公开范围、权属声明、活动关联等。未出现的字段不虚构。优先处理必须首次发布关联的活动，再文案、分类标签、封面和校验；按实际 UI 调整顺序。

普通分类与赛事话题分别核对；简介写了 hashtag 不等于后台关联。权属勾选须有依据；新法律协议遵守当前工具要求。

| 观察 | 记录 |
|---|---|
| 保存或只有预览 | 已保存草稿 |
| 发布收到、待审核 | 已提交发布审核 |
| 公开详情可访问，内容与测试配置一致 | 已公开发布 |
| 活动报名记录/应用关联明确 | 已提交参赛，注明是否待审 |
| 资格审核明确通过 | 已通过参赛审核 |
| 点击超时，无明确结果 | 待核实，查已有项目/报名，不重发 |

发布后检查真实详情 URL 的标题、简介、封面和输入区域，不必重复花费积分运行已验证的同一版本。修改影响生成行为后再测受影响部分。
