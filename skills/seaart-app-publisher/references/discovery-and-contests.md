# 热点与海艺赛事检索

## 热点证据

按当前日期生成搜索词，不把模板里的日期原样执行。没有用户选题时先收集约 3–5 个候选；用户选题明确时围绕其需求检查同类、差异点和实现路径即可。

优先近 7 天，必要时扩大至近 30 天。搜索 X/Twitter 原帖、短视频/创作者公开页面、SeaArt 热门应用与官方展示；搜索引擎索引只是发现入口，要打开主要来源核实。

可组合的查询示例：

```text
site:x.com ("AI effect" OR "image to video" OR "photo trend") after:YYYY-MM-DD
site:x.com ("AI photo" OR "AI transformation" OR "AI filter")
AI 爆款 玩法 照片 变身 视频 最近
site:seaart.ai/app/ <选题或效果关键词>
site:seaart.ai ("AI应用" OR "AI App") <用途或风格>
```

社交平台原生搜索不可用时，用公开索引和其它可访问来源交叉核实，说明 X 数据覆盖缺口，不声称搜索了不可见的登录内容。不要陷入连续变体查询；找到足够支撑方案的来源就进入设计。

每个有效候选保存：

| 字段 | 内容 |
|---|---|
| 效果与场景 | 上传什么、获得什么、谁会使用 |
| 来源 | 直接原帖/演示 URL、作者、平台 |
| 时效 | 发布时间、观察时间、搜索窗口 |
| 可见信号 | 播放、点赞、转发、回复或海艺使用次数，按原指标分别记录 |
| 传播证据 | 是否有独立创作者复现、多个来源讨论、新近增长证据 |
| 可信度 | 已核实、仅索引、仅样例/宣传、未知 |
| 海艺实现 | 所需模式、编辑器可用模型、输入输出、预计复杂度 |
| 差异点 | 比现有玩法增加的用途、视觉设计或输入适应性 |
| 赛事适配 | 候选活动、硬约束和未核实项 |

不相加不同平台的点赞/播放来虚构热度；累计值不等于近期增长。网页模板数字、无日期旧帖、营销自称“viral”不能单独支撑“近期爆款”。至少有近期传播或明显复现证据才称趋势；证据不足标记“潜力选题”，仍可依据质量制作，不能编造热度。

选题同时考虑时效和证据、海艺可实现性、视觉辨识度、操作门槛、差异点、成本/延迟及赛事主题。先排除无法实现或不符合硬规则的方案，再在可行项中选择；不必把主观打分伪装成统计模型。

热点用于提炼“转化机制”，不是搬运封面、作者素材、隐藏提示词或照抄品牌包装。固定模板应适用于用户新的主体，而不只适用于原帖某张图。

## 规则卡：先确认能投什么

每个候选记录以下字段及各自来源，未提供的写 `unknown` 或“规则未要求”，两者不能混淆：

- 活动名称、官方 URL、实际给出的 event ID、主办/发布作者、检索与更新时间。
- 当前阶段：未开始、征稿、投票、评审、已结束；是否仍可提交。
- 起止原文、日期年份、时区与可确定的截止时刻；必要时换算用户时区。只给日期时保留日期精度，不发明 23:59:59 或默认北京时间；若时间歧义会影响当前投稿资格，先查清。
- 允许类型：应用、图片作品、视频作品、工作流、其它；是否接受旧应用或要求活动期内首次发布。
- 主题、限定模型/版本、必须作为核心生成还是可选使用、工具要求。
- 作品参数：时长、比例、清晰度、文件格式、配音/字幕等实际要求。
- 强制标签、标题/简介文字、封面、示例、参赛说明、公开可见性。
- 提交入口/方式：首次发布勾选、活动选择已有应用、作品投稿或独立表单；发布前后顺序。
- 原创/素材要求、参与资格、次数上限、是否可跨活动投稿。
- 站外分享是必须还是可选，是否另有抽奖或长期计划；不能把可选项升级为任务要求。
- 评审依据及其能转为制作决策的部分，如生成质量、完成度、主题表达、实际使用。

关键规则冲突时比较来源版本，不拼接不同赛事、年份或赛道的规则。用户指定活动时优先该活动；不确定是否接收应用时不能默认接收。若只授权 App 投稿，优先可直接收 App 的活动，不擅自变成站外宣传活动。

## 从规则推导制作与投稿

| 规则 | 制作与提交动作 |
|---|---|
| App 专项 | 做可运行应用，按要求关联活动，记录 app ID 和报名证据 |
| 图像/视频作品赛 | 应用作为生产工具，实际生成合规作品，再单独投作品，保留两个链接 |
| 指定核心模型 | 在实际生成节点选择规定模型，检查任务记录；简介写模型名不能替代 |
| 发布时选择活动 | 发前配置，不能先公开再假定可补报 |
| 要求活动期内新作 | 核查草稿/首次发布日期，不重命名旧作假装新作 |
| 强制话题/标签 | 使用正式选项或规则认可的填写方式，不以相似普通分类代替 |
| 评审期不能改动 | 在提交前完成调试，后续维护遵守规则 |
| 站外分享可选 | 跳过，除非用户明确要求；不参与附加抽奖 |

把每条硬约束对应到具体模型设置、应用控件、素材、发布字段或参赛动作。核心指定模型不可用时寻找仍符合规则的实现；无合规实现则报告阻碍，不换其它模型后继续声称合格。

投稿前再次确认阶段与资格、实际发布版本、封面、标签、模型和必要材料。提交后独立检查报名回执、参赛列表、Creator Center 的活动关联或其它明确平台状态。普通公开页只能证明发布；增加 hashtag、按钮变灰或 Agent 的一句“成功”不足以单独证明报名完成。
