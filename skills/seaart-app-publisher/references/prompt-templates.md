# 海艺应用提示词与发布文案模板

在已确定选题、运行模式和赛事要求后使用本文件。先观察当前 SeaArt 编辑器及其可选能力，再实例化模板。模板里的 `{{占位符}}` 只是本地写作标记，**不是 SeaArt 已支持的变量语法、字段名或节点名**。提交前把它们替换成具体文本，或映射到编辑器实际提供的输入控件、提示词拼接方式与节点连接；不得把未解析占位符直接留给最终用户。

## 一、先完成真实控件映射

为本次应用记录以下映射。表中的“本地概念”用于设计，右侧必须以当次界面实际显示内容填写；没有对应能力就调整方案，不虚构控件或接口。

| 本地概念 | 本次真实编辑器中的实现 | 验证方法 |
| --- | --- | --- |
| 主参考图 | 实际上传控件名称、允许输入数量、连接的图像输入 | 上传后预览正确，并确实参与生成 |
| 可选文字 | 实际文字控件及其进入提示词的位置；不支持则删除 | 修改文字能改变允许变化的部分 |
| 可选风格或强度 | 实际选择控件与支持的参数；不支持则使用固定方案 | 切换后请求及结果符合选项 |
| 固定内置提示词 | 实际提示词配置位置或节点 | 保存后重新打开仍存在，运行时被使用 |
| 参考图/首帧/尾帧 | 当前模型实际支持的图像条件输入 | 明确区分角色参考、构图参考、首尾帧 |
| 生成模型 | 当次可选模型的真实显示名及选择位置 | 实际任务使用该模型并成功完成 |
| 输出 | 实际结果组件及其连接的任务结果 | 展示本次任务真实返回的图片或视频 |
| 参数 | 实际支持的比例、尺寸、时长等 | 保存并运行，核实未被重置或忽略 |

即使 App Agent 已生成漂亮页面，也不能据此宣称应用可以生成。必须存在真实输入到真实模型再到真实结果的完整链路；加载动画、示例图片、静态视频、伪造结果地址均不算通过。

## 二、发给 App Agent 的完整搭建 brief

将下面内容填实后提交给 SeaArt 当前可用的 App Agent。提交前删除与本次模式无关的分支；如果编辑器采用其他创建路径，把同一 brief 转译为其真实配置。

```text
请按下面授权范围搭建 SeaArt AI 应用。

【本轮执行范围与预算】
执行模式：{{draft_only / build_and_test / build_publish / build_publish_enter，填入与本轮用户授权一致的值}}。
允许动作：{{本轮已授权的配置、素材上传、付费生成、发布、参赛动作；未授权的不要代做}}。

本次可支配额度：{{从剩余额度分配给当前 Agent 操作的上限；主 Agent 与下游不能各自重复花整笔预算}}。
draft_only 模式只搭建/检查配置，不触发付费生成、不发布、不参赛；另有用户明确授权的草稿试跑除外。
只在已授权动作与可支配额度内运行，提交前核对界面费用；不自动购买、充值或订阅。结果不明先查看既有任务，不重复扣费。

【应用目标】
临时工作名：{{工作名}}
目标用户：{{谁会使用}}
一句话结果：用户提供{{必要输入}}，得到{{清晰可见、可重复实现的结果}}。
核心变化：{{本应用只负责实现的视觉转化}}
参赛适配（仅本次存在目标赛事时填写）：{{已核实的主题、作品形式、指定模型或工具、必选标签等；没有就删除本项}}

【运行模式与实际能力】
本次模式：{{图生图 / 文生图 / 图生视频 / 文生视频 / 当前确实支持的其他模式}}
根据当前编辑器实际可选模型，选用能支持上述输入、效果和输出形式的模型。
优先顺序：{{与任务相关的身份保持、转化质量、视频运动、生成成本、延迟等优先级}}。
若用户偏好的模型不可用，先检查能完成相同任务的可用模型；若模型是赛事硬性要求，则仅采用仍符合规则的实现，无合规实现时报告阻碍。不得填入未经确认的模型 ID、API 地址或密钥。

【用户输入】
必要输入：{{例如上传一张主体清晰的照片；按真实上传控件支持数量填写}}
输入指导：{{与本效果有关的构图、遮挡、光照、人数或物体要求}}
可选输入：{{只保留实际能连接模型且会改善结果的控件，例如场景短句或有限风格选择；否则填写“无”}}
可选文字的空值默认：{{具体默认值}}
可选文字的作用范围：仅补充{{场景 / 色彩 / 合法动作等范围}}，不能覆盖核心转化、身份保持和输出要求。
不要让用户重新编写整段提示词，也不要暴露没有实际作用的参数。

【固定内置生成提示】
{{填入已经实例化的完整图像或视频提示词；任何需要动态输入的片段，都必须接到当前编辑器真实提供的变量或节点机制}}

【真实工作流】
使用当前编辑器实际支持的组件，完成：
1. 接收并检查必要输入，显示可理解的缺失或格式错误提示。
2. 把上传媒体接入模型对应的真实条件输入，把固定提示词与允许的可选输入按实际机制组合。
3. 触发一次真实生成任务，展示当前编辑器能够获得的执行状态。
4. 等待任务完成，把真实返回结果显示在应用的结果区域，并提供当前平台支持的查看或保存方式。
5. 失败时展示实际错误，并允许在保留有效输入的情况下重试；不得用静态示例代替失败结果。

【默认参数】

参数被编辑器自动修正时，读取保存后的最终值并以其为准。
若当前模型提供随机种子，调试时可固定，公开应用是否暴露该控件按实际使用价值决定。

【界面与使用说明】
首屏顺序：一句话用途 → 必要输入 → 少量必要选项 → 生成操作 → 真实结果。
界面文案使用{{中文 / 用户指定语言}}。
说明适合的输入、会发生的变化和应保留的内容；不能承诺未实测的成功率、耗时、免费额度或分辨率。
应用必须围绕这一个核心效果，避免增加与生成无关的页面和功能。

【预览与验收】
创建后先进入实际预览，检查必要输入、空值默认、控件映射、模型连接和输出显示。
仅在本轮允许实际试跑且费用在分配额度内时，使用有权使用的测试素材完成真实生成；核实结果符合核心效果和下面的主体保持要求。draft_only 模式删除本条真实生成任务，输出配置检查和待测试项。
如果有可选控件，检查其真实连接；获准试跑时验证其改变了允许变化的部分。仅草稿时记录效果尚未实测，不只修改标签而不连接生成。
重新打开已保存的应用或预览，核实配置仍然有效。
若只完成界面、模型没有接通或无法取得真实结果，请明确指出缺失连接及原因，不得报告“应用已完成”。
```

对 App Agent 的输出做实际操作验证，不只接受其文字承诺。在已授权的工作范围内直接修正、预览和测试，不为每个日常步骤增加确认。若一次失败没有改变输入、连接或参数，不反复提交同一请求；先定位具体失败点。

## 三、图生图内置提示词

先选定任务究竟是“主体身份转化”“产品场景化”“整体画风转化”中的哪一种。主体不是人物时，用产品结构、轮廓、标志性纹理等替代人脸与发型要求。不要写与核心效果矛盾的保持项，例如换装应用不能要求衣服完全不变。

```text
根据用户提供的参考图生成一张{{最终视觉类别}}。

核心任务：把参考图中的{{明确主体}}转换为{{目标效果}}，使{{本应用最有辨识度的视觉变化}}清晰可见。

主体对应：以用户本次上传的主体为唯一身份依据。保留{{人物的脸部识别特征、发型或产品的形状比例、标志性细节等；仅填任务需要保持的内容}}。不要把示例图中的人物、产品或作者固定带入结果。主体数量为{{实际输入约束与效果相容的数量}}，各主体对应关系清楚。

保持不变：{{需要保留的身份特征、视角、主体动作、构图或关键物件}}。
允许改变：{{目标画风、材质、服装、背景、光线、配色或其他任务变化}}。
变化边界：只在{{限定范围}}实施变化；{{容易误改的部分}}保持可识别。

画面设计：{{主体位置、景别、视角、背景层次、留白等与效果相关的具体描述}}。
视觉质感：{{材质、光照来源、色彩关系及风格细节}}。
细节处理：{{与主题相关的清晰度、局部结构、文字或纹理要求}}。

可选补充（没有真实控件时删除本段）：用户补充的{{字段含义}}仅影响{{指定区域或属性}}；空值时采用{{默认内容}}。补充内容不能改变上述核心任务和保持边界。

最终结果：{{图像比例或构图要求，必须适配模型实际参数}}。画面只展示成品，不要出现操作界面、提示词、无关说明或无意生成的水印。
```

负面约束优先融入主提示词。只有当次模型确实支持独立负面提示词时，才使用其真实配置位置；不要假设所有模型都有该字段。涉及包装原文、商标或细密图案时，以测试结果核实复现能力，不在标题中承诺“完全一致”。

## 四、图生视频内置提示词

先核实本次模型是首帧、首尾帧还是多图参考模式，以及参考图实际承担什么角色。读取真实可用时长 `T`，把下面比例换算为秒数并适当取整，使阶段连续且覆盖完整 `T`；这些比例是编写动作节奏的工具，不是模型原生时间轴语法。短时长时减少动作阶段，不把多件复杂事件硬塞进短片。

```text
以用户提供的{{实际支持的首帧 / 角色参考图 / 多图参考}}为生成依据，制作一段{{真实支持并已选定的 T 秒}}视频。

核心效果：{{用户一眼能理解的动作、变化或运镜结果}}。
参考图角色：{{哪张图约束主体身份，哪张图约束初始画面或结束画面；仅填写真实模式支持的角色}}。

身份锚点：主角始终是参考图中的{{主体}}，保留{{关键外形、服装或产品结构}}。整个片段中的主体数量和对应关系保持稳定。
空间锚点：{{主体}}位于{{地面、桌面、门窗、背景物等参照关系}}；运动期间保持{{左右关系、接触关系、前后遮挡或光源方向}}合理连续。
初始状态：{{与首帧一致的姿态、位置、构图；如果只是身份参考则明确允许的开场构图}}。

动作与运镜：
开场约 0–20%：{{最短的建立状态及开始动作}}。
主体运动约 20–75%：{{一个明确主动作及其方向、力度、速度变化}}；镜头{{一种可执行的主要运镜}}，保持{{视觉锚点}}清楚。
收尾约 75–100%：{{动作自然完成后的可见结果及稳定落点}}。
如果使用尾帧：结束状态与实际绑定的尾帧{{构图、主体姿态、关键物体位置}}衔接，避免最后一刻突然跳变。

动态细节：{{头发、布料、粒子、水、光影等少量次级变化，必须符合本次场景}}。
光影与质感：{{与参考图和目标效果一致的描述}}。
连续性：{{本应用需要的一镜到底 / 明确允许的剪辑方式}}；保持主体识别、物体结构、运动方向和空间关系连续，不增加无关人物或物件。
输出：{{当前模型实际支持的比例与其他要求}}。不要出现无关字幕、界面元素或水印。
声音（只有本次模式实际支持且应用需要时保留）：{{真实可生成的环境声、音乐或对白要求}}。
```

实测时完整播放视频，检查开头、主要动作、最后落点和帧间稳定性。静态缩略图无法证明动作通过。若模型没有音频能力，删除音频诉求；若必须通过后续节点增加音频，先验证当前创建路径真实支持该连接。

## 五、标题、简介与封面 brief

发布文案以实际测试结果为依据，参赛信息以已核实规则为依据。将文案填入当前发布页存在的对应位置；标题长度、简介长度、标签数量、封面比例、像素尺寸与文件大小全部服从当次界面的真实限制。

### 标题与简介

```text
标题候选写法：
{{核心效果}}｜{{输入或使用场景}}
{{直观动词}}{{目标结果}}
{{核心视觉风格}}{{照片 / 动态 / 视频}}生成器

最终标题：{{选择一条简短、可理解、与结果一致的标题；删除候选列表}}

简介：
上传{{输入要求}}，将{{主体}}变成{{经过验证的核心效果}}。
保留{{实际测得可保留的特征}}，呈现{{最突出的视觉变化}}。
适合{{具体使用场景}}。建议使用{{能提升稳定性的输入建议}}。
{{如有真实可选控件，用一句话说明它改变什么；否则删除}}
{{如赛事明确要求展示活动文字且页面有合适位置，加入准确内容；否则删除}}
```

不要填入未经核实的“全网最火”“官方获奖”“100%还原”“永久免费”或固定生成耗时。以热门选题为灵感创作，避免沿用热点作者的独有标题与宣传文案。

标签先从当前发布页实际可选项中选择最贴合的主题、用途、风格与图像/视频类型，再添加赛事要求且确实支持的标签。不要把研究阶段的关键词直接当成平台存在的标签；不要虚构赛事标签或把相近字样替代规定标签。

### 封面制作 brief

```text
为 SeaArt 应用“{{已确定标题}}”制作发布封面。

真实效果依据：{{本应用本次真实测试输出的文件或可访问素材引用}}。
受众第一眼应理解：{{上传什么 → 得到什么}}。
主要画面：优先采用本应用真实生成结果，突出{{最能说明应用效果的主体和细节}}。
画面结构：{{单张结果特写 / 经输入与输出核实对应关系的前后对比 / 视频关键动作的代表帧}}。
如使用前后对比，明确区分输入与输出，主体、变换方向和比较关系一致。
文案：{{必要时保留短标题及一句效果说明；若缩略图中不可读则精简或删除}}。
视觉设计：{{适合主题的配色、主体占比、留白与文本层级}}。
规格：以当前 SeaArt 封面上传控件显示的真实比例、尺寸、格式与体积限制为准；保留能适应裁切的主体安全区域，上传后检查实际缩略图。

封面只展示本应用已验证可实现的效果。不得用热点作者的作品或他人应用宣传图充当本应用效果，不得把独立生成的更强效果伪装成本应用输出，不得标注未经取得的奖项或官方背书。
```

需要设计装饰时，可以围绕真实输出制作版式、背景、标题和视觉元素，但成品里的核心效果展示必须仍忠于真实输出。视频应用使用实际测试视频的代表画面；若编辑器另提供视频预览入口，按其真实支持方式上传，不能假定封面本身接受视频。

封面上传后检查裁切、文字可读性、主体完整度与实际应用结果的一致性。发布前保存最终标题、简介、真实选中标签、封面文件及测试结果记录，供发布结果和参赛结果核对。
