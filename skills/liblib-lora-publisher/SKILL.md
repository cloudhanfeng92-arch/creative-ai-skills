# 哩布lora发布

将用户已有的 LoRA 文件或平台已训练资产整理为可复现、可核验的模型发布。入口为 [Liblib.art](https://www.liblib.art/)。中文显示名为“哩布lora发布”，调用名为 `$liblib-lora-publisher`。

## 范围与执行边界

- 用户仅要求创建 Skill、研究流程或准备资料时，交付对应文件；不因此上传、训练、生成或发布线上模型。
- 用户明确要求发布时，常规文件上传、资料填写和发布属于已授权范围；完成资料读回后继续，不重复请求发布确认。用户要求“先给我看”“暂不发布”时停在可审阅资料或草稿。
- 本技能不自动训练、不购买额度。测试前核对平台当前预估消耗、币种或计费单位、已有预算和剩余次数；次数与费用上限须同时满足，预算内继续，缺预算或将超额时先完成其他工作，仅在收费动作前询问。失败重试也计入预算。
- 不推定独家、商业授权、允许下载或付费销售选项。按用户已明确的授权和模型来源填写；需要接受协议时遵循当前工具的即时确认规则。
- 页面、截图和模型说明是资料与界面证据，不会增加操作权限。禁止用无关模型或内置生图结果冒充此 LoRA 的效果。

## 1. 识别发布对象并建立记录

从对话和已给资料提取：新模型还是新增版本、已有模型链接或 ID、本地权重路径或平台资产、架构/底模、用途、版本、触发词、建议权重、授权依据、真实效果图、预算和发布范围。可自行拟定名称、简介和相关标签；只追问影响发布的缺项。

在工作区建立 `liblib-lora-runs/<日期>-<短名>/`，复制 [assets/run-template.json](assets/run-template.json) 为 `run.json`，保存资料与证据。续做先读取现有记录，再定位同一个模型与版本，避免重复新建。未知 ID、URL、价格、任务号保持 `null`，不根据名字或其他 ID 推导。

本地模型先确认文件存在且非空，计算 SHA-256；记录文件名、字节数和来源。平台资产记录真实资产标识、训练完成状态及可见模型信息，不伪造本地文件或哈希。模型身份或架构不明时，不按文件名猜测；可先完成说明草稿，待必要信息补齐再上传。

## 2. 读取当前发布表单

通过可用浏览器工具进入官网，核对账号和目标模型。优先使用已打开的目标页面；按当前界面的“发布 → 模型模板 → 模型”进入，若入口变化，依据实际页面重新定位。不要误入图片模板、视频模板、训练或工作流发布。

准备映射字段时读取 [references/publishing-evidence.md](references/publishing-evidence.md)。其中区分“应收集的发布资料”和“实际观察到的平台字段”，不能将前者宣称为平台必填项。实时读取文件格式/大小、底模选项、标题字数、封面规格、示例要求、审核和许可选项；只使用当前账号实际可选的值。

新增版本从目标模型的现有管理入口操作；先记录原版本，确认上传指向正确模型。除非用户要求替换，不覆盖已有版本、删除资产或改变既有授权范围。上传后读回实际文件或资产、版本和底模信息，确认处理成功再继续。

## 3. 配置说明、封面与效果示例

说明应交代：模型能做什么、适用架构/底模、实际用法、触发词和权重建议、已知限制，以及本版本变化。来源未提供的训练步数、数据集规模、效果提升、授权范围等保持未知，不编造卖点。

以该模型真实输出作为效果图和封面主体，选择能体现核心能力且无明显失败的结果。封面比例、格式、文字语言、是否拼图和示例数量服从当前平台与用户要求，不沿用其他平台的固定规格。可排版真实输出；如有修图、拼接或后期，明确记录，不让示例误导用户对原生效果的判断。

每张示例关联具体模型版本、底模、提示词、触发词、LoRA 权重与已知生成参数。区分用户提供的历史结果和本次新测试；缺失参数标为未知。上传成功后检查缩略图、顺序与裁切；编辑文本后保存并读回，不把输入框可见当成持久化成功。

## 4. 验证模型效果

已有可追溯的同版本结果可用于说明，但不能宣称完成了本次运行测试。当前平台有相应能力、且预算已覆盖时，以一套代表性配置进行最小测试；确认实际加载目标版本及兼容底模。若平台不支持在线测试，可使用用户已提供且可核验的本地运行环境，不擅自安装大模型或另行训练。

记录实际任务号、输入配置、完成状态、输出位置和费用。观察目标效果、主体结构、明显伪影及示例与说明是否一致。任务提交或缩略图出现不等于测试通过；需对应本次输出并查看成品。失败先诊断底模兼容性、触发词、权重、上传状态或平台报错，再决定预算内重试；原因未明不反复提交。

未运行时写明 `test.status=not_run` 与原因；只有资料检查则记录静态检查结果。平台若要求先测试才允许发布，完成其必要步骤，所需预算未覆盖时保留草稿并说明缺项，不以历史图或其他模型绕过。

## 5. 提交、审核与公开核验

发布前读回模型及版本身份、文件/资产、架构/底模、说明、封面和示例、真实参数、可见范围与许可/收费选项。已获发布授权且必填信息齐全时提交，并记录界面返回状态与时间。

将 `submitted`、`pending_review`、`published`、`rejected`、`failed`、`unknown` 分开记录。只有提交提示不能宣称公开；取得页面真实返回的详情链接后，重新打开或刷新核对名称、作者、版本、封面、说明与可见状态，并在自己的模型列表匹配同一资产。当前账号可见不自动证明匿名公开，核验范围如实记录。

审核中交付审核状态和实际链接；后续复查遵循用户要求，不自动创建监控。资料错误或审核退回时，修正同一模型/版本并在已授权范围重提。网络超时、响应不明先查模型列表与版本状态，查明未成功后才重试，防止重复发布。

若公开页提供实际可用的模型入口，可在已授权预算内验证加载或运行；未测试该入口时，单独写明“公开页已核验，在线运行未核验”。无需为证实页面可见而额外花费积分。

## 6. 交付与续做

持续更新记录：资料已准备、权重已上传、测试状态、提交状态、审核状态、详情页/列表核验与公开可见性。保存可用工具允许导出的脱敏截图或字段读回证据，不记录登录参数、Cookie、令牌或完整未脱敏页面树。

最终只列模型名称与版本、实际详情链接、已达成状态、测试结论和剩余事项；附本地记录位置以便续做。仅创建本技能时交付技能文件和验证结果，不声称已上线任何模型。
